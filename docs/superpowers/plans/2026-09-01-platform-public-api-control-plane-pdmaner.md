**Goal:** Extend the current Platform Support database blueprint from its 57-table baseline with the approved six-table unified public API control plane, and rename the tenant-member role grant table without weakening tenant isolation.

**Architecture:** Platform remains the database authority for global Account/Tenant IAM and becomes the current-configuration authority for public Gateway Targets, Routes, Route children, Guard Rules and human-console navigation resources. The implementation adds one focused PDManer diagram group, keeps Route children inside the Route aggregate, preserves runtime Redis state outside MySQL, and updates all active authority/requirements documents only after generated statistics are known. This task does not implement Java, migrations, seed data, Gateway runtime code, deployment or physical databases.

**Tech Stack:** Node.js ES modules, `node:test`, the repository PDManer manifest DSL and generator, PDManer 4.9.3 JSON, Markdown authority documents, TypeScript requirements catalog, npm build/test/lint.

**Spec:** `docs/superpowers/specs/2026-09-01-gateway-platform-support-dynamic-operations-configuration-design.md`

- `t_role.scope_key` is generated by Platform only: `PLATFORM` for platform roles and decimal `tenant_id` for tenant roles. It is never accepted as an external caller-selected isolation value.
- Do not add any `*_ver`, policy/binding version, draft/release/rollback/ack/snapshot/pointer/history/idempotency, tenant-override, guard-tier, API-scope-catalog or runtime-limiter-state table.
- Do not add a new database field whose name ends in `*_hash`; preserve the existing exact hash-field set.
- Only `t_gateway_target`, `t_gateway_route`, and `t_console_resource` receive ordinary optimistic-lock `version`; Route child tables have no `status`, `version`, or audit history.
- Public Route and Target rows are global configuration and contain no `tenant_id`; tenant isolation is derived at request time from a trusted human session or PLT-I03 credential result.
- Route `permission_id` is an optional local FK to `t_permission`, required only for `HUMAN_PERMISSION`. `required_scope_code` is required only for `API_SCOPE` and is intentionally not a foreign key to credential scope rows.
- Keep `t_gateway_target` identity controlled by seed/migration plus the Gateway Approved Target Registry; do not model arbitrary URI, scheme, host, IP, port, secret or script fields.
- Preserve all current CCT, Commerce, Payment, Finance and Risk files and generated statistics except shared navigation text that must mention the newly approved Platform boundary.
