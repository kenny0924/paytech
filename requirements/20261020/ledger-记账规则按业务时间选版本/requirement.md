# ledger：自动记账按业务时间选择规则版本

状态：**阶段 1—8 已完成（2026-10-20，已部署 mor-test ledger，已本地提交，未推送）**；Q1 采纳。确认记录见 [delivery.md](./delivery.md)，技术方案见 [technique.md](./technique.md)。

## 1. 背景

ledger 消费 account 入账批次时，按事实业务时间（支付成功时间 / 调整批准时间）选择自动记账规则版本。当前实现只读取规则包的**当前版本**，并要求业务时间落在它的生效区间内，否则整批拒绝（`TransactionPostingServiceImpl.effectiveBundleVer`）。

规则包切换版本后，旧版本退役、当前版本的生效时间晚于切换前发生的业务：

- 新版本 10:00 生效后，才到达一笔 09:59 支付成功的事实（消息延迟、重试、上游补发）；
- ledger 判定“业务时间无生效的自动记账规则版本”并拒绝；
- 按 [account / ledger 明细账决定](../../../agent-docs/decisions/2026-10-18-account-ledger-subledger-control-account.md)第 11 条，该分片后续批次全部停住，关账两段检查失败关闭。

即任何一次规则切换都可能卡住记账。用户 2026-10-20 选择方向一：按业务时间找当时生效的版本（含已退役版本）。

## 2. 目标

一笔事实无论何时到达、重试几次，都使用**其业务时间所在区间**的规则版本记账；规则切换不再导致迟到事实被拒绝。

## 3. 本期范围

- **R1** 自动记账选版本：在规则包的版本中，取生效区间 `[effective_from, effective_to)` 覆盖业务时间的那个版本；已退役版本按其区间参与，已作废、驳回、草稿、待审批版本不参与。
- **R2** 已批准、生效时间已到、但定时任务尚未切换的版本（最长约 1 分钟），对其生效时间之后的事实立即适用，与切换后结果一致。
- **R3** 被取代而从未生效的版本（零长度区间）不参与。
- **R4** 找不到覆盖版本时（业务时间早于首个版本、或数据缺失）仍整批拒绝，拒绝信息说明规则包、业务时间与原因。
- **R5（待确认，见 Q1）** 审批时生效时间已过：生效时间改按审批时间，避免新规则覆盖已经按旧规则过账的时段。

## 4. 不做

- 不重算已过账分录；不新增接口、页面或数据库结构。
- 不改变规则包维护流程（新建、提交、审批、驳回、作废、定时生效）的其他行为。
- 不处理 account 侧的映射（account 不使用规则包）。

## 5. 验收标准

| 编号 | 验收标准 |
|---|---|
| AC-01 | 规则包 v1 [T1, T2) 已退役、v2 [T2, ∞) 生效时，业务时间在 [T1, T2) 的迟到事实按 v1 规则行记账，不被拒绝 |
| AC-02 | 业务时间 ≥ T2 的事实按 v2 记账 |
| AC-03 | v2 已批准、生效时间 T2 已到但尚未切换时，业务时间 ≥ T2 的事实按 v2 记账；业务时间 < T2 的按 v1 |
| AC-04 | 被取代的零长度版本、作废 / 驳回 / 草稿 / 待审批版本从不被选中 |
| AC-05 | 业务时间早于首个版本生效时间、或规则包不可用时整批拒绝，不残留指令、Journal 或自动开立的账户；拒绝信息含规则包与业务时间 |
| AC-06 | 同一事实重试、或在版本切换前后处理，选中的版本相同（结果确定） |
| AC-07（随 Q1） | 审批时生效时间已过的版本，生效时间记为审批时间；未来生效时间不受影响 |
