# commercial 合同页交互优化

> 状态：阶段 1–3 合并评审稿（2026-10-20），待用户确认。确认记录见 [delivery.md](./delivery.md)。

## 1. 背景

用户反馈合同页「交互不舒服、不流畅、没有引导」。现状（mor-test 截图与代码核对）：

1. **没有主线**：合同从起草到可交易要走「起草 → 提交签署 → 各方签署 → 激活 → 订阅产品 → 新增开通项 → 条款方案 → 版本 → 价格 → 提交 → 复核 → 排期 → 生效」十余步，分散在详情 4 个页签和「价目」页；页头只按状态给「提交签署 / 激活 / 终止」，不说明当前在哪一步、还差什么。
2. **新建弹窗太重**：一屏 13+ 字段，含 Party ID、资料版本 ID、文件 ID、SHA-256 等裸 ID；Client 合同默认参与方是「Client + 平台签署方」，与常见的「Client + 经营主体」不符。
3. **依赖不提示**：开通项须先订阅产品（否则提交被拒）；签完最后一方后要自己回页头点「激活」；条款页签只显示当前 / 已排期版本，看不到草稿与待审批；新建方案要手填方案编号与 Owner，条款类型下拉不按合同类型过滤。
4. **原代码外露**：「MOR · SETTLE_THROUGH_PLATFORM · PLATFORM」、PAYOUT_FEE、SIGNING_DOCUMENT 等。

## 2. 目标

运营打开任意合同，一眼看到所处阶段、缺什么、下一步点哪里；新建合同分步完成、每步只填当下需要的字段；签署、开通、定价之间的依赖由页面提示和引导，而不是靠提交后被拒。

## 3. 范围

**包含（只改 operations-console-web）**

- **A 合同进度 + 下一步卡片**：详情页顶部六步「起草 → 签署 → 生效 → 开通 → 定价 → 可交易」，每步完成 / 当前 / 待办；下一步卡片写明缺口并提供直达按钮（登记某方签署、激活、订阅产品、新增开通项、去定价、查看待审批版本等）。终止 / 到期 / 取消合同显示结束态，不给引导。
- **B 详情页签按流程**：页签顺序「签约方与签署 → 产品与开通 → 定价」；打开时默认停在当前步骤的页签；页签标题带完成 ✓ 或待办点。
  - 「产品与开通」按已订阅产品分组：每个产品一个区块（名称、代码、已订阅、开通项数、［+ 新增该产品开通项］），区块内是该产品的开通项表（可开通项 / 币种约束 / 其他约束 / 滚动保证金 / 生效 / 状态 / 编辑）；已订阅无开通项的产品区块黄色提示并列出可开通项；底部一行列出未订阅产品与默认具备的基础产品，［修改订阅］在区头。
  - 「新增开通项」弹窗按产品打开：可开通项为卡片单选，只列该产品下的项，已开通的置灰；约束改为按类型的控件——币种标签（必填，至少一个）、消费者国家标签、要求 3DS 开关，提交时转换为原 `limits` 请求体；滚动保证金比例按百分比输入（5 = 5%，保存换算为 0.05，与价格费率同口径）；生效起点默认合同生效起点。
- **C 新建合同分步抽屉**：① 基本信息（类型、编号、名称、Client / Partner、OE、业务模式、生效区间）② 签约方（按类型给默认行：Client 合同 = Client + 经营主体；Partner 合同 = Local Partner + 平台签署方）③ 签署文件与确认（可后补，汇总预览）。每步校验后才能下一步；创建后进入详情，进度停在「签署」，卡片提示「下一步：提交签署」。
- **D 签署顺滑**：待签署时未签一方高亮且操作前置；最后一方登记成功后弹出「全部签署完成，是否立即激活？」；提交签署前若缺签署文件，下一步卡片直接提示，不等后端拒绝。
- **E 定价在合同内可见**：定价区显示该合同全部方案与版本（含草稿、待审批、已批准、已排期、生效），版本行可进入编辑器；Client 合同按「开通项 × 币种」显示当前价格覆盖（来自 rate-cards），未覆盖项标红；新建方案的条款类型按合同类型过滤、方案编号自动建议（可改）、Owner 自动带出不可改。
- **F 列表与文案**：列表上方状态快捷切换「全部 / 草稿 / 待签署 / 已签署 / 生效 / 已结束」带数量；模式、资金模式、定价权、文件用途、条款类型显示中文。

**不做**

- 不新增或修改任何后端接口、表、Platform 注册；合同状态机与校验不变。
- Party / 资料版本 / OE / 文件仍为手填 ID：client-master 运营查询接口（由 Client 带出 Party、OE 列表、平台签署方）与合同文件上传另立需求（mor-test 还需补 OE 与 Partner 主档）。
- 不改「价目」页、版本编辑器、价格抽屉本身。

## 4. 页面设计

设计稿：`operations-console-web/docs/operations-console.pen`，与商务 05–08、06b、10 同一行，向右依次：

- 「商务 · 11 合同详情（进度引导）」（x=8880）：以 DEMO-CL-002 为例（生效、已开通、v1 待复核）——六步进度停在「定价」，下一步卡片两条待办，页签「签约方与签署 ✓ / 产品与开通 ✓ / 定价 ●」，定价区为方案版本表与价格覆盖表。
- 「商务 · 12 新建合同（分步抽屉）」（三个抽屉并排）：第 1 步基本信息、第 2 步签约方（按类型预填角色卡片）、第 3 步签署文件与确认摘要。
- 「商务 · 13 合同列表（状态切换）」（x=12820）：筛选栏上方状态快捷切换带数量。
- 「商务 · 11b 合同详情 · 产品与开通」（11 正下方）：以开通中的合同为例——进度停在「开通」，下一步卡片提示出款已订阅无开通项；收单区块 3 个开通项，出款区块黄色空状态，底部未订阅 / 默认具备。
- 「商务 · 11c 新增开通项（弹窗）」（11b 右侧）：卡片单选可开通项（已开通置灰）、币种标签、国家与 3DS 开关、保证金百分比、生效时间。

### 4.1 步骤判定（全部由现有详情 / 方案 / 版本 / rate-cards 读数推导）

| 步骤 | 完成条件 | 当前步骤的下一步卡片 |
|---|---|---|
| 起草 | 状态不是 DRAFT | 缺签署文件：「补签署文件后才能提交签署」；否则［提交签署］ |
| 签署 | 状态为 SIGNED / ACTIVE 及之后 | 「还有 N 方未签署：角色 · Party」+ 每方［登记签署］ |
| 生效 | 状态为 ACTIVE | ［激活合同］，说明激活后才能排期价格 |
| 开通 | 至少订阅一个产品，且每个已订阅产品都至少有一个 ENABLED 开通项 | 未订阅：［订阅产品］；某产品已订阅无开通项：「出款（PAYOUT）已订阅，但还没有开通项」+［新增出款开通项］ |
| 定价 | Client：每个 ENABLED 开通项 × 约束币种都有当前价格；Partner：至少一个生效版本 | 「CARD_VISA / AED 等 N 项没有生效价格」+［去定价］；有待审批版本时提示「v2 待复核」；只有已排期版本时显示生效时间 |
| 可交易 | 以上全部完成 | 绿色「合同已可交易」，列出当前生效版本 |

### 4.2 交互规则

| 项 | 规则 |
|---|---|
| 默认页签 | 起草 / 签署 / 生效 → 签约方与签署；开通 → 产品与开通；定价 / 可交易 → 定价 |
| 页签标记 | 该页签对应步骤已完成 ✓；当前步骤橙点；其余无标记 |
| 激活询问 | 登记签署成功且返回状态为 SIGNED 时弹出「全部签署完成，是否立即激活？」［立即激活］［稍后］ |
| 新建抽屉 | 宽 720；步骤条三步；上一步保留已填值；关闭时有未提交内容需确认 |
| 方案编号建议 | `<合同编号>-<条款类型缩写>`，如 `DEMO-CL-001-ACQ`；冲突由 commercial 返回 Owner 错误 |
| 定价覆盖 | rate-cards 读取失败或 Partner 合同时不显示覆盖表，只显示方案与版本 |

## 5. 验收标准

**功能**

| 编号 | 验收 |
|---|---|
| AC-01 | 六步进度在 DEMO-CL-004（草稿）、003（待签署）、002（生效、价格待审批）、001（可交易）、PT-001（Partner）上分别停在正确步骤，下一步卡片文案与按钮正确。 |
| AC-02 | 下一步卡片按钮直达对应操作（打开同一个登记签署 / 激活 / 订阅 / 开通 / 新建方案弹窗或跳到版本），操作完成后进度自动刷新。 |
| AC-03 | 新建合同三步：每步校验、上一步保留数据；Client / Partner 默认参与方正确；创建成功进入详情并停在签署步骤；请求体与改版前一致。 |
| AC-04 | 最后一方登记签署后出现激活询问，点击立即激活成功；缺签署文件时起草步骤提示且不显示可点的提交按钮。 |
| AC-05 | 「产品与开通」按已订阅产品分组，已订阅无开通项的产品黄色提示；新增开通项按产品打开、只列该产品的项且已开通置灰；币种 / 国家 / 3DS 控件提交的 `limits` 与原行表等价；保证金 5 保存为 0.05、读回显示 5；未订阅任何产品时显示订阅引导。 |
| AC-06 | 定价区列出全部方案与各状态版本；Client 合同覆盖表正确标出缺价项（DEMO-CL-001 全覆盖，DEMO-CL-002 显示待复核）。 |
| AC-07 | 新建方案的条款类型按合同类型过滤，方案编号有建议值，Owner 只读。 |
| AC-08 | 列表状态快捷切换数量正确，切换后列表筛选同步；模式 / 文件用途 / 条款类型显示中文。 |
