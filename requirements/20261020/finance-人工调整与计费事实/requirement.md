# Operations 财务：人工调整与计费事实

状态：**阶段 1—8 已完成（2026-10-20，已部署 mor-test，已本地提交，未推送）**。确认记录见 [delivery.md](./delivery.md)。顺序：本需求为财务控制台后续三项中的第 1 项（之后为[期间关账与试算](../finance-期间关账与试算/requirement.md)、[记账规则包维护](../finance-记账规则包维护/requirement.md)）。

## 1. 背景

ledger 的人工调整（`ManualAdjustmentApi`：提交、审批、驳回、详情，双人复核与内容哈希）和 billing 的计费事实（`BillingFactQueryApi` / `BillingFactCommandApi`：查询、登记、审批）都已实现并部署 mor-test，但 Operations 没有入口：

- 人工调整没有列表接口，财务看不到待审批、已过账的调整；操作人通过请求体 `makerId` / `checkerId` 传入，未接统一身份（接口注释写明"未接 Gateway 与统一身份前不得对外发布"）。
- 计费事实的列表只返回已批准 / 已替代的事实，按主体 + 币种游标翻页；没有草稿（待复核）列表，也没有驳回 / 作废，填错的草稿无法处理。
- 影响 Client / Partner 余额的调整必须走计费事实（ledger 人工调整禁止控制科目），今晚的演示数据就是绕过控制台直接调内部接口登记的。

## 2. 目标

财务人员在 Operations 上完成两类调整的制单、复核和查询：总账层面的人工调整（非 Owner 科目），以及影响 Owner 余额的计费事实人工调整；操作人取自登录身份，不能自己复核自己。

## 3. 本期范围（草案）

- **R1 人工调整列表与详情**：按账簿、期间、状态、制单人筛选；详情显示分录行、借贷合计、内容哈希与审批记录。ledger 新增列表查询接口。
- **R2 人工调整制单**：选账簿、开放期间、原因、分录行（科目按编号 + 名称选择，只列可记账、非控制科目的账户），借贷平衡校验；可选附件（`fileId` + 哈希，见 Q4）。
- **R3 人工调整复核**：审批（过账）或驳回；复核时展示并回传内容哈希；同一人不能复核自己的调整。
- **R4 计费事实查询**：按主体、币种、Client、状态（草稿 / 已批准 / 已替代）、事实类型、时间筛选；详情显示明细行、引用与下游入账情况。billing 新增管理列表接口。
- **R5 计费事实登记**：本期只登记 `MANUAL_ADJUSTMENT`（主体、Client、币种、明细行：金额组件、付方 / 收方、金额、方向、目标余额桶；可选工单引用；可选替代某条已批准事实）。`COST_ADJUSTMENT` 需要已批准的支付事实，留到渠道成本控制台需求。
- **R6 计费事实复核**：批准（发布 `BillingFactRecorded`，account / ledger 入账）或驳回（见 Q3）；同一人不能复核自己的事实。
- **R7 统一身份**：制单人、复核人取自 Operations 登录账号，不再由页面填写（见 Q1）。
- **R8 权限**：查询、制单、复核分开授权（见 Q2）；新增菜单页需要 Platform 能力清单与注册数据。

## 4. 不做

- `COST_ADJUSTMENT` 登记、计费事实的批量导入。
- 人工调整的撤回 / 修改（提交后只能驳回重提）。
- 调整原因代码目录维护（沿用固定值）。

## 5. 验收标准（草案）

| 编号 | 验收标准 |
|---|---|
| AC-01 | 人工调整列表按账簿、期间、状态、制单人筛选结果正确，分页稳定 |
| AC-02 | 制单：借贷不平衡、控制科目、非开放期间、币种不符被拒并就地提示；成功后状态为待复核 |
| AC-03 | 复核：制单人本人不能审批或驳回；审批后生成分录并可从详情跳到账本分录；驳回后不生成分录 |
| AC-04 | 计费事实列表能看到草稿、已批准、已替代三类，筛选正确 |
| AC-05 | 登记 MANUAL_ADJUSTMENT 后为草稿；批准后对应 Client / Partner 余额与明细账、总账控制科目同步变化 |
| AC-06 | 计费事实驳回 / 作废后不入账、不能再批准（Q3 确认后细化） |
| AC-07 | 制单人、复核人均为登录账号，接口不再接受页面传入的操作人 |
| AC-08 | 无复核权限的账号看不到审批 / 驳回按钮，直接调用被拒 |

页面验收（阶段 3 原型后细化）：列表、制单抽屉、详情与复核、错误就地提示、空状态与无权限状态。

## 6. 待确认（2026-10-20 已决定，见下）

| 编号 | 问题 | 建议 |
|---|---|---|
| Q1 | 操作人身份怎么传 | ledger / billing 这几个命令改为读取 Gateway 传递的操作人 Header（与基础资料接口一致），去掉请求体里的 `makerId` / `checkerId` |
| Q2 | 权限是否把"复核"单独拆出 | 拆：新增 `FINANCE_ACCOUNTING_APPROVE`，制单用 `FINANCE_ACCOUNTING_MANAGE`，便于给不同角色（commercial 已有先例） |
| Q3 | 计费事实草稿填错怎么办 | 新增"作废"：草稿 → 已作废（新状态），有制单权限（MANAGE）的操作人可作废，不发布事件；作废人记入命令日志（不新增字段） |
| Q4 | 人工调整附件 | 本期不做上传，只填外部单据号（原因备注）；附件依赖 Platform 文件能力，另起需求 |
| Q5 | 页面放在哪 | 「财务」下新增一个菜单「调整」，内含「人工调整」「计费事实」两个页签 |

## 连续执行授权与已确认决定（2026-10-20）

- 用户回答：操作人「改为读登录身份 Header」；复核「新增复核权限」；规则包「新增定时任务」；推进方式「连续做到 test」——其余待定项按建议，三个需求按顺序连续完成阶段 2—7 并发布 mor-test，**提交前再询问用户**。
- 共用决定：ledger / billing 的调整、关账、规则、计费事实命令改为读取 `X-Gateway-Actor-Subject` / `X-Gateway-Session-Id`，请求体去掉 `makerId` / `checkerId`；新增权限 `FINANCE_ACCOUNTING_APPROVE`（复核），制单沿用 `FINANCE_ACCOUNTING_MANAGE`。
- 为减少共享组件（Platform、ops-bff、ops-web）重建次数，三个需求按顺序研发，合并为一次 mor-test 发布。
- 本需求 Q3 作废草稿、Q4 只填单据号不做附件上传、Q5 新菜单「调整」含两个页签：按建议。
- 人工调整原因代码（2026-10-20 确认，固定值，ledger 不做目录校验）：ACCOUNTING_CORRECTION 会计更正、RECLASSIFICATION 科目重分类、ACCRUAL 计提 / 摊销、AUDIT_ADJUSTMENT 审计调整、OTHER 其他；外部单据号写在分录行说明中。
