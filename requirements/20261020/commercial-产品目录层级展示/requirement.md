# commercial 产品目录层级展示

> 状态：阶段 1–8 完成（2026-10-20），已部署 mor-test，已本地提交（未推送）。确认记录见 [delivery.md](./delivery.md)。

## 1. 背景

运营控制台「商务 → 产品目录」现在把产品、可开通项、计费事件做成三个平级页签，后两者只用一列「产品」表示归属。模型里的真实关系是：

```
产品（t_product）
├─ 可开通项（t_product_capability.product_code）：合同在某 OE 下能开什么
└─ 计费事件（t_product_fee_event.product_code）：什么动作触发收费，按条款类型登记
```

可开通项与计费事件是同一产品下的**平级**，彼此没有关系；两者在价格层才交叉（画像条件对应开通项的细分维度，组件 `trigger_code` 指向计费事件）。三平级页签看不出谁属于谁，设计稿「L0 → L1 → L2」的编号也容易被读成三级链。

## 2. 目标

产品目录页以产品为主线展示归属：看一个产品就能看到它能开什么、按什么事件收费、事件可在哪些条款类型下配价，并把目录本身的缺口直接显示出来。

## 3. 范围

**包含**

- 产品目录页改为「产品主表 + 展开后上下两组平级分组（可开通项 / 计费事件）」，每组可单独折叠。
- 计费事件按「产品 × 事件」合并为一行，条款类型显示为标签（目录 21 行 → 13 行）。
- 条款类型筛选：只看某个条款类型可用的事件；该条款类型没有登记事件时给出明确提示。
- 目录缺口提示：非基础产品有可开通项却没有计费事件、条款类型没有登记事件。
- 补齐页面显示用的中文标签：条款类型 PAYOUT_FEE / FX_SPREAD / DISPUTE_FEE / PLATFORM_FEE，开通项种类，业务模式范围。
- 设计稿 `design-discuss/commercial/design.md` 六层表补一句说明：L1 与 L2 是 L0 下的平行分支。

**不做**

- 不改数据模型、commercial 接口、BFF、Platform 注册；三条目录查询接口原样使用。
- 不在本期补 PARTNER_BUY_RATE 的计费事件目录数据或 DATA_ANALYTICS 的计费事件（只在页面暴露缺口，补数据另立需求）。
- 不改合同订阅 / 开通 / 价格编辑抽屉里的目录下拉。
- 目录仍只读，不加维护功能。

### 4.2 交互与状态

| 项 | 规则 |
|---|---|
| 主表 | 每个产品一行：产品代码、名称、业务模式范围（BOTH 显示「MOR / PSP」）、基础产品标签（「默认具备」/「可订阅」）、状态、两个计数；按接口返回顺序。 |
| 默认展开 | 产品：有子项或有提示的默认展开，两组都为空的（TAX_INVOICE）默认收起。分组：有数据的默认展开；数量为 0 的默认收起，标题行直接写原因。「全部展开 / 全部收起」同时作用于产品和分组。 |
| 分组折叠 | 展开区内「可开通项」在上、「计费事件」在下，各占整行宽度；点分组标题（▾ / ▸ + 名称 + 数量）单独折叠。 |
| 可开通项子表 | 能力码、名称、种类（中文标签）、支付方式、维度条件（`CARD_BRAND = VISA`）、状态。 |
| 计费事件子表 | 同产品同事件合并一行；「可配价条款类型」为标签，按目录顺序；计费事实类型；未知条款类型显示原代码。 |
| 条款类型筛选 | 选项 = 目录中出现的条款类型 + 页面已知的 PARTNER_BUY_RATE，带事件数。选中后计费事件只留含该类型的行，主表只留有命中事件的产品，计数改为「命中 / 全部」；可开通项不受筛选影响。选中计数为 0 的类型时显示「该条款类型尚未登记计费事件，无法创建该类方案」。 |
| 空状态 | 写在收起的分组标题行：基础产品无开通项「基础产品默认具备，无需开通」；非基础产品无开通项「暂无可开通项」；无事件时基础产品「无事件费用」，非基础产品有开通项则为黄色缺口提示。 |
| 目录提示 | 顶部汇总缺口：非基础产品「有可开通项但无计费事件」。没有缺口时不显示。 |
| 加载 / 失败 | 三接口任一加载中显示表格 loading；任一失败沿用现有 `QueryFailure`，不显示半套数据。 |
| 窄屏 | 分组本来就上下排列；手机宽度下表格横向滚动在表格内部，页面不出现横向滚动。 |

## 5. 验收标准

**功能**

| 编号 | 验收 |
|---|---|
| AC-01 | 页面显示 7 个产品，每个产品的可开通项 / 计费事件计数与目录接口一致（ACQUIRING 6/6、PAYOUT 2/2、FX 1/1、DISPUTE 1/1、TAX_INVOICE 0/0、DATA_ANALYTICS 1/0、PLATFORM 0/3）。 |
| AC-02 | 计费事件按产品 × 事件合并：ACQUIRING 的 AUTH / CAPTURE / SALE / REFUND 各一行，带 Client 定价、Partner 分润、平台服务费三个标签；全页 13 行，覆盖接口全部 21 条登记。 |
| AC-03 | CHARGEBACK 在 ACQUIRING（Client 定价）和 DISPUTE（争议费）下分别出现，不合并跨产品的同名事件。 |
| AC-04 | 条款类型筛选「Partner 分润」时只剩 ACQUIRING 的 AUTH / CAPTURE / SALE / REFUND；选「Partner 底价」时显示未登记提示、主表为空。 |
| AC-05 | 顶部提示 DATA_ANALYTICS 有可开通项但没有计费事件；PLATFORM、TAX_INVOICE 不提示。 |
| AC-06 | 条款类型、开通项种类、业务模式范围显示中文标签，未知值显示原代码。 |
| AC-07 | 任一目录接口失败时显示统一失败提示，不显示部分数据。 |

**视觉 / 交互**

| 编号 | 验收 |
|---|---|
| AC-08 | 展开区内可开通项在上、计费事件在下，各占整行宽度；390px 宽无页面横向滚动。 |
| AC-09 | 产品与分组的默认展开规则、单组折叠、全部展开 / 收起按 4.2 生效；展开状态在筛选切换后保持。 |
| AC-10 | 风格与现有商务页一致（`commercial.css` / `configuration.css`、antd 组件、代码等宽字体），浅色与深色主题都可读。 |
