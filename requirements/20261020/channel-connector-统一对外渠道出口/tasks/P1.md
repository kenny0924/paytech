### 1. channel-connector

1. 新增业务能力模块 `paytech-channel-connector-protocol`（基础包 `com.paytech.channel.connector.protocol`），加入 channel-connector 父 POM 与 app 依赖；依赖方向 `core → protocol`，protocol 不依赖 core。
2. 把 `paytech/platform-support/paytech-platform-support-integration` 主代码按 technique 第 3.1 节搬入 protocol；platform-app 中 `ext/rest/externalapi/` 的 7 个 Controller 与 3 个 Converter 搬入 channel-connector-app `ext/rest/externalapi/`；`platform-support-api` 的 `externalapi/*` 接口与 DTO、7 个外部 API 枚举搬入 `paytech-channel-connector-api`（包 `com.paytech.channel.connector.api.externalapi`、`api.enums`），**HTTP 路径 `/external-api-admin/v1/**`、JSON 字段与状态码保持不变**。
3. 按第 3.2 节替换 Platform 耦合：
   - 去掉 `OperationsManagementPolicyService` 与会话头 `X-Gateway-Session-Id`。写接口必带 `X-Gateway-Actor-Subject`，读取方式复用 `ChannelConnectorHeaders.ACTOR_HEADER` 与现有校验；读接口不带操作人。
   - 去掉 `@Audit` 与 `OperationsAuditService`，改为同一事务写 `t_channel_config_change`：扩展 target_type / change_type 枚举，新增 `change_detail JSON NULL`，内容为 Platform 审计原有的字段名与摘要，不含值。
   - `t_channel_config_change` 的 DataObject、Mapper、Repository 从 core 移到 protocol，并发布一个变更记录 Service 接口，供 core 现有写入在同一事务中调用。
   - 锁沿用 `external-api-config` 的 TRY_LOCK。
   - ID 用 channel-connector 的 `IdGenerator`。
   - 事务用 channel-connector 的 `TransactionTemplate`，隔离级别与超时不变。
   - 配置键改为 `channel-connector.protocol.configuration.*` / `channel-connector.protocol.execution.*`，默认值不变。
   - MapperScan 与 4 个 TypeHandler 并入 channel-connector 的 MyBatis 配置。
   - 补偿目录增加 `INTEGRATION_VERIFY_RUN`，Handler 放在 protocol 的 `ext/eventhandler`。
4. 执行改为进程内调用（第 3.3 节）：
   - `ExecuteChannelOperationProcessor` 在事务外调用 protocol 公开的标准 API 执行 Processor，输入不变（`channelAccount{...}` + 卡票据）。
   - 原 `StandardApiExecutionErrorCode` 的 NOT_SENT 集合改为 protocol 内的类型化异常，outcome 映射与现在一致。
   - `PlatformPayOutputs` 改名为 `PayOutputs`。
   - 删除 `PlatformStandardApiClient`、`PlatformIntegrationClient(Impl)`、两个 Platform API Bean、`channel-connector.outbound.platform-*` 配置，以及 core 对 `platform-support-api` 的依赖（如还有其他用途须保留，在报告中说明）。
   - `ChangeChannelStatusProcessor` 的接入方存在性检查改为调用 protocol 的公开查询。
   - Vault Reveal 与读卡以 `channel-connector-service` 身份进行；读卡客户端配置从 platform-app 的 `PaymentCardMaterialConfiguration` 移到 channel-connector-app。
5. DDL：
