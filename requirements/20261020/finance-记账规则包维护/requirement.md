# Operations 财务：记账规则包维护

状态：**阶段 1—8 已完成（2026-10-20，已部署 mor-test，已本地提交，未推送）**。确认记录见 [delivery.md](./delivery.md)。顺序：财务控制台后续第 3 项。渠道成本方案由 [channel-connector 运营控制台](../channel-connector-运营控制台渠道成本与基础配置/requirement.md)负责，本需求不涉及。

## 1. 背景

ledger 的自动记账规则包（`STANDARD_TRANSACTION`、`STANDARD_ADJUSTMENT`）决定各类业务事实生成哪些分录，已实现版本生命周期：草稿 → 待审批 → 已批准 / 生效 / 驳回，新版本生效时旧版本退役，双人复核（提交人须为制单人、复核人不能是制单人）。目前规则包只能通过初始化 SQL 创建，版本也只能调内部接口维护；没有规则包列表接口；草稿建错只能提交后驳回；生效时间在未来的已批准版本没有任何机制到时生效。

## 2. 目标

财务在 Operations 上查看规则包与各版本的规则行，以现行版本为模板新建版本、提交、复核，并让定时生效的版本按时生效。

## 3. 本期范围（草案）

- **R1 规则包列表**：显示规则包、状态、当前生效版本。ledger 新增规则包列表接口。
- **R2 版本列表与详情**：按版本号倒序；详情按指令类型分组展示规则行（金额来源、核算对象角色、科目编号 + 名称、余额桶、借贷、是否必需）。
- **R3 新建版本**：以当前生效版本为模板复制规则行后编辑（增删改行），设置生效时间；保存为草稿。校验沿用 ledger 现有规则（科目须为可记账且启用、非控制科目，代码在目录内，账户身份矩阵）。
- **R4 放弃草稿**：草稿可以作废（新增接口，见 Q2）。
- **R5 提交与复核**：制单人提交；其他人审批或驳回；审批时生效时间已到则立即生效，否则为已批准待生效。
- **R6 到时生效**：新增定时任务，把到达生效时间的已批准版本切换为生效（见 Q3）。
- **R7 统一身份与权限**：同第 1 项的 Q1、Q2 决定。

## 4. 不做

- 新建规则包（规则包仍由初始化数据定义）。
- 规则行的金额来源、指令类型目录维护（固定目录）。
- 规则变更对历史分录的重算（规则只影响生效后的新事实）。

## 5. 验收标准（草案）

| 编号 | 验收标准 |
|---|---|
| AC-01 | 规则包列表显示 2 个规则包及当前版本；版本列表、详情与库内一致 |
| AC-02 | 以现行版本为模板新建草稿，规则行校验失败时就地提示（如科目已停用、控制科目、借贷不全） |
| AC-03 | 已有草稿或待审批版本时不能再新建；草稿可作废 |
| AC-04 | 提交人必须是制单人，复核人不能是制单人；驳回后可新建 |
| AC-05 | 生效时间已到的版本审批后立即生效、旧版本退役，新事实按新规则记账 |
| AC-06 | 生效时间在未来的版本审批后为待生效，到时由定时任务切换为生效 |

## 6. 待确认（2026-10-20 已决定，见下）

| 编号 | 问题 | 建议 |
|---|---|---|
| Q1 | 规则包列表 | ledger 新增只读列表接口（2 个规则包也走接口，不在前端写死） |
| Q2 | 草稿作废 | 新增「作废草稿」：草稿 → 已作废，只能制单人操作 |

| Q4 | 页面位置 | 「财务」下新增菜单「记账规则」 |

- 本需求 Q1 新增规则包列表接口、Q2 作废草稿、Q3 XXL-Job 每分钟到时生效、Q4 新菜单「记账规则」：按建议。
