# Operations 财务：期间关账、重开与发起试算

状态：**阶段 1—8 已完成（2026-10-20，已部署 mor-test，已本地提交，未推送）**。确认记录见 [delivery.md](./delivery.md)。顺序：财务控制台后续第 2 项（依赖[第 1 项](../finance-人工调整与计费事实/requirement.md)的身份与复核权限决定）。

## 1. 背景

ledger 已实现关账（7 个固定步骤：锁序号、检查异步与分录、检查 billing → account → ledger 入账进度、生成试算、处理异常、损益结转、最终试算）、重开（冲回结转）及其双人复核与关账哈希，并提供按期间的关账记录列表与详情；试算平衡可按账簿 + 期间发起。Operations 目前只有试算记录和科目余额的只读查看，没有关账、重开、发起试算入口，月结只能调内部接口。操作人同样由请求体传入。

## 2. 目标

财务在 Operations 上按期间完成月结：发起试算 → 发起关账 → 复核关账（或驳回）→ 需要时重开并复核；全程可看到每一步的结果和原因。

## 3. 本期范围（草案）

- **R1 期间关账看板**：按财务日历列出期间及状态（未开始 / 开放 / 关账中 / 已关账 / 重开中），每期显示最近一次关账或重开记录。
- **R2 发起试算**：账本查询 → 试算平衡页签增加「发起试算」按钮（上一需求未做的 E2）；运行后进入试算记录详情。
- **R3 发起关账**：只能按期间顺序关账（之前期间须已关账）；同步执行 7 个步骤，失败时显示失败步骤与原因，期间回到开放。
- **R4 关账复核**：查看步骤结果、各账簿最终试算与损益结转指令、关账哈希；审批后期间变为已关账，驳回后回到开放；制单人本人不能复核。
- **R5 重开与复核**：只有最近一期已关账期间可以重开；填原因（会计更正 / 延迟交易 / 审计调整）与申请单号；复核时展示冲回计划；审批后期间回到开放。
- **R6 统一身份与权限**：同第 1 项的 Q1、Q2 决定。

## 4. 不做

- 试算异常的处理入口（当前 ledger 没有异常处理接口；出现异常时关账会停在「处理异常」步骤，页面只显示异常明细，见 Q2）。
- 连续多期重开、部分账簿重开。
- 关账提醒、定时自动关账。

## 5. 验收标准（草案）

| 编号 | 验收标准 |
|---|---|
| AC-01 | 看板正确显示各期间状态与最近一次关账 / 重开记录 |
| AC-02 | 发起试算成功后可在试算记录中看到新运行，汇总与级次展示正确 |
| AC-03 | 前一期间未关账时发起关账被拒；步骤失败时显示失败步骤，期间仍为开放 |
| AC-04 | 关账复核：本人不能复核；审批后期间已关账、损益结转分录可在账本查到；驳回后期间回到开放且无结转分录 |
| AC-05 | 重开：非最近已关账期间被拒；审批后生成冲回分录、期间回到开放；驳回后期间仍为已关账 |
| AC-06 | 已关账期间不能再登记人工调整（与第 1 项联动） |

## 6. 待确认（2026-10-20 已决定，见下）

| 编号 | 问题 | 建议 |
|---|---|---|
| Q1 | 看板是否需要新接口 | 不新增：BFF 用现有「日历期间列表」+「期间关账记录列表」组合（BFF 聚合职责） |
| Q2 | 试算异常是否本期提供处理 | 不提供，只读展示；异常处理需要先设计 ledger 的处理规则，另起需求 |
| Q3 | 年末结转 | 沿用 ledger 现有规则（年末期间同时把本期利润转入留存收益），页面只展示，不另加确认 |
| Q4 | 页面位置 | 「财务」下新增菜单「期间关账」；「发起试算」放在现有试算平衡页签 |
