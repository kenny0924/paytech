# platform-support 工作流页面体验优化

> 状态：阶段 1 评审稿（2026-10-22），待用户确认。确认记录见 [delivery.md](./delivery.md)。
> 前置：[工作流需求](../../20261021/platform-support-工作流/requirement.md)（已上 mor-test，`1d39cd94` / `42879401`）。

## 1. 背景

用户反馈：「我的待办」「动作目录」「流程定义」三个页面体验不好——一个页面承载太多东西，看起来很乱，操作有点无厘头。

下面按三类使用者的真实任务逐页核对现状（依据：本机 e2e 与 mor-test 截图、`operations-console-web/src/pages/Workflow*.tsx` 与 `src/workflow/*`）。

### 1.1 三类使用者

| 角色 | 频率 | 来这里要做的事 | 最在意 |
|---|---|---|---|
| 处理人（填写人 / 审批人） | 每天多次 | 看有什么要我做 → 看懂背景 → 填写或做决定 → 下一条 | 快、不出错、知道做完了 |
| 发起人 | 偶尔 | 发起一个流程 → 之后看走到哪一步、卡在谁 | 进度清楚 |
| 流程管理员 | 偶尔、集中 | 配好动作和流程 → 发布 → 之后修改 | 不迷路、改错了能发现 |

### 1.2 我的待办：问题

1. **三层筛选叠在一起**：顶部「待处理 / 已处理 / 我发起的」，下面又一排「全部 / 待我执行 / 待我审批 / 超过 1 天」，再下面搜索框——处理人每次都要先过三层控件才看到列表。
2. **「我发起的」不是待办**：跟踪自己发起的流程和处理待办是两种心态，放在同一页签组里让「待办」概念变模糊。
3. **列表卡片信息顺序不对**：标题是节点名（「填写商户资料」），实例标题（真正的业务对象）退到第二行；第三行露出技术键「执行 · merchantInfo」；每张卡都有橙色「停留 0 分钟」，刚到的待办也像在报警。
4. **高级功能常驻占位**：「处理完自动打开下一条」开关和 J / K / A / R / T / Ctrl+Enter 快捷键说明一直占着列表底部，新用户看不懂，老用户不需要每次看。
5. **详情头部是一行长串**：「实例 · 流程 v1 · 编码 · 发起人 · 执行人 · 无审批人，必选动作完成即放行」挤成一行；流程进度是一排小圆点文字，看不出走到哪。
6. **先操作后背景**：「要做的事」在上，「参考信息」（启动表单）在最下——审批 / 填写前应先看懂背景。
7. **一打开就满屏红**：必填字段没动过就显示红框和「必填」，提交按钮置灰并提示「2 个字段未通过」，像是用户做错了事。
8. **操作散在四处**：「转交」「查看完整流程」在右上，「提交」在表单卡片右下，审批的「同意 / 退回修改 / 驳回」又是另一处；没有固定的操作区。
9. **批量审批模式不明显**：每张卡都有复选框，但只有不带动作的审批能勾；勾上以后右侧整块变成批量页，用户不知道自己进入了另一种模式。
10. **已处理是一张淡色表格**：链接、状态都是浅色，「类型」列又露出「执行 · merchantInfo」，「结果」和「实例状态」两列并排意义重叠。

### 1.3 动作目录：问题

1. **四列挤在一屏**：类型筛选、动作列表、动作详情三列并排，详情里「字段设计」又分「字段类型 / 字段 / 属性」三列——字段卡被挤到一个字一行（截图「商户名称」竖排、`<动作键>.merchantName` 断成多行），根本不能用。
2. **查看与编辑混在一起**：点列表直接进入可编辑状态，「停用」「保存」在头部，改没改、要不要保存不清楚。
3. **新建动作没有引导**：「新建动作」后直接给一张空表，类型要在表里选；表单 / 上传文件 / 页面任务 / 人工确认 / 数据查询五类配置完全不同，却共用一个入口表单。
4. **技术信息外露**：编码 `WF_E2E_FORM_093951`、「版本 2 · #236033080844881920 于 … 修改」（修改人显示账号 ID）在标题下；「执行人预览」叫法让人不知道预览什么。
5. **「数据查询」占一个类型位但不能用**：左栏专门有一段说明「本期只预留」，用户仍会点进去。

### 1.4 流程定义：问题

1. **卡片操作平铺**：每张卡四个同级按钮「编辑 / 发起 / 停用 / 版本」，「停用」红框最醒目，像是主操作；只有草稿的流程缩略图是空白。
2. **状态说不清**：「未发布」「v1 草稿」「v1」几个标签混用；编辑页头的「未建草稿（保存后从最新发布版本复制）」需要读两遍才懂。
3. **编辑页四块抢空间**：左侧节点面板（含一段操作说明）、中间画布、右侧属性面板、页头三个页签 + 校验 / 保存 / 发布三个按钮；没选中节点时右侧是一块大空白，画布被压窄，连线绕来绕去。
4. **校验是一个按钮**：「校验通过」看起来像按钮又像状态；问题要点它才知道。
5. **配节点要跳页面**：节点要用的动作必须先去「动作目录」建好；编辑流程时发现缺动作，只能离开编辑器（草稿未保存就丢了）。
6. **加节点只能拖**：从左侧拖到画布再拉线连接，常见的「在这条线后面加一步」没有快捷方式。

## 2. 目标

- **处理人**：打开「我的待办」就是一个干净的收件箱——左边一列要做的事，右边先看背景、再在固定位置做决定；做完自动到下一条。不常用的东西收起来。
- **发起人**：「我发起的」单独成页（或单独入口），一眼看到每个流程走到哪一步、在等谁。
- **流程管理员**：
  - 动作目录：浏览和编辑分开，编辑时给足空间；新建时先选类型。
  - 流程定义：列表一眼看出每个流程的状态和下一步；编辑器画布为主、面板按需出现；缺动作时在编辑器里就地新建；问题实时显示，发布前集中确认。

## 3. 范围（评审稿）

**包含**

- **A 我的待办（收件箱）**
  - A1 顶部只保留一组页签「待办 N / 已办」；类型用列表上方的轻量切换「全部 / 填写 / 审批」（带数量），「超过 1 天」改为排序与卡片上的超时标记，搜索收进图标。
  - A2 列表卡片：第一行实例标题，第二行「流程名 · 当前节点」，右侧只在超时（默认 24 小时）时显示红色时长，其余显示相对时间（灰色）；图标区分填写 / 审批；不显示技术键。
  - A3 详情三段固定结构：
    - 头部：实例标题、流程名、发起人与发起时间；流程进度改为横向步骤条（已完成 / 当前 / 未到），点击展开完整流程图。
    - 背景：启动信息、前面节点的产出、附件预览，默认展开、可折叠。
    - 我的任务：填写表单或审批内容。
    - 底部固定操作栏：主操作（提交 / 同意）在右；退回修改、驳回在旁；转交、查看完整流程收进「更多」。
  - A4 表单校验改为提交时与离开字段时提示，打开时不标红。
  - A5 批量审批改为显式模式：列表上方「批量审批」按钮进入，只列可批量的审批并出现复选框，右侧是确认清单；「退出批量」回到普通模式。
  - A6 快捷键与「自动打开下一条」收进右上角「⚙ / ?」：快捷键说明为浮层，自动下一条为设置项（默认开）。
  - A7 已办：列表同 A2 风格，显示我的处理结果（已提交 / 已同意 / 已退回 / 已驳回）与实例当前状态，点击在右侧只读打开。
- **B 我发起的**：从「我的待办」移出，见 Q1。每行显示实例标题、流程名、当前步骤与等待人、已用时长、状态；点击右侧只读查看进度与活动。
- **C 动作目录**
  - C1 列表页：类型改为列表上方页签（带数量），列表为表格或卡片（名称、类型、被几个流程引用、状态、更新时间），点击右侧抽屉只读预览（填写人看到的样子 + 引用的流程）。
  - C2 编辑独立成页（见 Q2）：全宽，左「基本信息 / 字段 / 提交要求 / 引用」步骤导航，字段设计为「字段类型 | 表单画布 | 字段属性」三栏且画布实时显示填写效果；页头显示「未保存修改」与保存 / 放弃。
  - C3 新建先选类型：类型卡片（表单、上传文件、页面任务、人工确认；数据查询标「即将支持」不可选），选中后进入该类型的编辑页。
  - C4 编码、版本号、修改记录移到「基本信息」与页脚，修改人显示姓名；「执行人预览」改名「填写预览」。
- **D 流程定义**
  - D1 列表：卡片或表格显示名称、状态（已发布 vN / 已发布 vN · 有未发布修改 / 仅草稿 / 已停用）、最近修改人与时间、被发起次数；主操作一个（发布状态下为「发起」，仅草稿为「继续编辑」），「编辑 / 版本历史 / 停用」收进「⋯」；仅草稿的卡片缩略图显示草稿图。
  - D2 编辑器页头：流程名 + 一个状态（「草稿 · 基于 v1，未发布」/「与 v1 相同」）；问题计数实时显示（0 个问题绿色），点开为问题清单并可定位节点；按钮只保留「保存草稿」「发布」，发布时弹出确认（变更摘要 + 问题清单，有问题不能发布）。
  - D3 画布为主：节点面板收为画布左上角的竖排图标工具条（悬停说明）；属性面板选中节点 / 连线时从右侧滑出，不选时收起；节点出口与连线中点的「+」可直接插入下一个节点；操作说明收进「?」。
  - D4 节点属性按「基本 / 动作 / 审批 / 通知与回调」分组；选择动作时可「新建动作」，在抽屉里完成（复用 C2 编辑器），保存后自动选中，不离开流程编辑器。
  - D5 「启动表单」「流程设置」保留为编辑器页签，与画布同一套保存 / 发布。
- **E 去掉动作验证与提交校验（2026-10-22 用户确认）**
  - 背景：现有「验证」按类型固定（表单字段规则、文件数量 / 类型 / 安全检查、确认说明），只有参数可配，实际只有文件扫描中会走「未通过 → 重新验证」，属于形式主义。用户先确认「去掉验证」，再确认「提交要求也不要，只保留必填」（参考 Camunda 表单、飞书 / 钉钉审批：只有字段级必填，没有单独的验证阶段），节点放行选 A。
  - E1 **只保留必填**：表单字段一个「必填」开关；上传文件只有「至少上传一个」开关，不限数量与类型；人工确认、页面任务的说明一律选填。去掉「提交要求」步骤，以及长度、取值范围、文件数量 / 类型、说明必填等配置。
  - E2 **动作状态**：待处理 / 已完成 / 已取消（已取消只由系统设置：驳回、终止等）。执行人按类型填写内容后点「完成」，只检查必填；必选动作在节点进入审批前可修改后再次「完成」，进入审批后锁定；可选动作在节点放行前仍可完成；审批人「退回修改」开新一轮，动作回到待处理。
  - E3 **扫描中不挡完成；已确认未通过的文件须删除重传**：文件扫描照常进行（平台对文件本身的保护），扫描中也能完成动作或发起流程；已确认未通过安全检查（隔离 / 拒绝）的文件在发起与完成时都会被拒绝，页面标红「未通过安全检查，请删除后重新上传」，删除前「完成」/「发起」不可用。审批人在提交内容里看到每个文件「检查中 / 已通过 / 未通过」，未通过的文件不能下载。
  - E4 **节点放行（A）**：必选动作全部已完成后，审批任务才进入审批人的待办（无审批人则直接放行）；审批人点「同意」时后端再检查一次必选动作全部已完成。可选动作不影响。
  - E5 通知触发「动作验证未通过」去掉，「重新验证」去掉。
  - E6 **业务结论**（如「核查结果：合格 / 不合格」）做成表单枚举字段，网关按字段分支；系统自动核对业务事实（用数据查询）有具体流程需要时另立需求，数据查询动作类型继续标「即将支持」。
  - E7 **技术保护保留**（用户不可配置、不可见）：字段值类型正确（保证网关条件可用）、文件为本人在本实例上传、文件地址格式正确、文本长度不超过平台上限。
  - 本节修订[工作流需求](../../20261021/platform-support-工作流/requirement.md)中的 R3「验证」列、B2 动作与验证、B3「验证通过」措辞、AC-06 / AC-07 与通知触发「动作验证未通过」。

**不做（评审稿）**

- 除 E 组去掉验证外，不改工作流业务规则、状态机、表结构；接口与注册变化见技术方案第 4 节。
- 不改「流程实例」看板页（管理员视角），除非 Q1 选择把「我发起的」并入它。
- 不做移动端适配。

## 4. 待确认问题

| 编号 | 问题 | 建议 |
|---|---|---|
| Q1 | 「我发起的」放哪里？ | 建议：工作流菜单下新增「我发起的」页（与「我的待办」平级）。不并入「流程实例」，因为「流程实例」需要实例查看权限，普通发起人没有。 |
| Q2 | 动作编辑用独立页面还是大抽屉？ | 建议：独立页面（`/workflow/action-templates/:id`），字段设计需要全宽；流程编辑器里就地新建时用同一编辑器的抽屉形态（D4）。 |
| Q3 | 「超过 1 天」超时阈值固定 24 小时，还是按流程 / 节点配置？ | 建议：本期固定 24 小时，前端常量；按节点配置时限属于业务规则变更，另立需求。 |
| Q4 | 是否允许为体验新增只读接口（待办计数、等待人、动作引用数）？ | 建议：允许，限于 BFF / Platform 只读查询，阶段 3 列清单后再确认；能用现有接口推导的不新增。 |
| Q5 | 交付顺序 | 建议：阶段 2 先在 `operations-console-web/docs/operations-console.pen` 画三个页面的高保真原型（含批量审批、新建动作选类型、就地新建动作、发布确认等交互态），确认后阶段 3 写方案、阶段 4 实施、阶段 5 本机 e2e、阶段 6 mor-test。 |

## 5. 验收标准（评审稿，原型确认后细化）

| 编号 | 验收 |
|---|---|
| AC-01 | 处理人从打开「我的待办」到提交一条填写任务，不需要操作任何筛选控件；页面同时可见的控件组不超过：页签、类型切换、列表、详情、操作栏。 |
| AC-02 | 待办详情先显示背景再显示任务；操作按钮固定在底部操作栏；打开表单时不出现红色校验提示。 |
| AC-03 | 批量审批需显式进入，进入后只列可批量项；退出后回到原选中项。 |
| AC-04 | 动作编辑页在 1280 宽度下字段卡完整横排显示（不出现逐字换行）；新建动作先选类型；数据查询不可新建。 |
| AC-05 | 流程定义列表每张卡只有一个主按钮，状态文案为四种之一；停用需二次确认。 |
| AC-06 | 编辑器未选中节点时画布占满可用宽度；问题计数实时更新；发布有确认步骤；可在连线上插入节点；可在节点属性里新建动作并自动选中。 |
| AC-07 | 原有功能（发起、填写、审批、退回修改、驳回、转交、批量同意、附件上传预览、版本、停用）全部可用，自动化测试与本机 e2e 回归通过。 |
