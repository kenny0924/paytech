# platform-support：文件公开桶与固定访问地址 · 需求

状态：**阶段 1 已确认**（2026-10-22，用户“没问题，按照你的建议做”：Q1—Q3、Q5—Q10 全部按建议，Q4 已按用户意见并入）。v2 按用户意见加入：同地址覆盖更新（R8）、存储相关页面一并维护（R9—R11）。确认记录见 [delivery.md](./delivery.md)。

前置：[文件多存储并存](../platform-support-文件多存储并存/requirement.md)（第一、二段已在 mor-test，第二段提交 `73a2460d`）。

## 1. 背景

现在所有文件都按私有处理：

- 上传完成只返回逻辑地址 `fileAddress`（`/files/v1/{fileId}`），浏览器不能直接打开；
- 下载要先由业务方授权，再签发最长 60 秒的临时地址；
- 桶记录只有实例、桶名、状态，没有"公开"属性；写入路由只按来源系统选桶，一个服务只能有一条路由。

需要对外展示的文件（商户 Logo、结账页图片、公开文档等）因此无法给出可长期引用的地址。

## 2. 目标

用户提出方案 A：**单独的公开桶 + 固定地址**。

1. 桶区分私有和公开；公开桶登记一个对外基础地址（CDN 或桶的公开地址）。
2. 上传时由调用方明确声明要公开还是私有；公开文件上传完成后返回**全路径、长期有效**的公开地址。
3. 同一个服务可以同时上传公开文件和私有文件，分别落到不同的桶。
4. 私有文件的行为保持不变。
5. 支持更新文件内容而地址不变（同地址覆盖），用于 Logo、模板等需要替换的文件。
6. 运营控制台补齐存储相关页面：检查策略维护、文件记录查询。

| 编号 | 内容 |

| R3 | 写入路由按"来源系统 + 访问级别"选择桶（见 Q2），路由只能指向同访问级别的桶 |

## 4. 不做

- 不建桶、不改桶策略、不配 CDN：公开读、CloudFront、域名与证书由基础设施负责，Platform 只登记和检查（沿用前置需求的规则）。
- 不把已有私有文件转为公开，也不把公开文件转为私有；不在桶之间搬迁对象；覆盖更新不能改变访问级别、桶或来源系统。
- 运营控制台不提供上传、覆盖或删除文件的操作，只查询和下载。
- 不做公开文件的访问统计、防盗链、图片裁剪或缩略图。
- 本期只验收 AWS S3 与 MinIO（见第 7 节 Q6）。

## 5. 业务规则（草案）

- B1：公开必须由调用方显式声明。路由配置错误不能让声明私有的文件落进公开桶，反之亦然。
- B2：公开地址 = 桶的基础地址 + `/` + 对象名；对象名仍是随机 UUID，不含业务信息或原文件名。
- B3：公开文件只有在格式检查通过（`AVAILABLE`）后才对外给出地址（具体是否在检查前就可匿名读到，见 Q3）。
- B4：公开桶不能被私有上传使用，私有桶不能被公开上传使用；桶的访问级别被记录引用后不能修改。
- B5：私有文件的下载仍走现有授权 + 临时地址流程；公开文件也可以走这个流程。
- B6：只有原来源系统可以覆盖自己的文件；覆盖写入用条件写（以当前版本为前提），两个覆盖同时提交时只有一个成功，另一个返回冲突。
- B7：私有文件覆盖后，新内容检查通过前下载仍返回上一个通过检查的版本；检查不通过时保持旧版本，覆盖记为失败。
- B8：检查策略按修订生效；已开始的上传按开始时的修订检查，新修订只影响之后的上传。

## 6. 验收标准（草案）

| 编号 | 场景 | 期望 |
|---|---|---|
| AC-01 | 登记公开桶不填基础地址、或填非 HTTPS 地址 | 拒绝并说明原因 |
| AC-02 | 私有桶实际可被匿名读取 | 检查失败"桶允许匿名访问"，不能启用 |
| AC-03 | 公开桶探测对象经基础地址匿名读不到 | 检查失败"公开地址不可访问"，不能启用 |
| AC-04 | 同一来源系统分别声明公开、私有上传 | 分别落到各自路由的公开桶、私有桶 |
| AC-05 | 公开上传完成并检查通过 | 返回 `publicUrl`，匿名 GET 该地址得到原字节；私有上传 `publicUrl` 为空 |
| AC-06 | 声明公开但没有公开路由 | 返回 503（或 422，见 Q2），不回落到私有桶 |
| AC-07 | 路由指向访问级别不一致的桶 | 保存路由时拒绝 |
| AC-08 | 不传访问级别的现有调用（客户入驻、工作流附件） | 行为与现在完全一致 |
| AC-09 | 运营控制台存储管理 | 桶列表与详情显示访问级别、基础地址；路由列表与表单有访问级别、策略下拉；视觉与现有存储管理页一致 |
| AC-10 | 覆盖私有文件 | `fileId` / `fileAddress` 不变；检查通过前下载得到旧内容，通过后得到新内容；版本历史有两条 |
| AC-11 | 覆盖公开文件 | `publicUrl` 不变，匿名 GET 得到新内容（缓存行为见 Q8） |
| AC-12 | 其他来源系统覆盖、覆盖时改访问级别、两次覆盖并发 | 分别拒绝（404 / 422 / 409） |
| AC-13 | 覆盖内容检查不通过 | 旧版本继续可用，文件记录显示本次覆盖失败原因 |
| AC-14 | 检查策略：新建、修订、停用；被路由引用的策略停用 | 新修订只影响之后的上传；被引用的策略不能停用 |
| AC-15 | 文件记录页：各条件查询、详情、下载、复制公开地址 | 结果正确；下载写审计；空状态、无权限、加载失败有明确提示 |

## 7. 待确认问题

| 编号 | 问题 | 建议 |
|---|---|---|
| Q1 | 公开 / 私有由谁决定？A：调用方每次上传声明；B：只按路由配置决定 | **A**。公开是对外暴露数据的决定，应由业务方明确表达；B 下改一条路由就可能把私有材料变公开 |
| Q2 | 路由键怎么扩展？A：来源系统 + 访问级别；B：来源系统 + `reason_code`（桶自带访问级别）；C：A 再加可选 `reason_code` 细分 | **A**。满足"一个服务既公开又私有"；按 `reason_code` 细分以后有真实需要再加。找不到同级别路由时，公开上传不回落到私有默认路由 |
| Q3 | 公开文件在格式检查通过前，对象已在公开桶里，猜中 UUID 理论上可读。A：接受（UUID 不可猜，检查通过前不给地址）；B：先传到私有暂存桶，检查通过后复制到公开桶 | **A**。B 需要复制和两次存储、流程更复杂；公开桶只放本来就打算公开的内容 |
| Q4 | ~~检查策略页面是否并入~~ | 用户 v2 意见：一起做，见 R7 |
| Q5 | 公开文件要不要支持"撤下"（删除对象或标记失效）？ | 本期不做，记为遗留；覆盖（R8）可以替换内容 |
| Q6 | 本期云厂商范围：只验收 AWS S3 + MinIO，其他厂商另立兼容需求？ | 是 |
| Q7 | "同名覆盖"的含义：A：**同一文件地址**换内容（`fileId` / 公开地址不变，推荐）；B：同一来源下**同文件名**自动覆盖 | **A**。文件名可重复也可能被用户随手改，用文件名匹配容易误覆盖；业务方已持有地址，按地址覆盖更可控 |
| Q8 | 公开文件覆盖后的缓存：CDN 会缓存旧内容。A：要求公开桶 CDN 设短缓存（如 5 分钟），接受短暂旧内容；B：公开地址带版本参数（`?v=版本`），每次覆盖返回新地址、旧地址仍是旧内容；C：Platform 覆盖后调用 CDN 刷新 | **A**，同时在返回结果中给出 `versionedUrl`（带版本参数）供需要立即生效的场景使用。C 需要 Platform 持有 CDN 权限，超出"只登记不配置"的边界 |
| Q9 | 公开文件覆盖后、新内容检查通过前，公开地址已经指向新内容（桶直接对外）。接受吗？ | 接受，与 Q3 同一取舍；检查不通过时 Platform 用旧版本覆盖回去并记录 |
| Q10 | "其他存储相关页面"范围：检查策略管理（R7）+ 文件记录查询与下载（R9、R10）+ 存储管理同步（R11），是否还缺你想要的页面？ | 按此三项；上传记录（含过期 / 失败的上传）并入文件记录详情，不单独建页 |
