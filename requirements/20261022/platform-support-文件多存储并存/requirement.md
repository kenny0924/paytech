# platform-support：文件多存储并存 · 需求（评审稿 v2）

> 状态：阶段 1—3 合并评审稿 v2，按用户 2026-10-22 两轮意见修订，待用户确认。确认记录见 [delivery.md](./delivery.md)，技术方案见 [technique.md](./technique.md)。

## 1. 背景

Platform 文件模块（`paytech-platform-support-file-document`）有 MinIO 和 S3 两个适配器，但：

- **同一时刻只能装配一个**：装配条件 `files.onboarding.storage-provider == 'MINIO'`（或 `'S3'`）互斥。切换后旧文件找不到适配器，同类型也不能接多个实例。
- **账号密码和桶写在配置文件里**：`files.onboarding.minio.*` / `s3.*`、`storage-container-ref`，改动要重新部署。
- **Platform 承担业务授权**：上传绑定到 CCT 的申请和主体（`owner_ref_id = applicationId:subjectPartyId`），开始上传时 Platform 反过来调 CCT 核对权限，`t_file_owner_ref` 记录文件挂在哪个业务对象上。文件服务因此依赖业务系统，换一个业务接入就要再写一套。

## 2. 用户决定（2026-10-22）

| 编号 | 决定 |
|---|---|
| D1 | 存储实例的账号密码要能管理，不放在配置文件里 |
| D2 | 桶要能管理 |
| D3 | 内部系统之间不做文件级权限：持有文件 ID 的内部服务都可以读取。文件只记录来源系统和 `reason_code`，用于以后反查文件是谁、为什么上传的 |
| D4 | Platform 不再调用 CCT；分两段做；与工作流会话由 Claude 沟通 |

## 3. 范围

### 第一段（本需求实施）

| 编号 | 内容 |
|---|---|
| R1 | 存储实例管理：类型（MINIO / S3）、地址、区域、私有 CA、凭据方式（`STATIC` 存 Vault / `IAM_ROLE`）；新建、编辑、更换密钥、测试连接、启用、停用 |
| R2 | 桶管理：登记、启用前检查（存在、版本控制、默认加密、读写探测）、只读、停用 |
| R3 | 写入路由：按来源系统选择桶和检查策略，有默认路由 |
| R4 | 多实例同时可用：读路径按记录上原实例和桶，不受当前路由影响 |
| R5 | 文件来源字段：上传和文件记录增加 `source_system`、`reason_code` |
| R6 | 内部文件接口：开始上传、完成上传、查询文件、签发下载地址；只校验内部调用身份，不做文件级权限 |
| R7 | 运营控制台"存储管理"页面与 Operations BFF 路由，写审计 |
| R8 | 删除配置文件中的存储配置；本机、auto、mor-test 改为库中配置 |

## 4. 不做

- 不建桶、不改桶策略：建桶、版本控制、加密、生命周期、访问策略由基础设施负责，Platform 只登记和检查。
- 不在存储之间搬迁对象，不改写已有记录的存储坐标。
- 不做病毒扫描、容量监控、真实 AWS S3 验收。
- `reason_code` 不建受控目录，只校验格式（见 Q8）。

## 5. 业务规则

- B1：实例代码就是记录上的 `storage_provider`。被记录引用后，实例代码和桶名都不能改，也不能删除，只能停用。
- B2：上传创建时固定实例和桶；完成、恢复、检查、下载只用记录上的实例和桶。改路由只影响之后的新上传。
- B3：只有 `ACTIVE` 的桶接受新上传；`ACTIVE` 和 `READ_ONLY` 的桶可读；`DISABLED` 的桶或停用的实例读写都返回 503。
- B4：`source_system` 取自内部调用 Token 的服务名，调用方不能自己填；没有调用身份的请求拒绝。
- B5：内部文件接口只在私网开放，不经 Gateway 暴露。浏览器拿到的只有短时上传或下载地址；BFF 和业务服务在调用下载前自己完成业务授权。
- B6：密钥只存在 Vault，Platform 表里只有 Token。每次存储操作前读取，不缓存原值。

## 6. 验收标准（第一段）

| 编号 | 场景 | 期望 |
|---|---|---|
| AC-01 | 新建 MinIO 实例和 S3 实例（STATIC 凭据），各登记一个桶并启用 | 两个实例同时可用；密钥只出现在 Vault，Platform 表与日志无原值 |
| AC-02 | 桶启用检查：不存在、未开版本控制、未开加密、无写权限 | 分别拒绝启用并给出原因 |
| AC-03 | 路由：来源系统 A 指向桶 1，默认指向桶 2 | A 的上传落到桶 1，其他来源落到桶 2 |
| AC-04 | 把路由从实例 MINIO 改到 S3 后，读取旧 MINIO 文件 | 下载、格式检查照常 |
| AC-05 | 记录的桶被设为 `READ_ONLY` | 可读，不接新上传 |
| AC-06 | 记录的桶或实例被停用 | 读写返回 503，无存储调用 |
| AC-07 | 更换密钥 | 新 Token 生效，之后的操作使用新密钥；旧 Token 不再引用 |
| AC-08 | Vault 不可用 | STATIC 实例的操作返回 503；IAM_ROLE 实例不受影响 |
| AC-09 | 内部接口无调用身份 | 拒绝；有身份时 `source_system` 等于 Token 服务名，与请求体无关 |
| AC-10 | 已有入驻文件 | 迁移后 `source_system`、`reason_code` 已回填，入驻上传和审核下载仍可用（第一段不改入驻链路） |
| AC-11 | 配置文件仍有旧存储键 | 启动失败并提示改到存储管理 |
| AC-12 | 现有适配器、上传、完成、检查、审核下载测试 | 迁到库中配置后全部通过，覆盖率门槛不降 |
