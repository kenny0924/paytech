# platform-support：数据查询服务（data service）· 需求

> 状态：**阶段 1 已确认**（2026-10-22 用户“可以，没问题，继续吧”）。Q1—Q6 已于 2026-10-22 回复，新增统一模板语法（第 7 节）。确认记录见 [delivery.md](./delivery.md)，技术方案见 [technique.md](./technique.md)（阶段 2—3 评审中）。

## 1. 背景

- **运营查询没有统一入口。** Operations 控制台的列表、统计、核对类查询都要由 Owner 服务逐个开发只读接口，BFF 再逐个对接。这类需求小、数量多，排期总是落后。
- **原规划的数据服务只有骨架。** [目标架构 V2](../../../agent-docs/decisions/2026-10-17-target-architecture-v2.md) 的 D25 / D35 规划了独立服务 `paytech/data-service`：Flink CDC 把白名单表同步到 Doris，服务在 Doris 上做只读查询。目前只完成阶段 0（模块骨架、CDC 白名单校验、Doris 健康检查），没有查询能力。本地 Doris 加 Flink 约需 4.75 GiB 内存，`mor-test` 未接入。
- **工作流已为它留了位置。** [工作流需求](../../20261021/platform-support-工作流/requirement.md)把 `DATA_QUERY` 动作预留给 data-service（C7），用 data-service 维护的 SQL 验证节点是否完成。

用户 2026-10-22 决定：

- data service 放进 Platform Support，作为独立模块，不单独部署服务。
- 数据源可以动态配置多个库。生产通常读写分离，配置的多数是**从库**，不担心查询压到主库。
- 本期调用方是 `operations-console-bff`。
- 首期只实现 JDBC 类引擎，其余引擎预留扩展点。
- 行数、超时、分页等约束由每个模板自己定义。
- 模板语法所有引擎保持一致，不用 MyBatis，自定义解析。
- 模板不做复核，修改后直接生效；不做权限码绑定。

## 2. 目标

1. 运营可以随时新增、停用、删除数据源，例如某系统的 MySQL 从库，不需要重启。
2. 运营在模板中写好查询，调用方只传模板编码和参数即可得到结果，不再为每个查询开发接口。
3. 一套模板语法支持占位符、条件片段、集合展开与循环，所有引擎共用，并从语法上杜绝注入。
4. 服务在任何层面都不能修改数据库。
5. 引擎可扩展：以后接入 PG、ClickHouse、ES、MongoDB 时，不改调用合同，也不改模板语法。

## 3. 概念

| 概念 | 说明 |
|---|---|
| 数据源 | 一个可查询的数据库实例连接（默认库可选，不填即整个实例），包括编码、引擎类型、连接参数、只读账号（密码存 Vault）、连接池与超时上限、状态 |
| 引擎 | 按数据源类型选用的执行实现，实现统一的 SPI。首期为 JDBC（MySQL 协议，覆盖 MySQL 与 Doris） |
| 查询模板 | 一条可复用的查询，包括编码、所属数据源、正文、参数声明、出参列声明、约束 |
| 模板版本 | 每次保存生成一个新版本号并立即生效，历史版本保留，可查看、对比，可从历史版本恢复 |
| 参数声明 | 参数的名称、类型（含集合与对象集合）、是否必填、默认值、取值约束；集合另有最大长度 |
| 片段参数 | 声明了可选值的枚举参数，每个值映射到一段固定正文，用于排序字段这类无法用值绑定的位置 |
| 系统参数 | `__` 开头的参数，例如 `__operator.accountId`，由服务端从调用身份注入，调用方不能传入 |

- **R1 归属调整：** 新增决定记录，包含以下内容：

  - 写明“各系统禁止跨库读取”的受控例外：只能经只读账号读取已登记的数据源，仅用于 Operations 查询和工作流验证，结果不作为业务执行依据。

  - 编辑后版本号加 1，多个实例在秒级内切到新配置，不需要重启。
  - 停用后不再接受新查询，进行中的查询完成或超时后再关闭连接池。
  - 仍被启用模板引用的数据源不能删除。
  - 启用前做只读权限自检（B5）。
- **R3 查询模板管理：**
  - 新建、编辑、试运行、启用、停用、版本历史与对比、从历史版本恢复。
  - 保存时做合法性校验（B2），通过后立即生效，不需要复核。
  - 试运行使用编辑中的内容，不保存，受同样的约束。
- **R4 统一模板语法：** 不使用 MyBatis。平台自带一个小型模板解析器，所有引擎共用同一套语法，见第 7 节。
  - 正文先解析成语法树，再交给各引擎的值绑定器输出：JDBC 输出 `?` 加绑定参数，以后 ES / Mongo 输出安全的 JSON 字面量。
  - 参数值只能经绑定器输出，永远不作为文本拼接进正文。
  - 参数规则见 B3。
- **R5 查询执行：**
  - 内部接口 `POST /internal/data-queries/{templateCode}/execute`：
    - 入参：参数、分页参数。
    - 出参：列定义、数据行、分页信息（含 `hasMore`，总数可选）。
  - 由 `paytech-platform-support-api` 发布 `@HttpExchange` 合同。
  - Platform 进程内的工作流 `DATA_QUERY` 调用同一个领域服务，接入工作属于工作流的后续切片。
- **R6 模板约束：** 每个模板定义以下约束，均不得超过系统硬上限（B4）：
  - 最大行数；
  - 超时；
  - 分页方式：不分页、偏移分页、游标分页；
  - 是否允许返回总数；
  - 出参列的屏蔽规则（可选）。
- **R7 引擎扩展点：**
  - 定义 `QueryEngine` SPI，分为值绑定、渲染后校验、执行三部分。
  - 首期实现 JDBC，覆盖 MySQL 与 Doris 方言。
  - PG、ClickHouse 以后作为 JDBC 方言接入。
  - ES（Query DSL）与 Mongo（aggregate pipeline）以后各自实现绑定器和执行器，模板语法与调用合同不变。
- **R8 查询审计：** 2026-10-22 用户决定取消，不建查询记录表，执行只留普通应用日志与指标。
- **R9 Operations 页面与注册：**
  - 页面：
    - 数据源：列表、编辑、测试连接。
    - 查询模板：列表、编辑器（语法高亮与错误定位）、参数配置、试运行、版本。
  - 注册：新增 Console Resource、权限、Route。块号在阶段 3 按 live `mor_platform` 选定，避开已登记的 127、128、129、130。

## 5. 不做

- 任何写操作，包括写数据源和导出文件。导出另立需求。
- PG、ClickHouse、ES、MongoDB 引擎实现（本期只预留 SPI）。
- 经 Gateway 对 Client / Partner 开放、租户过滤。系统参数机制保留，以后开放时使用。
- 模板复核（Maker-Checker）、模板绑定权限码。操作人能否进入页面由 BFF 按页面权限判断。
- 结果缓存、异步大查询、定时报表、跨数据源联查。
- 从库建设、主从同步与延迟监控，这些归 DBA 和基础设施。
- 详情页与“操作前校验”继续实时读 Owner 接口（D25 原则保留）。从库有复制延迟，查询结果不作为业务执行依据。

## 6. 业务规则（草案）

- **B1 数据源：**
  - 编码全局唯一，不可修改。
  - 密码只存 Vault Token，不回显，不进日志。
  - 连接池大小、单查询超时、并发上限都有系统硬上限。
- **B2 保存校验：** 保存时逐项校验，不满足的不能保存，并指出行号和原因：
  - 正文能被解析器解析：块标签成对，表达式合法，没有未知标签。
  - 正文引用的参数都已声明；声明了但未使用的参数给出警告。
  - 片段参数的每个可选值都映射到非空片段。
  - 解析器展开所有分支，并对每种集合分别取空集合和一个元素，生成用于校验的组合。JDBC 引擎对每个组合生成的 SQL 都要通过 B5 第 3 层校验，组合数有上限。
  - 引用的数据源处于启用状态。
  - 约束取值不超过硬上限。
- **B3 参数：**
  - 调用方传入的参数按声明校验类型、必填、范围、集合长度。未声明的参数直接拒绝，不静默忽略。
  - `__` 开头的系统参数只能由服务端注入。
  - 渲染时遇到空集合直接放进 `#{}` 会报错。模板必须用 `{{#if}}` 包住，或改用 `{{#each}}`。
- **B4 约束：**
  - 返回行数不超过 `min(模板最大行数, 系统上限)`，命中上限时 `hasMore=true`。
  - 超时则取消查询，返回明确的超时错误码。
  - 偏移分页的最大偏移量有上限。
- **B5 只读，多层防护：**
  1. 数据源账号必须只读。启用前用 `SHOW GRANTS` 自检，发现任何写权限或 DDL 权限就拒绝启用。
  2. 连接设为 `readOnly`，事务只读，`allowMultiQueries=false`。
  3. 保存与每次执行都用 SQL 解析器检查渲染结果：只允许单条 `SELECT` / `WITH … SELECT`；拒绝 `INTO OUTFILE`、`FOR UPDATE`、`LOCK IN SHARE MODE`，以及加锁或有副作用的函数。
  4. 服务不提供任何写数据源的入口。
- **B6 授权：** 调用方必须是登记的内部服务，本期只有 `operations-console-bff`。操作人需有执行权限，不做模板级权限判断。
- **B7 屏蔽：** 出参列可以声明屏蔽规则（不返回、全部掩码、保留首尾若干位），在服务端执行。不声明即原样返回。

## 7. 统一模板语法（草案 v1）

所有引擎共用以下语法，不依赖 MyBatis、Mustache 或其他第三方模板库。解析器由本模块自行实现，只认这几种标签，没有脚本能力。

| 语法 | 作用 | JDBC 输出 | 以后 ES / Mongo 输出 |
|---|---|---|---|
| `#{name}`、`#{item.field}` | 值占位 | `?` 加绑定值 | JSON 字面量（字符串转义、数字、布尔、null） |
| `#{ids}`（集合参数） | 集合自动展开 | `?, ?, ?` | `["a","b","c"]` |
| `@{sortBy}` | 片段参数，按声明的可选值输出固定片段 | 片段原文 | 片段原文 |
| `{{#if 条件}} … {{#elseif 条件}} … {{#else}} … {{/if}}` | 条件块 | — | — |
| `{{#each list as item, i separator=" OR "}} … {{/each}}` | 循环 | — | — |
| `{{#join " AND " prefix="WHERE "}} … {{/join}}` | 拼接：直接子块非空的用分隔符连接；全为空时前缀也不输出。可代替 MyBatis 的 `<where>` / `<trim>`，JSON 中也能处理逗号 | — | — |
| `{{!-- 注释 --}}` | 注释，不输出 | — | — |
| `\#{`、`\@{`、`\{{` | 转义，原样输出 | — | — |

条件表达式只支持以下几种形式，不支持函数调用和脚本：

- `name`：非空。非 null；字符串非空白；集合非空。
- `!name`
- `name == 'X'`、`name != 'X'`、`>`、`>=`、`<`、`<=`
- `&&`、`||`、括号

示例一（JDBC）：

```sql
SELECT order_id, client_id, amount, status, created_at
FROM t_order
{{#join " AND " prefix="WHERE "}}
  {{#if clientId}}client_id = #{clientId}{{/if}}
  {{#if statuses}}status IN (#{statuses}){{/if}}
  {{#if from}}created_at >= #{from}{{/if}}
  {{#if conditions}}({{#each conditions as c separator=" OR "}}(channel = #{c.channel} AND amount > #{c.minAmount}){{/each}}){{/if}}
{{/join}}
ORDER BY @{sortBy}
```

传入 `{"statuses":["PAID","REFUNDED"],"sortBy":"NEWEST"}`，片段参数 `sortBy` 声明为 `NEWEST → created_at DESC`，生成：

```sql
SELECT … FROM t_order WHERE status IN (?, ?) ORDER BY created_at DESC   -- 绑定 ["PAID","REFUNDED"]
```

示例二（以后的 ES）。写法与示例一相同，用的也是 `join`：

```json
{ "query": { "bool": { "filter": [
  {{#join ","}}
    {{#if clientId}}{ "term": { "client_id": #{clientId} } }{{/if}}
    {{#if statuses}}{ "terms": { "status": #{statuses} } }{{/if}}
  {{/join}}
] } } }
```

## 8. 验收标准（草案）

| 编号 | 验收标准 |
|---|---|
| AC-01 | 新增 MySQL 从库数据源并测试连接通过后，不重启即可被模板使用；修改连接参数后，各实例在设定的刷新周期内切到新配置 |
| AC-02 | 数据源账号带任何写权限或 DDL 权限时不能启用，并提示具体权限 |
| AC-03 | 停用数据源后新查询返回明确错误，进行中的查询正常结束；被启用模板引用的数据源不能删除 |
| AC-04 | 第 7 节全部语法按示例正确渲染：值占位、集合展开、片段参数、if / elseif / else、each（含对象集合与分隔符）、join（含全空时不输出前缀）、注释、转义 |
| AC-05 | 标签不成对、未知标签、表达式非法、引用未声明参数、任一展开组合生成多条语句或非 SELECT 的模板不能保存，错误指出行号与原因 |
| AC-06 | 以 `INSERT` / `UPDATE` / `DELETE`、DDL、`SELECT … FOR UPDATE`、`INTO OUTFILE`、多语句和参数值注入尝试试运行或调用，全部被拒绝，数据源数据不变 |
| AC-07 | 传入未声明参数、类型不符、缺少必填、集合超长、`__` 系统参数、片段参数的非声明值，返回字段级错误 |
| AC-08 | 返回行数不超过模板上限，超出时 `hasMore=true`；超时后查询被取消，返回超时错误码 |
| AC-09 | 保存模板后立即生效并生成新版本号；结果带版本号；可查看历史版本、对比、从历史版本恢复 |
| AC-10 | 声明了屏蔽规则的列在响应中按规则屏蔽或不返回 |
| AC-11 | （取消：不做查询记录，2026-10-22 用户） |
| AC-12 | 非登记调用方被拒绝 |
| AC-13 | 引擎 SPI 有 JDBC 实现，MySQL 与 Doris 方言能通过同一模板合同查询（Doris 为 manual 测试） |
| AC-14 | Operations 页面：数据源、模板（编辑器含错误定位、试运行）均可用，空状态与错误反馈完整 |

## 10. 阶段安排（建议）

按默认 8 个阶段推进。阶段 2 与 3 合并评审，因为现状差异小，主要工作是新模块设计。

| 阶段 | 内容 |
|---|---|
| 1 | 需求评审，即本稿 |
| 2—3 | 现状差异与技术方案：模块分层、表与 PDManer、接口、SPI、解析器文法与语法树、只读校验、多实例刷新、页面原型 |
| 4 | 研发 |
| 5 | 综合验证 |
| 6—7 | mor-test 发布准备与部署 |
| 8 | 提交归档 |

SQL 执行、部署、提交分别单独授权。
