**第 1 次唯一失败**：`refund.created` 冻结在 PENDING、version 1，而 test 上退款提交任务（Commerce 未接 Payment 退款）在脚本随后 GET 之前已把退款推进到 PROCESSING v2，比对出 3 个字段差异。这是脚本时序问题，不是产品缺陷：本机验证时 GET 恰好先完成，Commerce auto 测试也对这三个字段做了同样的还原。修正后脚本断言事件为 PENDING/v1，其余字段逐字比对。

**已知限制（阶段 1—2 已接受）**
- 建单使用 Commerce 内固定 Mock：CCT 商业事实（主体 `AE001`）、零税、假合同文档、Consumer 保护。
- `order.paid` 来自 PaymentSucceeded 夹具与手工 Intent 投影行（test 无 Payment）。
- Gateway 不处理 `Idempotency-Key`，只转发，不重放响应。
- 结账查询路由未登记（Commerce 未实现）。
- 退款提交任务先 `ERROR / INTERNAL_ERROR`、现为 FAILED（Commerce 未接 Payment 退款；退款保持 PROCESSING 与预占）；该任务 `event_type` 为字面值 `SUBMISSION_EVENT_TYPE`（既有代码）。
- Platform 或 Commerce 重启后约 1 分钟内，扫描触发会因执行器尚未重新进入组地址而失败（Admin 每 30 秒刷新地址），之后自动恢复。
