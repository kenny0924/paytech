# Finance 期间重开与年末结转

状态：阶段 1 已确认（2026-10-17）：用户回复“继续”，范围与 D1—D6 按建议执行。

## 1. 背景与目标

FIN-22 后半部分与 [Finance 数据库设计](../../../agent-docs/database/FINANCE_DATABASE.md) §6.6、全局不变量 15：已关闭期间需要可控地重开——新建 `close_type=REOPEN` 的流程，引用原关账、冻结重开原因与摘要并双人审批，不覆盖原关账证据；期间状态 CLOSED → REOPENING → OPEN（失败或驳回回到 CLOSED）。同时补齐“收入/费用 → 本期损益 → 留存收益”的第二段：财年最后一个期间关账时把本期损益全年累计转入留存收益。

期间关账（[2026-10-16 需求](../../20261016/finance-期间关账/requirement.md)）已实现 CLOSE 流程；本需求只做 Finance 内部闭环，不依赖其他系统。

使用者：Finance 内部与运营核对人员（内部开发接口，不接 Gateway/授权，Maker/Checker 由请求传入）。

## 2. 本期范围

| # | 内容 |
|---|---|
| P1 | 发起重开：Maker 提交原因代码与外部申请编号；期间 CLOSED → REOPENING；规划“冲回原关账结转分录”的指令行；冻结重开摘要（原因、原关账摘要、影响账簿、冲回行）；进入 PENDING_CHECK |
| P2 | 审批 / 驳回：Checker ≠ Maker 且确认同一摘要；批准 → 同一事务按账簿过账 REOPENING 冲回分录、期间回到 OPEN、流程 COMPLETED；驳回 → 期间回到 CLOSED、流程 REJECTED，不留任何分录 |
| P3 | 年末结转：关闭财年最后一个期间时，在损益结转之后把各账簿 `CURRENT_PERIOD_RESULT` 的累计余额转入 `RETAINED_EARNINGS`（同一条结转指令的额外行）；重开该期间时一并冲回 |
| P4 | 查询：沿用现有关账列表与详情接口，返回 REOPEN 流程及其引用的原关账 |

## 3. 明确不做

跨期间连锁重开、部分账簿重开、其他异常处置（Recon Resolution、Controlled Waiver）、调度任务、Gateway/授权、页面。

## 4. 已确认决定

| # | 决定 |
|---|---|
| D1 | 只能重开最近一个已关闭期间：同一日历中晚于它的期间不得处于 CLOSED 或 CLOSING |
| D2 | 冲回分录在审批通过时过账：发起时只规划并冻结冲回行；过账与期间回到 OPEN 在审批事务中一起完成；驳回不留分录 |
| D3 | 重开冲回原关账的结转（含年末结转行），REOPENING 指令；再次关账时按当时余额重新结转 |
| D4 | 财年最后一个期间 = 同一日历、同一财年中期间号最大的期间；年末结转作为同一条结转指令的额外行 |
| D5 | 重开流程不执行关账的 7 个步骤，只执行锁定水位、规划冲回、冻结摘要；重开后期间 OPEN，再关账时完整重新校验 |
| D6 | 内部开发接口，Maker/Checker 由请求传入，与关账一致 |

## 5. 验收标准（草案）

| 编号 | 标准 |
|---|---|
| AC-1 | 发起重开：CLOSED 期间进入 REOPENING，流程 PENDING_CHECK 且摘要冻结；非 CLOSED 期间、非最近关闭期间、已有活动流程均被拒 |
| AC-2 | 批准：REOPENING 冲回分录逐账簿过账，原结转科目恢复（收入/费用回到关账前余额，本期损益/留存收益相应冲回），期间 OPEN，流程 COMPLETED；REOPEN 流程引用原关账 |
| AC-3 | 驳回：期间回到 CLOSED，无冲回分录；同一原关账可再次发起重开 |
| AC-4 | 重开后普通过账恢复；再次关账得到新的流程编号，结转按当时余额重新计算；原关账证据保持不变 |
| AC-5 | 年末：财年最后期间关账后本期损益为 0、留存收益等于全年利润；非年末期间不做此结转；重开年末期间一并冲回 |
| AC-6 | Maker 自审、摘要不一致、重复批准被拒；`clean verify` 通过 |

## 6. 适用阶段

阶段 1—5；如涉及模型或本地 SQL 在阶段 3 单独授权；阶段 4 继续使用多 agent 并行；提交另行确认。
