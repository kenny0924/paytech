## 1. 背景

现有 Code-MoR 以六个核心系统 + Gateway + 三个 Console BFF + Vault 的形态建设，定位为 Merchant of Record 平台，MVP 聚焦 USD、一次性支付与 Hosted Checkout。用户决定在此基础上重构为一个**可装配的多实例支付平台**：

- 业务模式同时覆盖 MoR 与 PSP，由合同上的「业务模式」属性驱动卖方记录、税务责任与资金路径；
- 一套软件部署为多个完全隔离的实例：自营主站，以及为代运营伙伴部署的独立实例；
- 实例按产品订阅装配可选模块（卡收单、出款、外汇、争议、数据与分析等），不售卖的模块不部署；
- 实例内支持多品牌白标；
- 由独立的多实例运维平面统一部署、升级、下发配置与监控，但不接触任何实例的业务数据。

用户原始画板按接入 / 产品 / 核心 / 基础四层罗列能力；两轮外部评审（17 条 + 20 条）与多轮选项确认后形成本目录的 V2 讨论稿。

## 2. 目标

1. 给出一份边界自洽的目标服务划分：每个跨边界的事实有唯一裁决者，每个中间状态有持有者。
2. 明确业务模式、资金一致性、取消裁决、事件顺序、读模型、服务间身份、模块装卸、品牌、运维权限等跨系统决策，并登记状态。
3. 给出从现有六系统到目标架构的映射与迁移路径，以及首批可执行的契约工作。

## 4. 不做项

- 不修改现有运行系统的任何代码、Schema、配置或部署。
- 不在本期把现行 `agent-docs/` 权威改写为目标架构；现行文档继续描述运行系统，目标架构以 Proposed 决定草案并行存在，直到各切片按需求交付流程逐一落地。
- 不实现任何服务拆分、数据迁移或新服务；"阶段 0 立契约"及后续切片另行登记需求。
- 不做地理分站（D23 待定）、卡域独立部署条件（D10 待定）、迁移成熟度证据表（D15 待定）的设计。
