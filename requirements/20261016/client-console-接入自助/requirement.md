# Client Console 接入自助（API 凭证与 Webhook）— 需求

> 状态：2026-10-16 夜阶段 1。用户授权“等租户与工作区开发完后立马做这个……不用等我授权”，各阶段待决项由 Claude 按建议决定并记录在 [delivery.md](./delivery.md)，用户醒来可逐条推翻。

## 1. 来源与背景

- 来源：用户 2026-10-16“帮我分析一下【接入（API 凭证、Webhook）】的需求”，并要求在租户与工作区开发完成后立即实施。
- 客户审核通过、进入工作区后，要用 API 接入平台下单收款，并接收订单、退款等事件通知。目前这两件事都只能由运营代办：
  - **API 凭证**：Platform 已有凭证数据模型（`t_api_credential`、`t_api_credential_scope`，按 Tenant 归属，Argon2id 校验）、Gateway Bearer 认证链（PLT-I03）和运营侧查看与紧急撤销，已部署 mor-test；**没有任何生成凭证的代码**，客户无法自己创建（[ClientAPI 接入管理需求](../../20260913/platform-support-ClientAPI接入管理/requirement.md) 写明“Client 自助另期”）。
  - **Webhook**：Platform Webhook 投递已本地提交 `ee469e0`，管理入口只给运营代配置（[Webhook 投递需求](../../20261015/platform-support-Webhook投递/requirement.md) D-02、明确不做“Client Console 自助管理”）。
- 权威约定：PLT-02（凭证由 Platform 拥有，日常创建 / 轮换 / 撤销由 Client Console 自助完成）、PLT-03 / PLT-I07 / PLT-I08（Client Webhook 地址、订阅、投递状态），CLIENT_CONSOLE 能力“管理 API Key、Webhook 和团队权限”；PLT-I02 的目标调用方包含 Client Console BFF。

## 2. 使用者与目标

| 使用者 | 目标 |
|---|---|
| 工作区 OWNER（当前唯一成员） | 在工作区里自己创建、查看、轮换、撤销 API 凭证；自己配置 Webhook 端点、订阅事件、轮换签名密钥、发测试事件、查看投递并重发 |
| 运营 | 保留现有代办与紧急撤销能力，与客户自助并存 |

## 3. 本期范围

| 编号 | 功能 |
|---|---|
| F-01 | 工作区权限底座：Platform 提供 CLIENT 渠道权限判断（PLT-I02 CLIENT 版）；新增客户权限码 `CLIENT_API_CREDENTIAL_READ/MANAGE`、`CLIENT_WEBHOOK_READ/MANAGE`，授予工作区 `TENANT_OWNER` 角色（新开通与已开通工作区都有）；BFF 对每个凭证 / Webhook 请求先校验租户上下文再调权限判断 |
| F-02 | API 凭证列表与详情：名称、前缀、状态、Scope、创建时间、到期时间、轮换来源；不返回密钥与校验值 |
| F-03 | 创建凭证：填写名称、选择 Scope（V1 目录内，至少一个）、选择有效期（30 / 90 / 180 / 365 天，默认 365）；密钥**只在创建响应中显示一次**，页面提供复制与“我已保存”确认 |
| F-04 | 轮换凭证：生成新凭证（继承名称与 Scope），旧凭证按所选宽限期失效（立即 / 1 小时 / 24 小时 / 7 天，默认 24 小时）；新密钥同样只显示一次 |
| F-05 | 撤销凭证：二次确认后立即失效；已撤销再撤销返回原结果 |
| F-06 | Webhook 端点列表、新建、修改（地址、订阅事件、说明）、启用 / 停用；新建时签名密钥只显示一次 |
| F-07 | Webhook 签名密钥轮换（1 小时双签宽限或立即作废），新密钥只显示一次；发送 `webhook.ping` 测试事件 |
| F-08 | Webhook 投递列表（按端点、事件类型、状态、时间筛选）与详情（各次尝试的 HTTP 状态、粗粒度失败原因、耗时），单条重发 |
| F-09 | 工作区导航增加“开发者”分组：API 凭证、Webhook；无权限时不显示且接口拒绝 |

## 4. 本期不做

- test / live 双环境区分（每个部署环境本身就是一套）。
- 凭证最后使用时间（需要在每次 API 认证的热路径写库）、单凭证 IP 白名单、操作二次认证（step-up）与邮件通知。
- 公共 API `/api/v1/webhooks/**` 与 `/api/v1/api-keys/**`（只在 Console 内提供）。
- 删除 Webhook 端点、批量重发、连续失败自动停用。
- Platform 下发菜单（PLT-I21）与 Console Resource 注册；团队成员、自定义角色。
- 首次真实业务 API 开通（Commerce 事件源、Scope 生效验收）——PLT-02 原文另期；本期只保证凭证能通过 Gateway 认证。
- Integration Readiness（PLT-I13）推导。

## 5. 验收标准

### 功能

| 编号 | 场景 | 期望 |
|---|---|---|
| AC-01 | 账号上下文或其他工作区的成员调用凭证 / Webhook 接口 | 拒绝；不能通过路径或参数指定别的客户 |
| AC-02 | 创建凭证 | 返回一次完整密钥；之后列表与详情不再出现；该密钥经 Gateway 调用 Client API 能通过认证并带上本客户身份 |
| AC-03 | 凭证数量上限 | 每个工作区有效（ACTIVE）凭证最多 10 个，超出拒绝并提示 |
| AC-04 | 轮换 | 新凭证可用；旧凭证在宽限期内仍可用、到期后认证失败；选“立即”时旧凭证马上失效 |
| AC-05 | 撤销 | 撤销后新请求认证失败；运营与客户同时撤销同一凭证不出错 |
| AC-06 | 用凭证 ID 操作别的工作区的凭证 | 返回“不存在”，不泄露是否存在 |
| AC-07 | Webhook 新建 | 地址经 SSRF 校验（拒绝内网、非 HTTPS 等，沿用现有规则）；每个客户最多 5 个端点（含已停用）；密钥只显示一次 |
| AC-08 | 用端点 ID / 投递 ID 操作别的工作区的数据 | 返回“不存在” |
| AC-09 | 测试事件与重发 | 测试事件同步发送，结果（HTTP 状态 / 失败原因）立即显示在页面上，不生成投递记录（N13）；已结束（成功、放弃、已取消）的投递可重发，生成新投递，事件 ID 与内容不变；未结束的投递不提供重发 |
| AC-10 | 投递详情 | 只显示客户可见字段（HTTP 状态、失败分类、耗时、请求地址）；不显示运营账号、运营备注、内部系统名、内部事件主键 |
| AC-11 | 权限 | 没有对应权限的成员看不到菜单，接口返回 403（本期只有 OWNER，用测试夹具验证） |
| AC-12 | 安全 | 密钥不进入日志、错误正文、审计和浏览器存储；一次性密钥响应 `Cache-Control: no-store`；所有写操作有审计，记录客户账号 |

### 视觉 / 交互

| 编号 | 期望 |
|---|---|
| UI-01 | 工作区侧边栏“开发者”分组下有 API 凭证、Webhook 两项 |
| UI-02 | 一次性密钥弹窗：明显提示“关闭后无法再次查看”，提供复制按钮，需勾选“我已安全保存”才能关闭 |
| UI-03 | 撤销、轮换（立即失效）、停用端点有二次确认，写明影响 |
| UI-04 | 列表有空状态与加载失败状态；桌面与 390px 可用 |

## 6. 关键决定（夜间按建议；2026-10-17 用户复核“全部确认”）

| 编号 | 问题 | 决定 |
|---|---|---|
| N1 | test / live 区分 | 不区分 |
| N2 | 凭证有效期 | 必填，30 / 90 / 180 / 365 天可选，默认 365；不提供永不过期 |
| N3 | 每个工作区凭证上限 | 有效凭证最多 10 个 |
| N4 | 轮换宽限期（原 ClientAPI 需求 Q1） | 立即 / 1 小时 / 24 小时 / 7 天，默认 24 小时 |
| N5 | 凭证名称 | 需要，1—64 字符（需给 `t_api_credential` 加名称列，阶段 3 给出 DDL）；不做最后使用时间 |
| N6 | IP 白名单、二次认证、邮件通知 | 本期不做，列为风险 |
| N7 | 谁能管理 | 工作区 OWNER（权限码授予 `TENANT_OWNER`）；后续团队角色按权限码复用 |
| N8 | 客户自助与运营代配置 | 并存；同一对象并发修改由现有版本号 CAS 处理；审计区分渠道 |
| N9 | Webhook 端点上限与删除 | 沿用 5 个（含停用），不支持删除 |
| N10 | Webhook 重发 | 允许单条重发，频率由 Gateway 现有限流约束 |
| N11 | 导航 | 侧边栏写死“开发者”分组，按 BFF 返回的权限能力显示 / 隐藏，暂不接 PLT-I21 |
| N12 | 只有测试事件可收 | 接受；Commerce 事件源另行实现，页面事件订阅列表展示 8 种业务事件 |
| N13 | 测试事件是否进入投递记录 | 不进入：沿用现有 Webhook 设计的同步测试（运营入口相同），结果当场显示；2026-10-16 夜阶段 5 发现原 AC-09 与实现不一致后按此决定 |
