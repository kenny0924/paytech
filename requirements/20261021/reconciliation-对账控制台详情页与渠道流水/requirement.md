# reconciliation 对账控制台：详情改二级页面与渠道流水页

> 状态：阶段 1—3 已确认（2026-10-21），阶段 4—5 进行中。确认记录见 [delivery.md](./delivery.md)，方案见 [technique.md](./technique.md)。前序需求：[渠道资金对账切片 1](../../20261020/reconciliation-渠道资金对账切片1/requirement.md)（main `2f5f37f7`，已部署 mor-test）。

## 1. 背景与来源

切片 1 上线后用户在 mor-test 查看对账控制台（2026-10-21）：

- "为什么只有平台流水？外部流水记录没有吗？"——渠道账单行只能在单张账单的抽屉里看，不能跨账单查；银行流水在「银行对账」页且默认只显示未匹配。
- "那优化一下，作为二级页面展示吧，不要从右侧抽屉拉出来"。
- 用户选择（AskUserQuestion）：**所有对账详情**改为二级页面（录入表单仍用抽屉）；**加「渠道流水」页**；阶段 **1—3 合并**确认。

当前事实：对账 7 页的详情都在右侧抽屉（清算账户、银行账户、渠道账单、银行流水、对账异常）；银行对账单没有单独详情；reconciliation 没有跨账单的渠道账单行查询，也没有按 ID 读银行对账单头、银行流水的接口。控制台已有"列表 → 详情页"先例（渠道、MID、商务合同，`menu.ts` 的 `pageRoutePaths`）。

## 2. 使用者与目标

财务运营：从列表点一行进入独立详情页，地址可分享、可刷新、可后退；能跨账单查渠道流水，按外部交易号找到它在哪张账单、匹配到哪笔平台流水。

## 3. 本期范围

1. **详情页（Web，同一菜单页下的子路由，不新增菜单）：**
   - 清算账户 `/finance/reconciliation/clearing-accounts/:clearingAccountId`：基本信息、配置、所含 MID（挂 / 摘）、相关账单入口。
   - 银行账户 `/finance/reconciliation/cash-accounts/:cashAccountId`：信息、复核状态与复核 / 申请关闭操作。
   - 渠道账单 `/finance/reconciliation/statements/:statementId`：账单头、对平门禁、**全部账单行表格**（分页、按匹配状态 / 行类型筛选）、相关异常、作废。
   - 银行对账单 `/finance/reconciliation/bank/statements/:bankStatementId`：头、期初期末、全部流水。
   - 银行流水 `/finance/reconciliation/bank/lines/:bankStatementLineId`：流水信息、匹配建议与已确认匹配、确认 / 拒绝、手工多选匹配、人工开异常。
   - 对账异常 `/finance/reconciliation/exceptions/:exceptionId`：来源对象摘要（可跳转到来源详情页）、处置历史；提交处置、复核仍用抽屉。
   - 各详情页之间的引用（平台流水 ↔ 账单行、异常 ↔ 来源对象、银行匹配 ↔ 预期银行流水 / 账单）改为链接跳转。
2. **渠道流水页（新菜单页，财务 → 对账）** `/finance/reconciliation/channel-lines`：跨账单列出渠道账单行，筛选清算账户、账单状态（默认排除已作废）、匹配状态、行类型、外部交易号、交易日期；列出所属账单、匹配到的平台流水、实际费用；点行进入所属渠道账单详情页并定位该行。
3. **接口：** reconciliation 新增 `GET /reconciliation/v1/channel-statement-lines`（跨账单查询）、`GET /bank-statements/{id}`、`GET /bank-statement-lines/{id}`；BFF 对应转发；Platform 块 126 注册新菜单页与 3 条路由。
4. **抽屉保留：** 新建清算账户 / 银行账户、导入账单与对账单、提交处置、复核。

## 5. 验收标准

**功能**

| 编号 | 验收标准 |
|---|---|
| AC-01 | 6 类详情都可通过地址直接打开、刷新不丢失、浏览器后退回到列表（保留列表筛选与页码）；ID 不存在时显示"未找到"并可返回列表 |
| AC-02 | 渠道账单详情页列出该账单全部行（分页），可按匹配状态、行类型筛选；对平门禁与作废操作与原抽屉一致 |
| AC-03 | 银行对账单详情页与银行流水详情页可用；流水详情页的确认 / 拒绝建议、手工多选匹配、人工开异常与原抽屉行为一致 |
| AC-04 | 异常详情页显示来源对象并可跳转；提交处置与复核在抽屉中完成，完成后详情页刷新 |
| AC-05 | 渠道流水页跨账单查询：筛选条件生效、默认排除作废账单的行、按交易日期倒序、分页；外部交易号精确查询；点行进入账单详情并高亮该行 |
| AC-06 | 新接口有权限点控制（沿用 `FINANCE_RECONCILIATION_READ`）；不存在的 ID 返回 404 业务错误 |
| AC-07 | reconciliation、BFF、Web 测试与 arch-rules 通过；`console-resource-capabilities.json` 与 `pageCapabilities.ts` 一致 |
| AC-08 | mor-test：用现有演示数据走查 6 类详情页与渠道流水页 |
