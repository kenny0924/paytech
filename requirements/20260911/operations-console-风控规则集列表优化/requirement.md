## 1. 目标与范围

精简规则集列表展示，修复编码查询与浏览器回退行为，通过统一操作菜单直接访问详情、编辑和删除。本期以规则配置为主，隐藏 TEST Candidate 相关页面入口。已有规则配置及执行边界继续遵循[V1 配置决策](../../../agent-docs/decisions/2026-09-11-risk-rule-v1-configuration.md)；本需求已确认整体删除目标，具体接口与数据设计见技术方案第 10 节起。

| 用户条目 | 本次需求理解 | 验收标准 |
|---|---|---|
| 1 | 删除截图中规则集列表标题下方的蓝色说明提示 | AC-01 |
| 2 | 修复输入规则集编码后点击“查询”报错 | AC-02 |
| 3（已澄清） | 删除整个规则集；正在使用的规则集禁止删除 | AC-03 |
| 4 | 浏览器回退应回到实际上一层详情或列表，保留正确导航顺序 | AC-04 |
| 5 | 删除规则集列表“内容摘要”列 | AC-05 |
| 6 | 操作列改为统一下拉按钮，支持点击和鼠标悬停展开；包含“详情”“编辑”“删除”，删除用红色 | AC-06 |
| 后续澄清 | 一个规则集只显示一行；多版本展示留到下个需求 | AC-07 |
| 随后确认 | TEST Candidate 页面与操作入口留到后续；Candidate 历史引用与实际生效使用分别处理 | AC-03、AC-08 |

本期涉及规则集列表及其详情/编辑导航，列表和操作都以整个规则集为业务单位，不新增运行期风控决策或实际动作执行。历史版本的存储、Hash、并发及幂等合同继续保留；本期不做多版本列表、历史版本展开或版本切换入口。

## 2. 本期验收标准

### AC-01：列表说明精简

规则集列表不再显示截图中的“规则内容仅保留在当前页面内存中……”蓝色说明，移除后标题与列表区域间距自然。第 1 项按附图解释，不扩大为删除所有字段辅助说明或错误提示。

### AC-02：规则集编码查询

- 输入合法、已存在的规则集编码，点击查询能正常返回相应结果。
- 合法但不存在的编码显示空结果；清空输入后查询恢复未按编码筛选的列表。
- 非法格式在界面明确提示，不显示无法理解的泛化报错；合法查询仍保留服务端校验。
- 筛选、状态和分页可组合，改变筛选后按既有分页规则回到第一页。
- 默认沿用现有编码查询合同，不在修复时静默改成模糊搜索。实际报错原因在阶段 2 复现定位后记录。

### AC-03：删除

- **已确认：删除对象是整个规则集，不是其中一个草稿版本。** 删除后该规则集及其所有版本不再作为可管理规则集出现在列表或编辑入口；不能删除最新版本后又显示旧版本。
- **已确认：正在使用的规则集禁止删除。** 判断必须覆盖整个规则集的版本集合，不能只检查列表所代表的最新版本；旧版本正在使用同样需要拦截。
- 删除入口位于操作菜单，文字为红色。执行前显示规则集名称、编码及整体删除的确认说明；取消不产生变更。
- 成功后更新列表、总数与分页；失败保留明确错误。权限与使用状态由后端在命令执行时校验，不能仅依赖按钮隐藏或列表读取时的结果。
- 删除应保留历史审计、Candidate 引用的历史配置及已有检查记录，保证追溯完整；具体存储与回读方案留到技术设计阶段，不清理或改写这些历史事实。

**已确认的业务口径：任一版本被当前实际生效的发布使用，整个规则集禁止删除。** 单纯冻结、Candidate 引用或历史失效发布引用不单独构成“正在使用”；这些引用按历史完整性要求保护。没有生效引用时，不得仅以存在 Candidate 为由永久禁止删除。删除与并发校验、发布之间的一致性和必要的临时冲突处理在技术方案阶段明确。

### AC-04：浏览器回退与前进

- 从列表进入详情后回退，回到该列表；从列表直接编辑后回退，回到该列表。
- 从详情进入编辑后回退，回到进入编辑前的详情；不跳过实际内部访问层级直接回到审计日志。
- 回到列表时恢复原筛选与分页；浏览器前进能对称恢复相应视图。
- 未保存编辑的离开确认继续有效：取消回退保留页面与内容，确认离开才执行导航。
- 直接打开页面、没有内部访问历史时遵循正常浏览器历史；不将“回退”无条件固定跳到列表。刷新后的地址/视图恢复方式在技术设计阶段明确。

### AC-05：列表内容摘要

列表移除“内容摘要”表头及对应单元格，剩余列重新安排宽度。该项只改变列表展示，现有详情与内部内容完整性校验仍按各自合同处理。

### AC-06：统一操作菜单与直接编辑

- 操作列使用一个“操作”下拉按钮，鼠标悬停或点击均可展开；点击可满足触屏使用，键盘可访问菜单项。
- “查看详情”改为“详情”，打开原有详情视图。
- “详情”和“编辑”均针对该规则集当前配置，默认沿用最新已保存内容；“编辑”无需先打开详情，保存仍遵循现有新版本和并发校验机制。本期不增加版本选择器。
- 菜单按当前用户权限及记录状态控制可用项；不可用操作给出一致的隐藏/禁用策略，在技术设计阶段确定。
- “删除”为红色，遵循 AC-03。点击菜单或取消删除不应误触详情、编辑等其他动作。

### AC-07：每个规则集只显示一行

- 同一个规则集即使已有多个保存版本，也只显示一行；修改并保存后更新原有行，不追加一行历史版本。
- 总数、分页和筛选均按规则集计算，同一个规则集不能出现在不同页。不能只在已取得的一页版本结果上做前端去重。
- 列表移除“业务版本”列，不提供历史版本展开、版本列表或版本切换；多版本展示明确延期到下个需求。
- 详情与编辑进入当前配置。当前配置与实际使用中的版本可能不同，删除使用状态仍按 AC-03 覆盖整个规则集。
- 不同决策点下的同名编码按现有业务命名空间区分，不因展示合并而混为同一规则集；具体身份字段与 API 投影在后续技术设计中定义。

### AC-08：本期隐藏 TEST Candidate 入口

- 规则配置页面不再显示 TEST Candidate Tab，规则集详情不再提供“创建 TEST Candidate”等相关候选创建、校验或恢复操作入口。
- 旧书签或带 Candidate Tab 参数的访问应有明确的规则集页面落点，不出现空白或恢复隐藏入口；具体导航兼容策略在技术设计阶段确认。
- 现有 Candidate 后端接口、权限数据与历史记录保留，隐藏页面不等于删除后端能力。规则冻结能力的其他既有入口不因本项自动移除。
- TEST Candidate 的完整用户交互与多版本展示留到后续需求；本期不补做 Shadow、审批、激活或真实规则执行。

## 3. 阶段交接与技术待办

此前“只删当前草稿版本”和“Candidate 引用也算正在使用”的建议已被取代，业务选择不再重复询问。分析与已批准方案见 [technique.md](./technique.md)，各阶段确认及交接结果见 [delivery.md](./delivery.md)。

用户同时确认公共工程约束：未明确指定版本时直接调整原接口，新接口默认 `/v1`；类、接口和 record 名不带 `V1/V2` 等协议版本字样。规则集的业务版本字段、历史 Hash Schema 不因类型重命名改变。现行规则见[公共版本与命名决策](../../../agent-docs/decisions/2026-09-11-api-version-and-type-naming.md)。

阶段 3 已确认：增加规则集管理根、删除保留历史且编码永久占用、不提供恢复或隐式复活，以及相应接口、并发保护、权限和页面方案。这些合同不改变 AC-01 至 AC-08 的目标；实现、验证和部署状态以交付记录关联的当前台账为准。

编码查询已复现非法格式缺少就地提示的缺陷，已测合法编码正常；用户原始样例仍待补充，不能将已复现条件直接视为原始报错的唯一原因。浏览器回退问题已通过实际访问序列定位；详见技术分析。
