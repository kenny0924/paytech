## 1. 实施顺序与系统职责

| 顺序 | 系统 | 可审阅产物 |
|---|---|---|
| 1 | Risk | 按批准字段同步 PDManer、完整 Schema、增量 DDL；新增 risk-api 合同/模型及错误码，保持旧 Wire 精确形状 |
| 2 | Risk | 历史与发布引用 Repository/Mapper/Service/Processor；字典当前值读写、编码唯一/版本校验、异常后人工查询及原规则保存的目录资格；沿用现有 `Service + Impl` 项目规定及 Owner JAR 边界 |
| 3 | BFF | 14 条接口的鉴权转发、Query/Header/Body 白名单、Owner Shape 校验、安全错误映射；没有实际聚合不制造空 Processor，不接触 Risk 数据库 |
| 4 | Web | READ/EDIT 共用布局、精确版本与来源导航、历史/发布图、两类字典页面及选项组件、Resource 显隐、主菜单组件白名单 |
| 5 | Platform 配置 | 单一初始化 DML 与本轮注册清单对齐；14 路由、两菜单及按钮，默认 DISABLED；不新增业务 Target；Gateway 通用动态转发另见补改方案 |
| 6 | 根文档 | 需求与时序、Owner 模型说明及状态台账按实际证据更新；接口设计不等于实现，SQL 文件不等于已应用 |

风险保存事务的字典资格只在 FIRST 路径新增，不先改通用规范化/回读，避免破坏已有回放。先建立失败证据再实现；保持各应用未提交的无关修改。没有新增 Foundation 模块、锁能力、数据库、MQ/调度或 Runtime。

新字典写请求与原规则集命令的重试逻辑分开：Web/BFF 请求帮助方法及 Risk 的 Header/命令入口不能强制新字典写入携带幂等键；字典未知结果提示人工刷新，原规则集仍使用原命令键恢复。

## 2. 最小失败证据与回归清单

| 验收 | 必须证明的行为 / 失败分支 | 验证层 |
|---|---|---|
| AC-01/04 | read 模式看全内容，无任何写控制/保存请求；只读账号切换规则和基本信息；Authoring Context 不可用不抹掉旧事实 | Web 组件/路由测试 + 浏览器 |
| AC-02/03 | 多版本、RETIRED、唯一根主列表不变；固定 maxVersionNo 翻页期间新增版本不重复；明确版本刷新不漂移；根删除后历史 404 | Risk 真实 MySQL 公开 HTTP + BFF + Web |
| AC-05 | 主列表→历史第 2 页→详情→浏览器返回/前进；从引用图进入旧版再返回；列表筛选保留；无审计页误跳 | Web 路由测试 + 真实浏览器 |
| AC-06/07 | 当前 #3 草稿但旧 #2 ACTIVE；TEST/PRODUCTION、候选/SUPERSEDED；inUse 不随分页过滤错误变 false；破损占槽/闭包报错，依赖失败不为空图 | Risk 公开 HTTP + BFF 形状/错误 + Web |
| AC-08/09 | 创建/内容更新/启停、代码永久唯一、含义说明及状态；标签不设置主体类型限制；停用仍可读；当前/历史/删除根引用分页，TAG 与普通同值字符串不能混淆 | Risk HTTP + 真实本地 MySQL |
| AC-10 | 原因选择默认消息、规则内覆盖、后台刷新不覆盖；标签不按主体类型限制；直接构造 HTTP 请求也不能新选停用/未知代码，原工程目标绑定资格保持 | Risk HTTP + Web 交互 |
| AC-11 | 旧代码/停用项按同规则同项沿用；改消息、复制规则/动作增加次数、换目标不得豁免；旧空消息回读与原新保存门禁；旧 Hash 和成功命令回放不随字典改名/停用变化 | Risk 正常与异常集成回归 |
| AC-11/12 | 字典重复 code 创建冲突、旧 expectedVersion 重复更新冲突；超时/5xx 后 UI 不自动重发，人工查询当前值/版本/更新人；不写幂等或回执记录，事务失败不留部分更新；原规则集成功命令回放保持 | Risk HTTP + Web + 定向 DB 检查 |
| AC-12 | 相同 CAS 的两修改仅一成功；同 code 两创建仅一成功；字典停用与新规则保存的两个锁顺序都符合约定；独立代码不共享业务大锁 | Risk 真实 MySQL/Redis，多请求协调并发，不用 sleep 偶然命中 |
| AC-12 | 只读者无六项写权限；配置人员可取字典但不能维护；绕过按钮直调依然 403 且无数据变化；伪造 actor 不越权 | BFF/Platform Simulator 按项目规范 + 发布后真实入口 |
| 跨项 | 空页、大小上限、未知/重复 Query、非法/重复 JSON、BIGINT/时间、14 API 精确 Shape、新错误白名单、GET 无 Body | Risk/BFF 协议门禁 |
| 跨项 | 新增前后旧主列表、保存/冻结/Candidate/删除/历史回放回归；静态初始化 DML/增量等价、模板冲突、权限/Resource/Guard 完整闭包 | 原应用回归 + Platform 现有 Catalog 验证 |

并发验证使用项目允许的测试协调器，在真实 HTTP/事务边界安排锁竞争，检查成功/409 及数据库最终不变量。测试只使用合成非敏感数据，公共入口验证后由 TestMapper/Checker 精确断言，不为了覆盖内部方法造机械测试。

## 3. 检查和环境边界

- 遵循 [UNIT_TEST_GUIDE](../../../agent-docs/UNIT_TEST_GUIDE.md)，使用各服务既有 Maven/前端门禁，不引入 Mockito 替代项目禁止的测试模式或自动基础设施。编写测试前再次读取最近目录规则和当前构建。
- Risk 真实测试依赖仓库 local-environment MySQL/Redis；缺依赖要清楚失败，禁止自动 Testcontainers、自动 Schema/种子。应用本地 SQL 仍须给出确切环境、备份位置与文件清单并单独获得授权。
- 第一轮针对修改范围验证后再运行现有相关回归与构建；不将本阶段的 Markdown/SQL 静态检查、Pencil 图片或需求站点检查称为新功能测试通过。
- 每个证据记录命令、HEAD/工作区差异、环境、成功/失败/未运行项。阶段 5 对照上述 AC 做综合联调和视觉验收，不重复宣称上一需求部署已经包含这些页面。

## 4. 分阶段交付门槛

阶段 4 输出 Risk/BFF/Web 代码差异、模型/SQL 同步、必要开发测试和剩余项，停下确认。阶段 5 输出 AC 验证报告及浏览器证据，停下确认。阶段 6 核实真实 test 基线，制作制品清单、SQL 备份/恢复及逐 API 注册启用方案，再请求具体部署授权；当前不提前申请泛化授权。

由于旧 BFF 对响应键严格校验，本方案保留旧 Wire；部署时先增加 Risk 新能力，再发布识别它的 BFF、Web，最后按审核清单开启新菜单/路由并重新加载权限。新保存资格在 Risk 端生效，会影响旧前端继续录入自由代码，因此实际窗口需先完成字典准备并控制编辑入口，不能声称“新增 API 全部向后无感”。若要回滚，在存在新字典约束写入后不能直接放回不做资格校验的旧 Risk；阶段 6 需明确停写或前滚修复方案。

阶段 7 完成 test 真实入口验收后列出待提交差异，阶段 8 才按用户具体授权提交/归档；不自动 push。
