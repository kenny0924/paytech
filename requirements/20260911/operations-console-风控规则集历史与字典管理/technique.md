## 6. 关键兼容风险与阶段 3 决策输入

以下为本阶段提出的建议，随阶段 2 评审收敛，具体实现不提前批准。

| 问题 | 建议口径 | 不处理的后果 |
|---|---|---|
| 旧手工原因/标签未登记或已停用 | 历史原样查看；编辑最新版本时允许严格沿用基线中同一条规则的未改旧项，新增/替换必须使用启用且适用的目录；不能靠客户端传 legacy 标记豁免 | 一上线就无法维护旧规则，或者任意新规则利用兼容口径绕过字典 |
| 历史 DENY 缺文案 | 历史回读保持原空值；目前新保存已要求代码/文案完整，本次不自动放宽或批量补造。保存时沿用该完整性门禁 | 编造历史消息，或静默改变既有新保存要求 |
| 字典名称/默认文案变化 | 原规则代码/文案和 Hash 不变；当前名称若仅作辅助说明，必须与当时保存事实区分；旧版没有名称快照就不伪造“当时名称” | 追溯页面随字典改名而错误解释旧配置 |
| 停用及标签适用范围收窄 | 停用仅禁止新选，既有已保存配置不被撤销；首次新保存必须在写事务内复核资格，字典更新与该检查有一致性保护 | 页面加载后被停用仍可绕过；或字典维护暗中改变生效策略 |
| 字典命令/保存并发 | 字典自身使用业务资源上的 CAS/必要资源锁；规则保存继续锁规则集，另行设计与所引用字典行的数据库最终保护及稳定加锁顺序，防止竞态/死锁；不改成操作者或 Tenant 大锁 | 丢失修改、死锁、停用检查失效 |
| 原成功命令回放 | 先按已有命令协议识别成功回放，复原首次结果；不能先要求当前字典启用/存在或重新填默认消息 | 已成功保存的同键重试会因之后的字典修改变成失败 |
| 整集已删除后历史入口 | 本次普通历史入口仍面向未删除根，保留原普通详情 404；字典引用明细若包含已删除根，应标明并禁止导航到普通编辑页；不新增回收站/恢复或任意历史越权入口 | 借字典引用绕过整体删除的已确认管理边界 |
| 字典“被引用”的统计口径 | 查询覆盖保存配置引用，区分当前配置/历史版本/已删除根，并单列 ACTIVE 使用证据；保存引用不能都叫“正在使用” | 旧版引用与运行占用混淆，误导停用/删除判断 |
| 图与明细范围 | 有界加载并标明当前查询范围；存在更多引用时可继续分页/展开，不能把一页关系宣称为全图。关系损坏或依赖失败不能返回“无引用” | 漏画旧版 ACTIVE 引用，造成错误操作判断 |
| 跨系统升级 | 现有 BFF JSON Shape 要求精确键，新增字段也可能破坏旧消费者；设计保持原响应优先，必要时协调 Risk→BFF→Web 升级和旧新制品兼容验证 | 把“沿用 v1”误解为任意加字段都安全 |

不涉及实际执行，因此停用字典不应被扩展为停用规则或撤销已经存在的发布。未来激活/执行如何处理这些目录，需要其独立设计。

## 7. 工作量与验证重点

| 工作包 | 相对工作量 | 判断依据 |
|---|---|---|
| 统一只读及历史查看 | 中 | 数据/详情已有，但查看模式、导航和当前目录依赖要解耦；需验证只读及 RETIRED |
| 发布引用 | 中 | 关系表已有，需要新的领域查询/完整性校验、BFF 投影、图和明细；无新发布流程 |
| 两类字典与编辑器接入 | 较大 | 新增持久化、管理 API/页面、权限、选项读取、引用反查、并发与历史兼容；主要风险集中于此 |
| 注册数据与联调 | 中 | 新 API/菜单需要 Platform 数据及真实 Gateway/BFF 权限链；包含拒绝访问和严格响应兼容 |

后续应复用并扩展现有公开入口测试：Risk 历史详情/目录退役与删除 HTTP 回归；增加历史分页、引用完整性、字典 CRUD/CAS/权限、保存与停用竞争、同键回放。BFF 覆盖原始键形态/类型、归属、错误投影和拒权 Risk 零调用。Web 覆盖只读模式、直接历史 URL、导航、默认消息与手动覆盖、停用/未登记旧值、图空态/失败/分页。真实浏览器需验证布局与无写请求，不能以 Node 测试代替页面验收。

当前 test 历史证据中没有 ACTIVE Release，不能从空图证明实际使用保护正确；后续用项目批准的本地测试夹具验证各状态和异常关系，不通过新增激活产品功能制造测试数据。综合验证及部署分别在对应阶段授权后进行。
