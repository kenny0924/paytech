# operations：运营控制台多语言迁移 · 需求

版本：v2（2026-10-23 阶段 2—3 答复修订） · 登记日期：2026-10-23 · 阶段：1 需求评审与范围确认

## 1. 背景

[多语言管理](../../20261022/platform-support-多语言管理/requirement.md)（2026-10-23 已上 mor-test，块 135）建成了 Platform 多语言模块与前端运行时：key 和英文基准随代码导入，运营在控制台翻译并发布不可变语言包，前端运行时按 manifest 拉取，缺失时回退到构建内置英文。该需求 R9 只让 `client-console-web` 全量接入；`operations-console-web` 只有新增的多语言管理三页五弹窗接入，其余既有页面写明"另立需求"。本需求就是这项"另立需求"。

现状（2026-10-23 盘点，源码不含测试和注释）：

| 项 | 数量 |
|---|---|
| ops-web 源码文件 / 含中文文件 | 351 / 287（多语言模块 18 个文件已接入，不计） |
| 中文字面量 / 去重后文案 | 约 9,900 / 约 6,300（其中约 860 处是带插值的模板字符串） |
| 测试中的中文断言 | 79 个测试文件、约 1,700 处 |
| Platform 中的 Operations 菜单 / 按钮资源 / 权限名称 | 82 / 91 / 118，`display_name` 均为中文 |
| ops-bff 中的展示文案 | 约 70 处（审计详情字段名映射、"其他权限"分组名等） |
| ops-bff 中的校验信息 | 约 640 处（`message =`，属服务端报错文案，不在本需求范围） |

另外，ops-web 全局固定 antd `zh_CN` 语言、没有语言切换入口，日期组件与少量 `Intl` / `toLocaleString` 写死中文格式。

## 2. 目标与使用者

- **使用者：** 平台运营、财务、风控、技术支持等 Operations 用户；其中有不读中文的同事。
- **目标：** Operations 控制台的全部界面文案可以在英文和简体中文之间切换，文案由 Platform 多语言模块维护和发布，与 client-console 一致。
- **成功结果：** 英文用户能独立完成全部页面操作；中文用户的界面与迁移前完全一致；之后新增页面不能再写死中文。

## 3. 本期范围

- **R1 全量迁移。** ops-web 所有既有页面、弹窗、抽屉、菜单、表头、按钮、空状态、提示、确认框、表单校验提示和通知标题，全部改为 key + 英文基准 + 简体中文翻译。包括登录、强制改密、会话恢复、导航与面包屑、错误通知框架。按模块划分命名空间（约 25 个，如 `common`、`nav`、`enum`、`finance`、`risk`、`workflow` …），细节在阶段 3 定。
- **R2 中文零变化。** 每个 key 的 `zh-CN` 翻译就是迁移前代码里的原中文文案，逐字保留。切到简体中文后界面不应有可见差异；现有中文选择器的验收脚本需先选中文（`?lang=zh-CN` 或本地选择）后继续可用。
- **R3 英文基准。** 为全部 key 编写英文基准文案，术语遵守 [AGENTS.md 规范术语](../../../AGENTS.md#canonical-terminology)（Client、Operating Entity、Local Partner、Channel 等），先产出一张术语表供审阅（见 Q4）。
- **R4 枚举与状态。** 现有约 250 个 `xxxLabel / xxxText` 映射表改为 `enum` 命名空间下按"枚举类型.值"的 key，未知值仍显示原始代码。
- **R5 菜单与权限名称。** 侧边栏菜单、面包屑、页面标题、角色编辑里的权限树，按资源编码取 key（`nav.resource.<resourceCode>`），没有 key 时显示 Platform 返回的 `display_name`；Platform 权限本身没有名称，未挂资源的权限照旧显示编码。Platform 数据不改（见 Q2）。
- **R6 BFF 展示文案。** ops-bff 中直接返回给页面的展示文案（审计详情字段名、权限分组名等约 70 处）改为返回编码，由前端翻译（见 Q3）。
- **R7 语言切换。** 页头用户菜单增加语言切换（English / 简体中文），只列 manifest 已发布的语言；选择保存在浏览器本地。**默认语言为英文 `en`**（不读浏览器语言）；用户切换后以本地选择为准，`?lang=` 预览保留。**本地加载：** 已用过的语言的 manifest 与语言包缓存在浏览器本地，下次启动直接用本地缓存渲染，后台核对是否有新发布并替换；网络不可用时继续用本地缓存。切换后 antd 组件语言、日期选择器、日期与数字格式一起切换。
- **R8 防回归。** ops-web 测试增加全量扫描：源码（注释除外）不允许出现中文字面量。之后新增页面必须走 key。同步更新开发约定第 10 节与 UI 文案决定的适用范围。
- **R9 发布数据。** 本需求首次发布时，在 mor-test 上为 `operations-console` 创建新命名空间、导入英文 key、导入中文翻译并发布，覆盖率 100%。

## 4. 明确不做

- 不做服务端报错与校验文案的多语言：Problem `detail`、BFF / 核心服务的 `message =` 校验信息仍是中文。英文界面下，接口返回的错误详情会显示中文（见 Q5）。
- 不做运营录入的业务内容多语言（产品名、模板名、角色名、流程定义名等），也不翻译 Platform 菜单数据本身。
- 不做 client-console、checkout、partner-console 的改动。
- 不做账号级语言偏好、`<html lang>` 之外的 SEO、RTL 与中英以外的语言。
- 不改页面布局和交互；英文文案过长导致的折行、截断在本需求内修到可用，但不借机改版。
- 不改 Platform 多语言模块的数据模型与接口（若容量限制挡住发布，在阶段 2 提出最小调整）。

## 5. 业务规则

- **B1 key 命名。** `<命名空间>.<页面或区域>.<名称>`，与 client-console 一致；同一句话在不同页面含义不同时用不同 key，不为了去重合并。
- **B2 插值用 ICU。** 带变量、数量的文案用 ICU MessageFormat 参数，不在代码里拼接翻译片段。
- **B3 回退。** 运行时查找顺序：目标语言（网络或本地缓存）→ 英文（网络或本地缓存）→ 内置英文 → key。Platform 或公开桶不可用且本地无缓存时退回内置英文。
- **B4 测试断言。** 单元测试按 key 或英文基准断言，不断言中文；验收脚本可继续用中文选择器（中文界面不变）。
- **B5 新页面约束。** 本需求合入后，ops-web 任何新增或修改的界面文案都必须先加英文基准 key，并在多语言模块补中文翻译后发布。

## 7. 验收标准

**功能验收**

- **AC-01** 默认（未选择语言）打开控制台为英文；切换为简体中文后，登录页与全部菜单页面与迁移前文案逐字一致（逐页可见文本比对 + 中文选择器验收脚本在选中文后回归通过）。
- **AC-02** 页头切换为 English 后，登录页、导航、全部菜单页面、弹窗、抽屉、空状态、确认框、表单提示、通知标题均为英文，不残留中文（服务端错误详情与运营录入的业务数据除外）。
- **AC-03** 切换后 antd 组件（分页、日期选择、空状态、确认按钮）与日期 / 数字格式跟随语言；刷新页面后保持所选语言，且首屏直接用本地缓存的语言包（不等待网络）；断开 manifest 与公开桶后再刷新，仍显示所选语言。
- **AC-04** 菜单、面包屑、页面标题、角色权限树在英文下显示英文；某资源没有 key 时显示 Platform 的中文名称而不报错。
- **AC-05** 枚举 / 状态在两种语言下均正确显示；遇到未知值显示原始代码。
- **AC-06** 审计详情的字段名在两种语言下正确显示（BFF 返回编码）。
- **AC-07** 在多语言管理中修改某个 ops 文案并发布后，刷新控制台即显示新文案；切回上一发布后恢复。
- **AC-08** manifest 或语言包不可用时，控制台以内置英文正常工作，不白屏。
- **AC-09** 全量扫描测试通过：ops-web 源码（注释除外）无中文字面量；`npm test` 与 `build` 通过；ops-bff 测试通过。
- **AC-10** mor-test 上 `operations-console` 的 `zh-CN` 覆盖率 100% 并发布 READY。

**视觉 / 交互验收**

- **AC-11** 语言切换入口位于页头用户菜单，当前语言有明确标识；只列已发布语言，无发布时隐藏。
- **AC-12** 英文下各模块主要页面在 1440 宽与 1280 宽无文字溢出、按钮折行错位、表头截断不可读；侧边栏菜单项过长时省略并有完整提示。
- **AC-13** 切换语言不丢失当前路由与页面状态以外的数据（允许页面重新加载数据）。
