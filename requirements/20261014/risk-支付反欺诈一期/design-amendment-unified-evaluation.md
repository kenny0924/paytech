- 日期：2026-10-14
- 状态：**已确认**（用户 2026-10-15 回复“U1到U4都采用，改起来吧”，并授权在本机 mor_risk 执行本修订增量 SQL）
- 修订对象：[一期设计](./design.md)第 2 节（支付评估接口）、第 3.5 节（动作与认证要求）及相应实现
- 来源：用户 2026-10-14 讨论风控点时提出：①“风控接口应该只有一个，不同的点要求不同的参数，但接口是一个”；②3DS 等判断应该在规则中处理，而不是写在引擎代码里

## 1. 结论

| # | 修订 | 原设计 |
|---|---|---|
| A | 同步风控点共用一个接口 `POST /risk-decisions/v1/evaluations`，按 `pointCode` 区分；入参按该点登记的输入合同校验 | 每个风控点一个专用接口（`/payment-risk-assessment/v1/assessments`） |
| B | 风控点在合同中声明**附加输出**（如认证要求）；输出值由决策流**结束节点**配置，引擎只返回所到结束节点的配置 | 引擎识别“3DS 动作”，沿途命中即标记需要 3DS |
| C | 删除 3DS 专用动作 `ALLOW_PAYMENT_WITH_THREE_DS`；支付规则只用放行、审核、拒绝三个终态动作 | 四个终态动作 |

不变：规则、变量、Feature、名单、执行发布、影子运行、失败即拒绝、重放规则、评估事实落库、各风控点的快照表。

## 2. 统一接口

```text
POST /risk-decisions/v1/evaluations
请求：
  pointCode        风控点编码，如 PAYMENT_ATTEMPT_RISK
  contractVersion  输入合同版本，如 1
  businessKey      该点的业务身份（支付为支付尝试 ID），同一 pointCode 内唯一
  inputs           { 字段编码: 值 }，字段集合由该点输入合同决定
响应：
  evaluationId     评估 ID
  result           ALLOW / REVIEW / DENY / FAILED / TIMED_OUT
  outputs          { 输出编码: 值 }，只含该点合同声明的输出；非 ALLOW 时为空对象
```

- **校验：** 未登记的 `pointCode` 或合同版本返回 400；`inputs` 按合同逐字段校验——未知字段、缺少必填字段、类型或格式不符返回 422，字段级错误指出字段编码。原支付接口上的字段格式规则全部转为合同中的格式定义，IP 字面量校验保持在构造输入时。
- **重放：** 身份为 `pointCode + businessKey`。合同标出参与“内容一致”比较的字段（支付：除 IP、User-Agent 以外的全部字段，含风控 Action ID）；一致返回原结果，不一致 409。
- **未配置：** 该点在本环境没有生效发布返回 503 `RISK_DECISION_NOT_CONFIGURED`（替代 `PAYMENT_RISK_NOT_CONFIGURED`）。
- **只服务同步风控点：** 授权结果、拒付等事件经 MQ，Client 监控等由 Risk 定时任务执行，都不走本接口。
- **调用方类型提示：** `risk-api` 为每个风控点提供输入记录类（如 `PaymentAttemptRiskInput`），由它生成统一请求；线上只有一个接口，调用方代码仍是强类型。
- **日志：** `/risk-decisions` 整个路径只记元数据。

## 3. 风控点的输入、输出合同

在现有输入合同（字段、类型、必填、数据分级）基础上补充：

| 补充项 | 说明 |
|---|---|
| 字段格式 | 每个字段的必填、正则与最大长度，由该点评估器登记（与原支付接口字段规则一致） |
| 业务身份 | 合同指定业务身份格式（支付：支付尝试 ID，正整数） |
| 重放比较 | 由该点评估器实现：支付比较风控 Action 与稳定输入摘要（不含 IP、User-Agent） |
| 附加输出 | 输出编码、取值集合、默认值；支付声明 `AUTHENTICATION_REQUIREMENT`：`NOT_REQUIRED`（默认）/ `THREE_DS_REQUIRED` |

输入合同与附加输出声明由工程登记在代码中；附加输出的取值随决策流图进入执行发布内容摘要，决策点版本摘要不变（支付点版本 220002 摘要未重算）。新增风控点 = 登记合同与输出 + 初始化数据 + 内部评估器（输入转换、重放、快照写入、结果映射），不新增接口。

## 4. 结束节点配置输出（取代引擎内的 3DS 判断）

- 决策流结束节点在“结论、原因码、原因文案”之外，可配置该点合同声明的输出值。
- 校验：只允许合同声明的输出编码与取值；输出只允许出现在 ALLOW 结束节点。
- 默认值：保存流程时为 ALLOW 结束节点补齐未配置的输出（取合同默认值）并写入流程版本，随流程图进入执行发布摘要；执行发布校验（TERMINAL_ACTION）要求 ALLOW 结束节点带齐声明的输出。运行期引擎只读结束节点上的值，不再读取代码中的默认值，代码改默认值不影响已冻结的发布。
- 运行：引擎走到哪个结束节点，就返回该节点的结论与输出，不再检查沿途命中了什么动作；评估超时取发布冻结的决策点版本。
- 运营配置示例：认证规则集节点“有命中”→ 结束节点“放行（需要 3DS）”；否则 → 结束节点“放行”。决策流图上即可看出为何需要 3DS。
- 兼容：没有输出配置的结束节点（含结账现有流程）内容摘要投影不变。

## 6. 对 Payment 接入清单的影响

一期设计第 14 节第 1、5 项改为：调用 `RiskDecisionApi`，以 `PaymentAttemptRiskInput` 构造请求；保存 `evaluationId`、`result` 与 `outputs.AUTHENTICATION_REQUIREMENT`。响应不再返回 `assessmentId`（Risk 内部按支付尝试关联交易评估）。

## 7. 本次不做

- 出款资格（RCO-I09）与结账准备暂不迁入：二者运行期尚未实现，届时以适配器接入本接口，并废弃出款资格专用接口。
- 引擎其余通用化（如规则动作直接产出输出）。
