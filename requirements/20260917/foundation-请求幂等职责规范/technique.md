# 文档影响与维护方式

前序开发规范仅要求“业务唯一键足够时不新增机制”，旧 Foundation 决定及技术栈仍允许按需引入组件，Gateway 旧合同仍规定只透传 Key；这些说明不能表达用户最新确认的全项目职责。

维护方式：先记录[后继决定](../../../agent-docs/decisions/2026-09-17-gateway-request-idempotency.md)，把完整语义集中到开发规范第 5.4 节，工程/架构/技术栈只投影各自职责；更新 AGENTS、导航、治理及 Cursor 薄规则，规范化公共写接口示例，并为旧合同标注取代与迁移范围。

所有系统适用，不代表所有接口强制启用 Key。Gateway 具体实现与存量 Header/组件迁移不在本次范围；内部业务身份、数据库防重及必要恢复继续保留。没有 API、表、字段、索引或 SQL 变更，不因文档更新宣称运行能力已完成。
