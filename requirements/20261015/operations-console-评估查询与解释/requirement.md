## 1. 背景

Risk 已提供评估结论查询与评估解释接口，但运营后台没有入口。商户或玩家询问“这笔支付为什么被拒、为什么要 3DS”时，运营只能找研发查库；新规则激活前也看不到影子评估为何与正式结论不同。

## 2. 目标

运营在后台输入支付尝试 ID 或评估 ID，看到 Risk 的结论，以及“走了哪条路、哪条规则的哪个条件成立、用到的变量值是多少、影子评估结论是否不同”。

## 3. 使用者与场景

| 使用者 | 场景 | 成功结果 |
|---|---|---|
| 风控运营、客服 | 拿到支付尝试 ID，查这笔支付的风控结论 | 看到结论（放行/放行需 3DS/审核/拒绝/失败/超时）、拒绝原因、发布与流程版本、评估时间 |
| 风控运营 | 想知道为什么是这个结论 | 按顺序看到经过的流程节点与走过的连线；每个规则集节点内执行了哪些规则、各条件的完整表达与是否成立；用到的变量取值（常量、集合注明是当前值） |
| 风控运营 | 核对输入 | 看到评估时冻结的全部输入（含 IP、User-Agent、卡指纹、消费者引用原值） |
| 风控运营 | 新发布影子运行后，对某笔支付比较新旧结论 | 正式评估下列出影子评估及是否变化，点击进入影子评估的解释 |
| 排查人员 | 评估失败或超时 | 看到失败码、失败的变量、已完成部分的过程；旧评估明确提示“路径未记录” |

## 4. 本期范围与不做项（草案）

**包含**

- BFF：接入 Risk `RiskEvaluationQueryApi` 三个接口；按页面需要组装条件表达（调用既有规则集版本详情）与节点名称；权限检查经 PLT-I02；响应体不写日志。
- Web：风控菜单下新增“评估查询”页：查询框（支付尝试 ID / 评估 ID）、结论卡片、解释（路径、规则与条件、变量、输入、影子评估）；影子评估可跳转查看。
- Platform：新页面的菜单资源、权限点、Gateway 路由注册 DML（需求目录下提交执行文件）。
- 本机联调与浏览器验收；mor-test 部署 BFF/Web 并执行注册。

**不做**

- 修改 Risk 代码或合同（Risk 侧问题记录后另行处理）。
- 按订单、Client、时间范围检索评估列表；按影子批次列出样本（Risk 无此接口）。
- 流程画布上高亮路径（本期以步骤列表展示，见 Q4）。
- 受限输入的脱敏开关、导出、打印。

## 5. 已确认事实

| 事实 | 依据 |
|---|---|
| Risk 三个接口：按 ID 查结论、按 `pointCode+businessKey` 查正式评估、按 ID 查解释；内部直连、不需要 Gateway 身份头 | Risk design.md 第 4 节 |
| 解释含受限输入原值；用户已确认可以展示；Risk 日志只记元数据，要求 BFF 不记录响应体 | Risk requirement.md Q1；交接单第 2 节 |
| 解释只给谓词 `nodeId` 与结果；条件结构需用 `ruleSetVersionId` 调既有 `GET /decision-rule-sets/v1/rule-sets/{ruleSetVersionId}` | 交接单第 2 节 |
| `valueBasis=CURRENT` 的变量（常量、集合）是当前值，须标注 | 同上 |
| `pathAvailable=false` 表示评估早于路径记录上线；mor-test 现有 4 条均如此 | Risk test-acceptance.md |
| BFF 已用 `operationsRiskProxyFactory` 为 Risk 各 API 建客户端；风控菜单现有 7 个页面（规则配置、决策流、拒绝原因、主体标签、变量、名单、执行发布） | `RiskClientConfiguration`、`navigation/menu.ts` |
| mor-test Risk 已部署新接口；Operations BFF/Web 当前镜像为支付风控配置接入版本 | CURRENT_IMPLEMENTATION |

## 6. 已决问题（2026-10-15 用户确认按建议）

| 编号 | 问题 | 结论 |
|---|---|---|
| Q1 | 页面入口 | 风控菜单新增独立页“评估查询”；执行发布详情暂不加入口（Risk 没有影子样本列表） |
| Q2 | 权限 | 新增独立的只读权限点“风控评估查询”，不复用规则配置的读权限：页面含 IP、卡指纹等原值，应能单独授予 |
| Q3 | 条件展示深度 | BFF 用规则集版本详情把每条执行过的规则的条件树渲染成可读表达（变量名、运算符、值），逐个谓词标出成立/不成立；未执行的规则不列出 |
| Q4 | 路径展示 | 以步骤列表展示（节点名称、类型、规则集、是否命中、决定、所走连线），复用节点已有中文名；不在流程画布上高亮，以免改动决策流页面（与通知管理的并行改动无关，但工作量翻倍） |
| Q5 | mor-test 验收数据 | 同 Risk 发布做法：经临时代理用 3 个合成支付尝试对联调基线发布评估，浏览器查看后用清理 SQL 删除；联调基线不变 |

## 7. 验收标准（草案）

**功能**

| 编号 | 标准 |
|---|---|
| AC-1 | 输入支付尝试 ID 能查到正式评估结论；输入评估 ID 同样可查；不存在时提示“没有找到评估”；格式错误在提交前提示 |
| AC-2 | 结论卡片显示结论、认证要求、拒绝原因码与文案、失败码、风控点、发布、流程编码与版本、评估时间、耗时、正式/影子 |
| AC-3 | 路径按顺序显示节点名称与类型、规则集编码与版本、是否命中、决定、所走连线名称、复用标记；`pathAvailable=false` 时显示“路径未记录（早于该功能上线）” |
| AC-4 | 每条执行过的规则显示编码、名称、优先级、是否命中、是否终态、动作，以及条件表达和各谓词是否成立 |
| AC-5 | 变量表显示编码、名称、来源、类型、取值、依据；`CURRENT` 标注“当前值，可能与评估时不同”；Feature 失败显示失败码 |
| AC-6 | 输入区显示 17 个字段原值，未提供显示“未提供” |
| AC-7 | 正式评估列出影子评估（结论、结论是否变化、认证要求是否变化、严重程度），点击进入影子评估的结论与解释 |
| AC-8 | 无“风控评估查询”权限时菜单不可见、BFF 返回 403；BFF 日志不含响应体与受限原值（自动化测试覆盖） |
| AC-9 | mor-test 部署后经 Gateway 实际访问页面完成以上功能；现有页面回归不受影响 |

**视觉/交互**

| 编号 | 标准 |
|---|---|
| UI-1 | 沿用 Operations Console 现有查询页布局：顶部查询条，结果分区为结论卡片 + 标签页或分段（路径、规则、变量、输入、影子） |
| UI-2 | 结论用颜色区分（放行/审核/拒绝/失败），命中规则与成立的谓词醒目标出 |
| UI-3 | 有加载、空、错误状态；浏览器前进后退与刷新保留当前查询（ID 在 URL 中） |

## 8. 与并行工作的冲突约定

- 动手前与每次提交前查看 `git status`；当前另一会话的“通知管理”有未提交改动（BFF 4 个文件、Web `notification`/`pages`/`navigation`、Platform 大量文件），本需求不修改这些文件；必须共用的文件（如菜单）只改本需求的行，提交时只暂存这些行。
- Platform 注册 DML 先查询已占用的 ID 与编码，避开并行需求的号段；执行前再次核对。
- mor-test 的 BFF/Web 镜像从已提交代码导出、叠加本需求改动构建，不带入他人未提交代码；部署前核对容器镜像与启动时间，发现他人正在部署同一服务即停止并告知你。
