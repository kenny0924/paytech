# Operations 通知管理需求

> 状态：阶段 1 已确认（2026-10-15），阶段 2 已确认，阶段 1—5 已完成，已提交（未推送）；阶段 6—7 已在 mor-test 部署 Platform 并启用，已确认。确认记录见 [delivery.md](./delivery.md)。

## 1. 背景与来源

Platform Delivery 已能经 Amazon SES 发送普通通知和 Client 认证邮件，但模板、语言内容、发送账号和路由只能通过初始化 SQL 写入；改一句文案、停用一个模板或切换备用账号都要写 DML 并手工执行。发送记录也只能直接查库。

[Delivery 领域规划](../../20260920/platform-support-Delivery领域规划/requirement.md)把"Operations 模板/内容/Provider/路由管理"列为单独处理；[接口规划](../../20260920/platform-support-Delivery领域规划/api.md)把通知查询（`getNotification` 草案）暂缓。本需求把两者放到运营后台。

当前事实（2026-10-15）：

| 项 | 现状 |
|---|---|
| 配置表 | `t_notification_template`（编码、介质、启停）、`t_notification_template_content`（每语言一条：标题、正文模板）、`t_notification_provider`（发送账号编码、介质、启停）、`t_notification_route`（每模板一条：主账号、备用账号、启停），均带 `version` 乐观锁 |
| 发送记录表 | `t_notification_request` → `t_notification_delivery`（每收件人一条，邮箱只存 Vault Token）→ `t_notification_attempt`（每次发送尝试） |
| 模板语法 | 占位符 `${name}`；标题 ≤255 字符且不含换行，正文 ≤64 KiB；纯文本 |
| 发送账号 | 表里只有编码和启停；发件地址、区域、凭据 Token 来自部署配置 `notification.ses.*`，适配器按 `provider_code` 绑定 |
| 即时发送模板 | `CLIENT_EMAIL_VERIFICATION`、`CLIENT_PASSWORD_RESET` 由配置 `notification.transient-template-codes` 限定，正文需含 `${link}` |
| 管理接口 / 页面 | Platform 无任何通知管理或查询接口；运营后台无通知菜单、页面、权限和 Console Resource |

## 2. 使用者与目标

| 使用者 | 目标 |
|---|---|
| 运营配置人员 | 在后台查看和维护通知模板、各语言文案、路由，启停模板和发送账号，修改即时生效 |
| 运营 / 客服排查人员 | 按来源、模板、状态、时间查发送记录，看到每个收件人的投递状态和每次尝试的结果码 |
| 平台管理员 | 通过角色权限控制谁能看、谁能改；每次修改有审计记录 |

## 3. 本期范围（建议）

1. **模板**：列表（编码、介质、状态、已有语言、是否即时发送模板）、详情、新建（编码创建后不可改，介质本期只有 EMAIL）、启用 / 停用。
2. **语言内容**：在模板详情中新增、修改某语言的标题和正文；保存前按发送时的同一规则校验（占位符语法、长度、标题无换行）。提供**预览**：填入示例参数后渲染出标题和正文，不发送。
3. **路由**：每个模板一条路由，设置主账号、可选备用账号（不能与主账号相同）、启用 / 停用。
4. **发送账号**：列表（编码、介质、状态、是否已在本环境配置适配器、被哪些路由引用）、启用 / 停用。不在页面维护发件地址、区域和凭据（见 Q-02）。
5. **发送记录查询**（见 Q-01）：请求列表（按来源系统、来源事件键、模板、时间范围、投递状态筛选，分页）；请求详情含各收件人投递（状态、尝试次数、下次重试时间）及每次尝试（账号、状态、响应码、时间）。邮箱默认不显示（见 Q-05）。
6. **保护规则**：
   - 修改带乐观锁版本，并发修改返回冲突，不覆盖他人修改；
   - 停用正在被启用路由引用的发送账号、停用即时发送模板、停用其路由前要二次确认，并提示影响；
   - 即时发送模板的正文必须保留 `${link}`；
   - 不提供删除：历史请求引用模板和路由 ID，只能停用（见 Q-04）。
7. **权限与审计**：新增"通知管理"菜单及只读 / 维护两级权限，经 Platform 现有 Console Resource、Permission 机制注册；每次写操作记 Platform 审计。
8. **分层**：Platform 提供管理与查询接口（`*ManagementApi`），Operations BFF 转发并组装页面模型，Operations Web 实现页面；与 Vault、Risk 等现有运营配置页面保持同一交互模式。

## 4. 明确不做

| 项 | 说明 |
|---|---|
| 发送账号的凭据、发件地址、区域维护 | 仍走部署配置与 Vault；改成页面维护需要把这些搬进数据库并重新设计凭据边界，单独立项 |
| 新建发送账号 | 新账号必须有对应的部署配置和适配器才能发信，页面新建会产生"能配不能发"的账号（见 Q-02） |
| 删除模板、内容、路由、账号 | 只停用 |
| 修改历史 / 版本回滚 / 双人审批 | 只保留审计记录（见 Q-03） |
| 取消、人工重试、主动刷新投递 | 延续 Delivery 规划"后续单独讨论" |
| 测试发送真实邮件 | 本期只做预览（见 Q-06） |
| SMS、HTML 邮件、多介质 | 当前只有纯文本 Email |
| Client / Partner 侧通知页面 | 只做运营后台 |
| 修改 `transient-template-codes`、HTTP 调用方白名单 | 仍是部署配置，页面只展示 |
| 执行 SQL、部署 | 按阶段单独授权 |

## 5. 验收标准

**功能验收**

| 编号 | 验收标准 |
|---|---|
| AC-01 | 有只读权限的运营账号能看到"通知管理"菜单及模板、发送账号、发送记录页面；没有权限看不到菜单，直接调接口返回 403 |
| AC-02 | 新建模板、增改语言内容、设置路由、启停模板 / 路由 / 账号后，新发起的普通通知和认证邮件立即按新配置发送；不需要重启 |
| AC-03 | 内容保存时校验与发送时一致：占位符语法错误、标题含换行、超长均拒绝并定位到字段；即时发送模板缺 `${link}` 拒绝；预览用示例参数返回渲染结果且不调用 Vault 和 SES |
| AC-04 | 两人同时修改同一对象，后保存者收到冲突提示，数据不被覆盖 |
| AC-05 | 路由主备账号必须是已启用的 EMAIL 账号且互不相同；停用被引用的账号、停用即时发送模板或其路由时页面二次确认并说明影响 |
| AC-06 | 发送记录可按来源系统、来源事件键、模板、状态、时间筛选和分页；详情显示投递与尝试；页面、接口响应、日志都不出现收件邮箱原文、参数里的敏感值和凭据 |
| AC-07 | 每个写操作产生 Platform 审计记录（操作人、对象、动作、结果） |
| AC-08 | Platform、BFF、Web 的自动化测试覆盖上述主流程与失败分支；Platform 现有通知测试全部通过；覆盖率不低于既有水平 |
| AC-09 | Console Resource、Permission、API 路由注册 DML 写入 Platform 初始化 SQL；SQL 不执行 |

**视觉 / 交互验收**

| 编号 | 验收标准 |
|---|---|
| AC-10 | 菜单入口、列表、详情、编辑抽屉或页面与现有运营配置页面（如 Vault 数据类型、Risk 配置）风格一致；列表有空状态、加载和错误反馈 |
| AC-11 | 内容编辑区提供占位符提示和预览区；字段错误就地显示；冲突用横幅提示并可重新加载 |
| AC-12 | 发送记录状态用一致的状态标签；详情时间按本地时区显示，并能看出尝试先后 |

## 6. 问题与结论（2026-10-15 已确认：全部按建议）

| 编号 | 问题 | 结论 |
|---|---|---|
| Q-01 | 发送记录查询纳入本期吗？ | **纳入**，只读，不做取消 / 重试 |
| Q-02 | 发送账号只做启停，还是要能在页面新建、维护发件地址和凭据？ | **只做查看和启停**；新建与凭据维护单独立项 |
| Q-03 | 修改是否需要双人审批或版本历史？ | **不需要**，即时生效 + 审计 + 乐观锁 |
| Q-04 | 是否需要删除？ | **不提供**，只停用 |
| Q-05 | 发送记录要不要显示收件邮箱？ | **不显示**；受权限控制的单条 Reveal 是可选项，本期不纳入 |
| Q-06 | 要不要"测试发送"（用当前配置发一封真实邮件）？ | **本期只做预览**，测试发送后续再议 |
| Q-07 | 即时发送模板（认证邮件）在页面上可以改文案和停用吗？ | **可以改文案**（强制保留 `${link}`）；**停用需二次确认**，并提示会导致注册和找回密码邮件发不出 |
| Q-08 | 本需求同时改 Platform、`operations-console-bff`、`operations-console-web`。后两者目前有其他会话在改（支付风控配置接入），本会话能否编辑这两个目录？ | 允许本会话在这两个目录**新增**通知管理相关文件，对共享文件（菜单注册、路由、BFF 配置）只做增量修改；如有冲突先停下说明 |
| Q-09 | 适用阶段 | 1、2、3、4、5 照常（阶段 3 含页面设计）；6–7 test 部署**暂定不适用**，需要时再提；8 提交单独授权 |
