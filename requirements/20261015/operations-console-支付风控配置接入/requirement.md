## 1. 背景

Risk 已在 mor-test 交付支付风控点 `PAYMENT_ATTEMPT_RISK` 的运行期评估与配置能力（实时累计、名单、结束节点附加输出、执行发布、影子运行）。运营后台仍按结账点 `CHECKOUT_PREPARE` 写死，也没有接入名单与执行发布，mor-test 至今没有任何支付规则和生效发布，Payment 调用统一评估一律得到 503 `RISK_DECISION_NOT_CONFIGURED`，无法联调。

## 2. 目标

1. 运营在后台按风控点（`CHECKOUT_PREPARE` / `PAYMENT_ATTEMPT_RISK`）配置规则集、决策流与变量。
2. 运营能维护风控名单，能创建实时累计、名单命中两类变量，并在支付决策流的放行结束节点配置认证要求。
3. 运营能对支付决策流完成执行发布：创建、校验、影子运行、激活，激活前看清影子差异。
4. 在 mor-test 配置并激活一套支付规则，供 Payment 联调。

## 3. 已确认事实

| 事实 | 依据 |
|---|---|
| 规则集、决策流、变量的列表与创作按 `pointCode` 区分；各点可用字段、运算符、终态动作以创作上下文为准 | 交接单 2.1 |
| 支付点终态动作只有 `ALLOW_PAYMENT`、`REVIEW_PAYMENT`、`DENY_PAYMENT`，不开放附加动作 | 交接单 2.1；修订 C |
| 实时累计、名单命中变量只能属于支持运行期的风控点（当前只有支付点）；创建后参数不可改 | `VariableDefinitionValidator`；交接单 2.2 |
| 执行发布只支持运行期风控点（当前只有支付点）；结账点继续使用旧“测试候选”发布 | `CreateExecutionReleaseProcessor`；一期设计 6 |
| 执行发布没有列表接口，只有创建、详情、校验、影子运行、激活 | `ExecutionReleaseManagementApi` |
| 名单主体值是受限值；Risk 响应已脱敏，页面与 BFF 日志不得展示或记录原值 | 交接单 2.3；标准目录第 2 节 |
| 认证要求输出只在放行结束节点配置，可选 `NOT_REQUIRED`（默认）/`THREE_DS_REQUIRED`；创作上下文暂未返回声明 | 交接单 2.4 |
| 首个执行发布校验通过即可激活；已有生效发布时须先完成影子运行，且失败/超时为 0 | 交接单 2.5 |
| 只在 TEST 环境单人激活，PRODUCTION 双人审批未开放 | `ExecutionReleaseManagementApi` 类注释 |

## 4. 使用者与场景

| 使用者 | 场景 | 成功结果 |
|---|---|---|
| 风控运营 | 在规则配置页切换到“支付尝试”风控点，查看/编辑规则集、决策流、变量 | 列表与创作表单只显示该点的字段、运算符和终态动作；切回“结账准备”行为与现在一致 |
| 风控运营 | 新建名单、加入/失效成员 | 成员主体值只以脱敏形式展示；重复加入有明确提示 |
| 风控运营 | 新建实时累计或名单命中变量，在规则中引用 | 参数按 Risk 约束填写，创建后只读 |
| 风控运营 | 在支付决策流中把某个放行结束节点设为“需要 3DS” | 保存后流程详情显示每个放行结束节点的认证要求 |
| 风控运营 | 对支付决策流版本创建执行发布，校验、（必要时）影子运行后激活 | 激活确认框醒目展示“拒绝转放行”“认证要求变化”；激活后旧发布变为已替代 |
| Payment 联调方 | mor-test 调用统一评估 | 返回正常结论而不是 503 |

## 5. 本期范围与不做项（草案）

**包含**

- BFF 升级 risk-api 至当前版本（流程节点 `outputs`），回归既有规则集、决策流、变量、旧候选发布、字典能力。
- Web 规则配置支持风控点切换（规则集、决策流、变量）。
- 名单维护：名单创建与列表、成员加入/列表/失效（BFF 接入 `/risk-lists/v1` + Web 页面）。
- 变量新增 `VELOCITY`、`LIST` 两种来源的创建与展示。
- 决策流放行结束节点的认证要求输出（暂写死两个值，Risk 补上上下文声明后改为读取）。
- 执行发布：创建、详情、校验、影子运行（异步轮询）、激活；错误码 `RISK_RULE_SET_IN_USE`、激活前置 `BUSINESS_CHECK_FAILED` 的提示。
- Platform 菜单、权限点、Gateway 路由的注册 DML（按既有流程，在需求目录下提交执行文件）。
- mor-test：部署 BFF/Web，在后台配置并激活一套支付规则。

**不做**

- 修改 Risk 代码或合同；Risk 接口问题记录在 [technique.md](./technique.md) 的待问清单。
- 结账点的执行发布与运行期评估（Risk 未支持）。
- 影子运行批次历史与逐样本明细（Risk 一期只返回最近批次汇总）。
- PRODUCTION 发布、双人审批；名单批量导入/导出；名单编辑或删除（Risk 未提供）。
- 规则阈值的业务定稿：mor-test 规则只用于联调，不代表上线建议。

## 7. 验收标准（草案）

**功能**

| 编号 | 标准 |
|---|---|
| AC-1 | BFF 使用当前 risk-api 构建；既有规则集、决策流、变量、旧候选发布、字典接口回归测试全部通过 |
| AC-2 | 规则集、决策流、变量页面可在 `CHECKOUT_PREPARE` 与 `PAYMENT_ATTEMPT_RISK` 间切换；表单字段、运算符、终态动作来自对应创作上下文；结账点行为与改动前一致 |
| AC-3 | 可创建名单、分页查看名单；可加入成员（可选生效起止）、按主体值/状态查询、填写理由后失效；重复加入返回明确提示 |
| AC-4 | 页面任何位置只展示 Risk 返回的脱敏主体值；BFF 日志不含主体原值（自动化测试覆盖） |
| AC-5 | 可在支付点创建 `VELOCITY` 变量（事件、锚定主体、算法、去重主体仅 DISTINCT_COUNT、窗口四选一、是否计入本次；金额类自动带 MONEY 与币种变量）与 `LIST` 变量；创建后参数只读；Risk 校验错误按字段展示 |
| AC-6 | 支付决策流放行结束节点可选择认证要求 `NOT_REQUIRED`/`THREE_DS_REQUIRED`，非放行结束节点不可配置；保存后详情回显；`INVALID_OUTPUT`/`INVALID_NODE_CONFIG` 定位到对应节点 |
| AC-7 | 可对支付决策流版本创建执行发布，查看八项静态检查结果；校验后进入 SHADOWING 或 REJECTED |
| AC-8 | 已有生效发布时可发起影子运行（样本数默认 200、上限 2000），页面轮询至完成并展示全部汇总字段 |
| AC-9 | 激活确认框醒目展示“拒绝转放行”`denyToAllowCount` 与“认证要求变化”`actionChangeCount`，以及失败/超时数；不满足前置时展示 Risk 返回的原因，不激活 |
| AC-10 | 删除被执行发布引用的规则集时，提示 `RISK_RULE_SET_IN_USE` 并说明需查看执行发布 |
| AC-11 | 新页面与操作按阶段 3 确认的权限拆分受 Gateway/Platform 控制；无权限时菜单不可见、接口 403 |
| AC-12 | mor-test：BFF/Web 部署新制品；在后台配置的支付规则激活成功，Payment 以统一评估接口调用得到 ALLOW/REVIEW/DENY 及认证要求，不再 503 |

| 编号 | 标准 |

| UI-2 | 名单页与执行发布页沿用 Operations Console 现有列表/详情/抽屉风格，含空状态、加载、错误提示 |

## 8. 阶段安排（建议）

八个阶段全部适用：

1. 需求评审（本稿）
2. 现状差异与影响
3. 方案、接口、页面与权限设计（含 Platform 注册 DML 清单）
4. 研发（BFF + Web）
5. 本地验证：接本机 Risk 最新代码联调与浏览器验收
6. mor-test 发布准备：制品、注册 DML、联调规则与阈值清单
7. mor-test 部署、注册激活，配置并激活支付规则，与 Payment 联调确认
8. 提交归档

交接单的四步顺序在阶段 4 内按 ①risk-api 升级与风控点切换 → ②名单与新变量 → ③执行发布与结束节点输出 实施，④ 对应阶段 7。
