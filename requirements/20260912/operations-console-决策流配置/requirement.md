# 决策流配置：需求评审稿

状态：原阶段 1–4 已确认，阶段 5 未完成。用户新增确认“先精简，不要有重复的逻辑”，优先取消规则保存的重复协议/字段及旧顺序绑定依赖；精确实现和兼容取舍见待确认的 [精简修订](./simplification.md)。其余业务范围保持。原开发证据见 [开发交付报告](./development-checks.md)，确认及实现状态分别见 [delivery.md](./delivery.md) 和 [当前台账](../../../agent-docs/CURRENT_IMPLEMENTATION.md)。

一句话范围：完成决策流的列表、新建编辑、条件连线、静态校验、版本保存、详情与历史只读、整体删除，同时将规则命中后的动作改为可选，以支持按检查结果分流，所有保存操作均不执行真实风控。

## 1. 背景、使用者与成功结果

使用者为具有相应权限的 Operations 风控配置人员。运营需要将同一决策点下的规则集组合起来，配置“满足条件走哪条路径、何时结束”，而不是只能排列规则集的执行顺序。

典型场景：配置 Client 检查、订单检查等规则集节点；某次检查符合条件时连到 DENY 或 REVIEW 结束节点，否则继续下一次检查，最后显式选择结束决定。节点名称、判断字段和阈值由配置提供，示例不是系统内置策略。

本期成功结果是：用户在画布中完成一份结构合法、引用明确的配置，保存后重新打开可准确还原，能只读查看此前版本。静态校验通过仅说明配置满足本期合同，不代表规则已执行、执行器已就绪或业务流量已接入。

## 2. 已确认边界

- 本期交付配置管理：编辑、保存校验、历史查看；真实执行下一期。
- 使用 Pencil 评审页面；前端采用 React Flow 承担画布交互，Risk 拥有流程业务结构。后续执行器采用 Risk 自定义轻量实现，不引入外部后端流程框架。
- 连线可以承载判断条件，业务节点之后可以连接结束节点。页面方向以最新 [条件连线方案](./ui.md) 为准。
- 详情和历史复用编辑画布，只读且没有保存或修改入口；页面不加返回按钮，使用浏览器返回。
- 未明确要求升级接口时，沿用原接口版本或默认 `/v1`；代码类型名不带 V1/V2。配置历史版本与接口版本是不同概念。
- 保留现行规则终态语义：ALLOW / REVIEW / DENY 终止整个规则流程。技术失败不能当作正常未命中，更不能隐式放行；提前结束不能绕过系统义务。

确认来源统一记录在 [delivery.md](./delivery.md)；业务范围的窄范围取代关系见 [范围决定](../../../agent-docs/decisions/2026-09-12-risk-decision-flow-configuration.md)。

## 3. 本期功能

以下功能已随阶段 1 整体确认，阶段 2 据此核对完整代码与系统影响。

| 功能 | 目标行为 |
|---|---|
| 列表与检索 | 一条决策流一行；按当前决策点、编码或名称检索，查看当前配置版本。操作菜单含详情、编辑、历史版本和红色删除，不把多版本平铺到主列表。 |
| 新建与编辑 | 填写编码、名称、所属决策点和变更原因，编辑节点、连线及布局。编码和所属决策点首次保存后不可修改，避免历史身份混用。 |
| 规则集节点 | 选择同一决策点下的规则集准确版本，展示名称、版本、规则数与摘要。节点只管理引用，不嵌入另一套规则编辑器；规则集产生新版本后由运营主动选择，不自动追随最新版本。 |
| 条件连线 | 可顺序直连，也可配置条件出口与“其他情况”出口；条件展示在线上，在侧栏编辑。配置来源、字段、运算符、值和条件顺序，不开放 SQL、脚本或任意表达式代码。 |
| 结束节点 | 可以在任意业务节点后结束，可有多个结束节点；每个结束节点显式选择 ALLOW、REVIEW 或 DENY，不预选放行。DENY 复用现有拒绝原因字典及文案快照规则。 |
| 校验与保存 | “校验配置”只检查结构、字段、类型和引用；保存时 Risk 再做完整校验。保存产生不可变配置版本，保存失败保留页面输入，不自动发布或激活。 |
| 详情与历史 | 当前详情和任一历史版本均使用同一画布只读呈现，可查看节点、连线条件、引用和结束决定；历史不因字典改名、规则集新版本或后续编辑而改写。 |
| 整体删除 | 删除整个决策流的管理入口，不删除某一个版本或级联删除规则集。保留历史版本及既有引用证据，具体可删除条件见第 4 节。 |
| 配套规则配置 | 统一为匹配条件必填、命中后的动作可选；未配置动作时提供命中结果，由流程连线继续分流。不增加规则类型或模式切换。本项会涉及已有规则编辑与保存校验，已纳入本期范围。 |

## 4. 已确认业务规则

### 4.1 节点、连线与路径

1. 首期只有开始、规则集、结束三类节点，判断直接配置在线上，不另加独立判断节点、子流程、并行、循环或评分节点。
2. 一份完整配置恰有一个开始节点；开始节点无入线且有一条无条件出线。结束节点无出线。每个节点必须从开始可达，每条结构路径必须能够到达显式结束节点。
3. 规则集节点二选一：一条无条件出线；或一条及以上有顺序的条件出线，加且仅加一条“其他情况”出线。“其他情况”无需重复填写否定条件。
4. 多条条件按运营配置的顺序判断，第一条满足的出口胜出；全部正常求值且不满足时才走“其他情况”。画面明确显示顺序，不依赖连线创建时间或屏幕位置决定优先级。
5. 不做复杂的条件重叠推理。顺序已经定义重叠时的结果；保存检查的是顺序唯一、条件合法、出口完整。
6. 删除节点同时移除与其相连的线，不自动把前后节点重新连通。用户完成修复并通过校验后才能保存，避免悄悄改变判断路径。

以上描述用于定义本期保存的配置含义；本期不实现逐节点执行或条件求值引擎。

### 4.2 条件数据与可选动作

首期条件来源限定为当前决策点已开放的输入字段，以及当前出线所属规则集节点的“是否命中”。不读取任意服务数据，不引用后续节点或其他分支节点的输出。

“是否命中”的含义为：该规则集至少有一条启用规则满足自身条件；禁用规则不参与，全部未命中为否。只有节点没有产生最终决定时，才需要用这个结果选择出线。字段名称、类型与可用性由 Risk 的配置合同声明，不能把画板中的名称当作已有 API。

这里存在一项明确的旧约束变更：[原规则配置决定](../../../agent-docs/decisions/2026-09-11-risk-rule-v1-configuration.md)第 2 节禁止“无终态且无附加动作”的规则。本次允许命中后的动作留空，使“检查是否命中，再由连线决定下一步”不必附带冷却或标签动作。用户已确认取消“仅判断 / 配置决定或附加动作”的模式切换；统一使用原规则编辑器，匹配条件必填、动作可选，不新增规则类型或模式字段。仅扩展保存校验和回显，旧规则不自动转换；精确表示仍是现有 CONFIGURATION 的 action=null、additionalActions=[]，不能将需求批准解释为现有代码已放开限制。

如果一条旧规则仍配置了 ALLOW / REVIEW / DENY，命中后结束整个流程，不能将该决定降级为可继续的普通结果。仅产生附加动作的规则仍按原语义保留其动作；本期保存不实际执行任何动作。

未知字段、错误类型、错误运算符及不合法的结果来源在保存时拒绝。运行输入的空值、缺失、失败和超时不是本期可用真实数据验证的内容：本期记录字段可空性及已有操作符约束，不新增一个将运行错误转为“其他情况”的配置开关；准确求值合同在后续方案中与现有规则条件语义对齐，真实行为在执行需求中验证。

### 4.3 配置身份、版本及引用

- 同一决策点可以保存多条有独立编码的决策流，但本期不选择哪条对真实请求生效，不增加默认激活、流量匹配或发布审批功能。
- 允许选择同一决策点下仍可用于配置的 DRAFT/FROZEN 规则集准确版本；不强制运营为画图先冻结规则。禁止跨决策点引用，也不把已删除规则集或 RETIRED 版本作为新的可选项。具体资格须在阶段 2 与现有目录能力核对。
- 保存后的流程版本不可覆盖，继续编辑当前配置时产生新版本；历史入口只读，不新增历史回滚或从任意历史分叉的操作。并发保存不能静默覆盖其他人的更新，应保留当前编辑并提示重新加载。
- 只保存校验完整的配置，不增加服务端半成品草稿或自动保存功能。这里的“完整”是结构完整，允许引用配置阶段的规则版本，不表示达到冻结或运行发布条件。
- 保存名称、条件、规则集版本引用、结束决定和必要的展示布局；底层图形库的全部内部状态不成为业务合同。保存与重新打开的可观察结果必须一致。
- 历史查看保留原引用及当时的必要展示内容。后续规则集删除不级联清除流程历史；本期不因普通流程配置引用就扩大既有规则集“正在使用”的删除阻断口径。新保存时引用已被删除的规则集应提示替换。
- 决策流整体删除保留编码与历史，避免同一编码被重新解释；若现有生效配置确实引用它则禁止删除，不能只凭 FROZEN 或普通草稿引用判定使用中。实际是否存在此类消费关系由阶段 2 核对，不为未来执行预建无消费者的关联或锁定机制。

### 4.4 提前结束与旧配置兼容

新画布要求每条结构路径显式结束，不使用一个全局默认 ALLOW 掩盖断线；新增结束节点不预选决定，未配置完整时不能保存。

现有顺序规则及 Decision Point 默认决定继续按旧合同解释，本期不改写历史内容或历史 Hash。新图形配置如何与现有顺序配置共存、如何在详情中呈现旧数据，在阶段 2/3 核对后制定明确转换或隔离方案，不能把旧默认决定直接删掉。

## 5. 明确不做

本期不交付后端真实决策执行、样本试运行、执行轨迹、业务调用方接入、实际冷却/打标签、运行状态存储；不新增 TEST Candidate 操作入口、冻结发布、审批、激活、灰度或回滚功能。既有接口的兼容责任仍需在影响分析中核对。

不新增通用工作流能力，包括人工等待恢复、并行汇聚、循环重试、任意脚本、子流程调用或评分卡。图上的 REVIEW 是结束决定的配置，不表示系统已能创建并恢复一个人工审批任务。

## 6. 验收标准

以下为已确认的验收口径；不是已经实现或通过的测试结果。

### 功能验收

| 编号 | 可验收结果 |
|---|---|
| AC-F01 | 同一决策流有多个配置版本时，主列表仍只有一行；编码/名称/决策点查询正确，无匹配时显示空结果。详情、编辑及历史分别进入正确模式。 |
| AC-F02 | 新建并保存含开始、至少两个规则集及多个结束节点的流程；重新打开时节点位置、引用版本、连线条件、顺序与结束决定一致。 |
| AC-F03 | 可以保存顺序直连、条件命中后提前结束、其他情况继续三种结构；条件优先级明确，拖动节点不改变路径或条件顺序。 |
| AC-F04 | 未选结束决定、缺少出口/其他情况、多个开始、环路、不可达节点、错误字段/类型或非法引用，均被服务端拒绝且指出对应节点/连线；直接请求接口不能绕过校验。 |
| AC-F05 | 匹配条件必填，命中后的动作可留空，保存后无损回显；不新增规则类型或模式切换。已有动作可直接编辑、清空最终决定或逐项移除附加动作，旧配置不自动变更。连线可保存本节点“是否命中”的合法条件，但界面不展示伪造的实际命中结果。 |
| AC-F06 | 选择的规则集必须属于同一决策点并绑定准确版本；另存规则集新版本不会自动更新已有流程引用；已删除或不可用的新引用被拒绝并提示原因。 |
| AC-F07 | 修改当前配置产生新版本，旧版本及引用内容不变；并发保存冲突不覆盖他人改动，校验/网络失败后本地编辑仍在。 |
| AC-F08 | 当前详情与历史画布均可查看节点、连线和结束配置，不能保存、增删或修改；现有顺序历史依批准的兼容方案回显，不改写原数据。 |
| AC-F09 | 整体删除需要明确确认，成功后不再出现在正常列表；历史及规则集记录仍保留。存在经核实的生效引用时拒绝删除并说明引用；普通配置引用不被误称为正在运行。 |
| AC-F10 | “校验配置”和“保存”不会调用真实决策、执行动作或激活流程；仅查看权限的账号不能通过页面或直接 API 修改配置。 |

### 视觉与交互验收

| 编号 | 可验收结果 |
|---|---|
| AC-U01 | 沿用已认可的 Pencil 风格与条件连线布局；节点即使收起仍能辨认名称及版本，连线条件和分支顺序可读。 |
| AC-U02 | 选中节点或连线打开对应侧栏，编辑与只读模式区分明确；历史没有保存、删除或可修改控件。允许平移/缩放查看，不能拖改节点位置。 |
| AC-U03 | 页面没有返回按钮；列表到编辑/详情/历史及侧面引用查看后，浏览器返回到真正上一页，回到列表保留查询条件。未保存编辑离开时提示确认。 |
| AC-U04 | 覆盖首次新建、空列表、搜索无匹配、加载失败、保存失败与校验错误状态；错误能定位到节点/连线，删除入口为红色且提示删除对象。 |

## 7. 本阶段确认点与后续安排

第 3–6 节已整体确认，包括规则动作可选、条件按顺序首个匹配、同一决策点可有多条配置、只保存完整结构、允许准确的 DRAFT/FROZEN 引用，以及保持配置引用与运行使用的区别。

本需求适用 [公共交付流程](../../../agent-docs/REQUIREMENT_DELIVERY_WORKFLOW.md) 的八个阶段，每一步交付后等待确认。阶段 1–4 已确认，阶段 5 的验证结果完成后仍需用户确认；当前按用户要求先复核表关系。

阶段 2 交付现状证据、能力缺口和逐系统影响。阶段 3 交付正式接口/数据/页面及验证设计，并按用户要求用一句话统计：涉及系统、新增/修改接口、表与字段、索引、注册 DML 和页面数量。精确规模及合同以 technique.md 顶部设计包为准。
