## 1. 唯一变量库如何工作

Risk 在现有 risk-decision 内维护 `t_risk_variable` 与 `t_risk_variable_member`。定义、标签、值类型、用途、来源映射、格式关联、可选值集合和当前共享值均从数据库读取。Web 按查询结果生成选项；BFF 先授权后转发/组装，不持有业务变量名单。Risk 的保存校验器接收本次事务读取的变量定义，不能在启动时固化目录。

输入/输出合同仍是工程边界。管理页面的“来源字段”取自真实合同的字段元数据；字段键、实际类型、必需性、安全等级与最大用途由合同声明，变量的名称/用途选择由库维护。RCO-17 尚无输入执行器，不能把原 Descriptor 移个名字继续做“唯一变量目录”：研发时将它拆成精确输入协议结构与隔离的历史 Reader；新 authoring 仅查询库，协议结构只负责验证映射是否可能提供、类型和用途是否超界。不得为每个新变量生成 Java enum 或在三个应用写 switch。

例如新增 `ORDER_AMOUNT_ALIAS → ORDER_PREPARATION/4.net_amount` 是登记一个已支持事实的变量；创建后刷新即可选择。新增一个合同没有的“近 7 日交易额”不接受，本期没有对应取数算法。节点输出同理，真实结果没有运行记录可读，本期不构造样例运行值来冒充结果。

### 目录查询与刷新

- 不新增跨实例缓存、变量 Snapshot 服务或失效 MQ。Risk 每个查询/校验/保存从本库读取，批量加载本次引用及其直接依赖；同一次查询使用一个一致性读取事务。
- 原规则/流程 authoring-context 返回通用能力、准确合同和变量查询上下文；变量选项统一走 N02，分页搜索。空结果即空结果，禁止静态回退；目录失败可重试，不能保存未经 Owner 校验的草稿。
- 页面首次进入、选择器打开、搜索条件变化、窗口重新获得焦点、变量保存成功以及用户点击刷新目录时重新请求。保留草稿的编码和值，只刷新元数据/当前值，停用或缺失引用原位标红。
- 已打开的其他标签页在重新获焦或打开选择器时自动获取最新值；本期不承诺后台页面实时推送。共享值“自动采用”指下一次成功查询、校验及未来执行解析使用已提交的新值，绝不以重存规则/流程或重启应用为生效条件。
- 当前详情/历史详情对动态引用返回 `currentVariables` 与 `valuesAsOf`；这些是查询展示投影，均排除在内容 Hash 和保存回执之外。成员列表分页用 `expectedVersion` 检测翻页期间整批更新，冲突要求重新载入，不混合两次成员集。

## 2. 变量与集合的最小模型

变量来源固定为 INPUT / CONSTANT / COLLECTION / NODE_OUTPUT，值类型为 STRING / NUMBER / BOOLEAN / DATETIME / DURATION。集合只存同类型标量，不嵌套集合，不支持计算表达式。

- `point_code` 非空表示准确一个已支持决策点；常量/集合可为空，表示全部已支持决策点。首期无需任意多选点关系；不是用逗号字符串/JSON 存多点。字段及节点输出必须绑定准确点及来源合同版本。
- 三个用途开关分别对应规则条件、流程条件、既有动作主体参数。合同上限优先：INPUT_CLIENT_ID 仅动作可用；NODE_OUTPUT 仅当前 RULE_SET 节点出线可用，不能在规则内部、开始节点或其他节点引用。
- 定义创建后编码、来源、类型、映射、适用点、用途、量纲/币种关联、格式、可选值关联固定。修改名称、说明、常量值、集合成员、可用状态无需审批。结构需要变化时另建变量，并通过明确编辑替换引用，避免系统做隐含迁移。
- 系统管理定义的结构/状态/删除/系统集合成员不开放运营修改；仍可改名称说明。两个节点输出由工程合同登记，N04 不接受自行创建 NODE_OUTPUT 或 systemManaged。输入字段可创建别名，不能超过原合同的安全与用途上限。
- 普通常量值不能为空，集合允许 0–1000 个成员。单次整批保存同时受 64 KiB 请求上限约束；并不承诺 1000 个最长字符串都能装入一个请求。成员 512 字符、可选名称 255 字符；String 保留大小写及前导零，格式不合法明确报错，不偷偷大写或转数字。
- 集合以根 CAS 管理当前完整成员集，先校验并去重再一次性替换。成员 `value_key` 是规范值的精确字符串，配合全长唯一索引防重；数字 `8` 与 `8.00000000` 同一键。不是另一份业务真值或 Hash 版本表。
- `allowed_values_variable_code` 仅指向同类型且范围覆盖当前变量的集合，用于可选值展示和保存校验。集合本身不可再引用集合；集合是已批准变量事实，不另建通用字典平台。已有拒绝原因/主体标签仍走原字典 Owner，不复制到变量集合。
- 命名常量/字段变量与对应枚举范围比较时，显式 literal、常量当前值、集合当前成员均受值域校验；两个动态输入在静态阶段只校验类型/量纲，未知运行值不伪造。共享值后续变化不重算旧历史：下一次校验可提示当前值域不相容，历史展示继续保留结构。

### 停用、删除与使用关系

停用不删除定义和当前值；禁止新的配置保存引用它（含从旧版本编辑后另存），已存内容继续可读。执行期如何处理停用留待执行设计，本期不产生真实执行。变量删除为 DELETED 墓碑：必须没有任何版本引用或其他未删除变量依赖；即使仅历史引用也不能删除。编码永不复用。系统定义不能删除。

引用查询覆盖规则左右操作数、金额 literal 的币种变量、既有动作主体、流程条件左右操作数及币种、变量的可选值/币种依赖。返回准确根与版本、条件/动作/连线位置，并区分 CURRENT / HISTORY；删除根下保留的版本也计入 HISTORY。旧 CONTEXT 不冒充已经迁移的 VARIABLE 引用，旧数据可通过原合同读取，系统映射定义自身不可删除。

不新建引用影子表。规则/动作/定义依赖按新增索引读取；流程按既有条件行ID分批读取CONDITIONAL整树，由同一严格Reader解析两个格式并提取变量和币种引用；不使用数据库JSON路径、文本模糊匹配或新增影子索引表。旧格式没有VARIABLE引用，但仍须准确解析；未知/损坏格式报数据完整性错误，不能当作“无引用”。查询按分段游标和行 ID 顺序扫描，完整分页合同见 api.md；删除检查必须扫完相关候选或发现第一处引用，超时失败不删除。首期接受流条件候选扫描成本，不以漏报换性能。

## 3. 两侧共用一个操作数合同

操作数仍用现有 `operandRole + valueSequence`：新写 `sourceType=VARIABLE` 引用稳定 `variableCode`，或 `LITERAL` 保存本条条件自己的值。规则 AST 与流程新条件使用相同操作数结构、规范化器与类型校验器。没有“仅判断模式/动作模式”的新增分类。

| 运算符 | 左侧 | 右侧 | 类型 |
|---|---|---|---|
| EQ / NE | 1 个标量变量或 literal | 1 个标量变量或 literal | 同标量类型；NUMBER 量纲/币种一致 |
| GT / GTE / LT / LTE | 同上 | 同上 | NUMBER / DATETIME / DURATION；不对字符串排序 |
| IN / NOT_IN | 1 个标量 | 1 个集合变量，或 1–100 个同类型 literal | 成员类型与左侧一致，集合不能与 literal 混排 |
| BETWEEN | 1 个标量 | 下界、上界各 1 个标量变量或 literal | NUMBER / DATETIME / DURATION；含两端；已知下界大于上界拒绝 |
| IS_NULL / IS_NOT_NULL | 1 个标量 | 无 | 任一标量；不允许 literal null，常量非空时可静态成立/不成立 |

两侧变量/常量四种组合均允许。左侧为集合、集合 EQ 集合、隐式字符串转数值、未知编码、越权来源及类型不匹配均拒绝。集合变量容量与内联 literal 最多 100 项分开；不能在保存时展开集合引用为 100 个常量来伪装支持。

空值逻辑固定为三值逻辑的配置合同：合法可缺省运行字段没有值时为 NULL；EQ/NE/大小/IN/BETWEEN 遇到 NULL 返回 UNKNOWN；NOT UNKNOWN 仍为 UNKNOWN；AND 有 FALSE 则 FALSE，否则有 UNKNOWN 则 UNKNOWN；OR 有 TRUE 则 TRUE，否则有 UNKNOWN 则 UNKNOWN。只有 TRUE 满足连线，UNKNOWN 不胜出，可继续下一条件/ELSE。IS_NULL/IS_NOT_NULL 是显式判断；空集合 IN 为 FALSE、NOT_IN 为 TRUE（左侧非空时）。运行异常/未取到必需事实不是 NULL，不能借 ELSE 放行。这里只固定含义，不实现求值器。

### 数字与金额

NUMBER 使用 DECIMAL(24,8)，API 十进制字符串，不允许指数、NaN、Infinity、溢出或静默四舍五入。DURATION 非负 BIGINT 毫秒字符串，DATETIME 六位微秒 UTC。通用 STRING 格式由 `format_code` 选择，不按 country_code 等具体变量编码分支；TOKEN 为既有 ASCII 业务编码格式，其余通用格式定义见 api.md。

NUMBER 的 `numericUnit` 为 SCALAR 或 MONEY。MONEY 必须二选一：固定 currencyCode，或引用同点的 INPUT STRING 币种变量 currencyVariableCode；币种来源不能再指向金额/集合，禁止环。两个变量比较要求相同单位与相同币种绑定，固定 USD 与“取自订单币种”不自动视为相等。变量别名按准确合同/字段的币种绑定规范化后可认定同源；不按显示名推断。

金额 literal 的单位/币种也显式存入操作数。UI 可从另一侧选定的金额变量填入，但必须显示并随请求提交；两边都是 literal 时必须选择量纲与币种。原例 `8000 < 实付金额` 将 8000 设为订单币种金额；不能把任意 SCALAR 阈值当成 MONEY。常量阈值初始化为 MONEY + INPUT_CURRENCY，保留原示例含义。

## 4. 节点结果的建议定稿

本节是本阶段供确认的具体建议，不是假称执行器已有行为。

- 唯一业务 Wire 延用 `ALLOW / REVIEW / DENY`，页面显示 `PASS / REVIEW / REJECT`，显示名来自系统管理的 `NODE_DECISION_VALUES` 集合。用户选择 REJECT 实际保存 DENY，不额外增加另一套结果枚举。
- 本节点规则按已有 priorityNo 由小到大判断，**第一条命中且配置决定的规则**产生节点处理结果。命中但没有决定的规则继续；多条可能命中时不新增投票/最高风险汇总器。`matched` 表示已有至少一条规则命中，与是否产生决定独立。
- 全部未命中，或命中的规则均未配置决定：`decision=null`；前者 matched=false，后者 matched=true。不默认 PASS，不增加 NONE/NO_HIT 枚举。用 IS_NULL 可以配置无处理结果分支；异常不归入无结果。
- 在新流程中节点的 DENY 只是出线可比较的结果。`NODE_DECISION = DENY → 下一个规则集` 合法；只有到达 END 才形成新流程最终决定。旧 Candidate 的 FIRST_TERMINAL/原历史不按该语义重解释。
- 本期只保存/校验此定义，不执行规则、聚合结果、取数或附加动作，页面没有试运行/轨迹入口。

## 5. 旧数据、Hash 与回放

- 旧规则 content_format、旧 point/input snapshots、旧 schemaVersion=1 连线 Reader 保留，用原内容校验原 Hash。不得拿当前变量库重建旧输入快照并覆盖旧 Hash。
- 新规则保存请求显式 `operandFormat=VARIABLE_REFERENCE`，存储使用 `RISK_RULE_SET_VARIABLE_CONFIGURATION` content_format；新条件 condition.schemaVersion=2 复用原图 graph.schemaVersion=1。这是存储内容判别，不升级 HTTP v1，也不在类名附加 V1/V2。
- 新 Hash 投影包含变量编码、声明类型、literal 原值及其量纲/币种、节点/条件顺序和原其他业务内容；**不包含变量名称、当前常量/成员、变量 CAS、currentVariables、valuesAsOf**。变量定义结构创建后固定。
- 历史编辑先显式装配新草稿：原 CONTEXT 按“系统定义 + 准确点/合同/字段”找到变量（系统映射唯一，普通别名不影响默认映射），旧 literal 值仍是 literal；旧 NODE_RESULT matched 转 NODE_MATCHED 引用。UI 提示将保存新版本，原版本不改写。无法映射时不能保存，不用名称猜测。
- 对新鲜的旧格式保存请求返回 400 LEGACY_AUTHORING_NOT_SUPPORTED，指导刷新页面；对已成功的原幂等命令先验证原请求 Hash 并按原回执重放，不查当前变量可用性、不再次创建版本。新命令同样先走原 claim/replay 路径，再做首次写入校验。
- 当前/历史详情可返回旧结构加非 Hash 展示投影。动态引用展开明确标“当前值”，不承诺还原共享值的历史版本。旧直接 literal 仍显示原保存值，不能标成公共阈值。
- 新统一变量内容一律 CONFIGURATION_ONLY。Freeze、Candidate 创建和静态执行就绪校验拒绝该格式；旧已成功回放与旧可用路径保持，不把“字段变量恰好映射旧输入”当作新格式已可运行。

## 6. 事务与并发

现有 Foundation Redis-first @ResourceLock 复用，锁实际变量编码或规则/流程根，不增加 Tenant 锁。变量管理 Processor 在代理入口持资源锁，短本地事务内根 FOR UPDATE + expectedVersion CAS；集合根和成员同事务整批提交。普通变量维护不引入命令回执表；响应未知由用户刷新/重试同一 CAS，创建编码唯一防重。

保存新规则/流程先完成现有业务根锁/幂等流程，再按编码排序对全部变量及其选项/币种直接依赖 FOR SHARE，校验 ACTIVE、类型、作用域和当前值后写内容。变量维护只锁目标根，不反向锁规则/流程根；删除事务的首次数据库访问必须是目标根FOR UPDATE；取得该锁后才建立引用查询的一致性读取视图，避免等待期间已有保存提交却仍使用过早快照漏报。相关引用用普通一致性查询，不能升级成反向锁整个引用图。根改名/常量值/成员替换与保存竞争由共享/独占锁串行化。创建定义时先收集依赖并按编码排序锁相关现存根，校验不会循环；并发死锁按现有业务冲突处理，不偷偷多次改请求。

停用/删除不会穿过已有持共享锁的保存；等待后重读最新引用。整批更新失败全部回滚，不留下半批成员。CAS 冲突返回当前版本而不覆盖用户草稿；不自动把用户 expectedVersion 改成最新再提交。仅查询引用不作为删除的授权凭据，删除事务必须复核。

## 7. 对现行规则的窄范围修订

本设计确认后，研发阶段同步以下投影：Risk 数据库规范中的 Operand 来源增加 VARIABLE；RCO-17 的新配置输入来源改为库，原三张 point/feature 表继续供旧历史/执行版本使用；节点结果子项 RCO-18 的 Wire/空结果语义采用第 4 节；完整规范化仍由 Foundation JCS 提供，业务 Hash 投影归 Risk。

本阶段不改写历史决定为已实施。Gateway 数据库 Snapshot、BFF 逐请求 PLT-I02、核心系统分库、禁止任意 SQL/脚本来源、手工 SQL、现有 Service interface + Impl 和 Java 分层规范保持。
