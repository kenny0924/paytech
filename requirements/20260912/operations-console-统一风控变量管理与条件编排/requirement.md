# 统一风控变量管理与条件编排

编号：RCO-19。阶段 1 范围与验收已获用户确认；来源、确认和下一停点见 [delivery.md](./delivery.md)。阶段 2 分析已确认，见 [technique.md](./technique.md)；阶段 3 [完整方案](./design.md)已获用户确认，阶段 4 代码研发与开发回归已授权。

**一句话范围：以变量库作为风控业务变量定义的唯一来源，移除前后端新配置链路中的业务变量硬编码，让规则条件与决策流共用变量引用，并迁移 test 示例；左右两侧仍支持直接常量，本期交付配置管理，不交付真实执行。**

## 1. 背景与目标

使用者为有相应权限的 Operations 人员。目前国家/地区、行业代码等可选字段受固定目录约束，规则与流程条件分别维护选择逻辑，不能自由比较两个变量，也不能引用集中维护的集合。

目标是在一个地方维护变量定义，在规则和流程编辑器按可用场景选择；调整国家集合、行业集合或公共阈值时，不必在多条条件中重复录入。变量有清楚的业务名称、来源、类型和使用关系，已有配置与历史仍可准确查看。

用户进一步明确：“系统（不论前端还是后端）不再 hardcode 变量，而是所有的变量都由变量库管理。”本需求中的变量指风控业务变量，包括输入字段、共享常量、集合和节点输出；统一目录需要真正来自 Risk 拥有的变量库，Web 从接口获取目录、后端仍用固定列表限制字段的做法不满足本需求。

## 2. 本期范围

### 2.1 统一变量目录

变量的“来源”与“数据类型”分开表达。字段和常量都可以产生数字或字符串；集合另有统一的成员类型。

| 来源 | 示例 | 本期能力与边界 |
|---|---|---|
| 字段变量 | 国家/地区、行业代码、MCC、币种、实付金额 | 变量库维护其来源、输入字段映射、类型及适用范围，映射必须符合已接通的输入合同；已有字段整体纳入，不保留用于新配置的第二份代码字段目录 |
| 常量变量 | 公共金额阈值 `8000` | 集中维护有名称和类型的固定值，供多个条件引用；区别于直接写在某条条件里的数值 |
| 集合变量 | 受限国家集合、关注行业集合 | 集中维护同一类型的成员，支持查询、增删、批量粘贴和去重；至少覆盖国家、行业、MCC 等字符串集合，不做任意嵌套对象集合 |
| 节点输出 | 本节点是否命中、本节点处理结果 | 定义、输出字段映射和适用节点保存在变量库，按当前节点过滤展示；实际输出由对应取数能力提供，运营不能手工编造运行结果，也不能在结果尚未产生的规则内引用它 |

字段变量的登记不意味着新数据源已经接通。本期复用已有批准输入；新增系统查询、统计计算等需要后续明确的数据接入需求。

### 2.1.1 变量库与代码的职责

- **变量库拥有定义：** 变量标识/编码、名称、说明、来源与字段映射、数据类型、业务可选值或既有字典引用、适用决策点/节点范围、可用状态，以及常量值和集合成员。既有字典可作为可选值 Owner，不复制字典事实。
- **后端按库校验：** 配置读取、保存、变量存在性、适用范围和类型判断以库中定义为准；不得再通过具体国家/行业/金额字段的枚举、名单或逐字段分支维护第二份变量事实。已有动作配置如消费同一业务变量，也应复用变量库，不扩展新的动作能力。
- **Web/BFF 按目录消费：** Web 的选择器、名称、类型及选项来自接口，BFF 转发并做通用协议校验；不得保留固定业务变量列表，或把不存在的变量补成默认项。库中无定义或不可用时按合同提示，不能回退到静态目录。
- **代码拥有通用能力：** 取数适配器、输入/输出合同、字符串/数字等类型系统、比较运算及权限规则仍由代码实现。代码根据变量定义定位已有输入或输出，不为新增同类变量再写逐变量分支。新增尚未提供的数据、取数来源或运算算法仍需要相应研发；配置一条变量不能生成不存在的事实。
- **初始化与历史：** 国家、行业、金额、matched 等现有变量转为变量库注册数据，初始化遵守现有手工 SQL 流程；不得在启动时重建目录。旧历史解码如确需保留固定旧合同，仅用于识别原版本，不能为当前新配置提供另一份目录，后续分析需逐项列明。

核心验收场景：在已支持的来源和输入合同范围内，新增变量定义后，无需修改、重新构建或发布 Web、BFF、Risk，两个编辑器即可发现该变量，后端可校验、保存和回读其引用。目录刷新、缓存失效及生效时点须在阶段 3 明确，不能用重启应用作为正常维护方式。

### 2.2 变量管理

- 列表支持按编码、名称、来源和数据类型查询，查看定义及引用位置。
- 支持常量、集合及已注册字段映射的新增、编辑、详情；系统节点输出在可用目录中展示，其含义不可由运营修改。
- 编码作为稳定引用标识；有引用的定义不能通过改编码、改数据类型或删除而破坏已保存配置。允许修改的范围及停用/删除方式在方案阶段明确，避免增加额外审批流。
- 集合支持批量粘贴成员，保存前反馈重复项、格式错误及有效数量；一个集合不混用字符串与数字，不把行业代码或前导零编码转为数字。
- 使用关系可以定位到引用它的规则集/决策流及版本，并区分当前配置与历史引用。先提供可查询、可跳转的关系，不强制新建复杂血缘画布。
- 共享常量或集合成功保存修改后，所有引用它的规则/流程自动采用最新值，无需逐条修改、重新保存或主动更新引用；具体边界见第 5 节 Q1。规则/流程仍引用同一个变量，不因共享值变化自动生成新的规则/流程版本。

### 2.3 两处条件编辑器共用操作数

条件统一表达为“左侧值 → 运算符 → 右侧值”。每侧可以选择变量或直接输入常量；直接常量仍属于当前条件，只有通过变量编码引用的值才由变量管理维护。

| 示例条件 | 验收目的 |
|---|---|
| 国家/地区 **属于** 受限国家集合 | 字段变量与集合变量比较 |
| 行业代码 **不属于** 允许行业集合 | 同一个集合可被多处引用 |
| 实付金额 **大于** 公共金额阈值 | 字段变量与常量变量比较 |
| 实付金额 **小于等于** 商品金额 | 两个已有数字字段比较 |
| `8000` **小于** 实付金额 | 左侧常量、右侧变量 |
| 本节点处理结果 **等于** `REJECT` → 下一个规则集 | 输出变量驱动流程连线，REJECT 不强制连向结束节点 |

同一表达式结构可描述两侧都是常量，但是否成立仍由运算符和类型校验决定。保留已有条件组、条件顺序、空值判断和区间判断；一元运算符不强制填写右侧，区间边界按相同变量/常量原则设计。

类型不兼容时不能保存，例如金额与国家集合做数值比较。`IN/NOT_IN` 的右侧必须是成员类型与左侧相容的集合，可选择集合变量或直接输入集合常量。金额比较还必须有一致的单位/币种语义，不能仅因为都为数字就允许无意义的比较。完整运算符矩阵、空值和容量限制在阶段 3 固定。

### 2.4 节点结果与历史兼容

- [RCO-18 节点处理结果](../operations-console-决策流节点处理结果/requirement.md)作为本需求子项纳入，保留原“是否命中”，另增“本节点处理结果”。具体结果语义以该子项为入口，不复制一套结果字典。
- 节点输出只在合法上下文出现；首期限定当前规则集节点的出线，不新增任意前序、兄弟或未来节点的结果引用。
- 节点输出定义与选项来自 Risk 变量库及其引用的已有字典，由统一目录接口提供；Web、BFF 和后端目录生成器不各自维护一份变量名单。底层输出合同仍须与这些定义一致。
- 旧规则条件、matched 条件及历史版本原样可读，保存新配置时不能静默把旧条件改成新含义。旧 Candidate 与运行接口不得因为增加可配置变量而自动宣称支持真实求值。
- 本期的“本节点处理结果”是可保存、可校验的条件定义，不产生真实节点运行结果。多规则结果汇总、未命中/空动作和新旧终态语义需要在方案中明确，执行实现仍延期。

### 2.5 test 示例迁移

用户已明确“修复数据”是将现有 test 示例改为统一变量引用，纳入本期功能交付。迁移目标为现有 `DEMO_FLOW_AMOUNT_CHECK` 规则集及 `DEMO_CHECKOUT_BRANCH_FLOW` 决策流，沿用其管理身份；发布前核对当时的最新版本，不能覆盖期间用户的修改。

| 当前示例条件 | 迁移目标 | 初始业务含义 |
|---|---|---|
| 规则：net_amount > 直接常量 8000 | 实付金额变量 > 示例金额阈值变量 | 阈值变量初始值为 8000 |
| 流程：NODE_RESULT matched = true | 本节点是否命中变量 = 直接常量 true | 保留 matched，不替换成处理结果 |
| 流程：currency != 直接常量 USD | 币种变量 != 示例标准币种变量 | 标准币种变量初始值为 USD |

- 变量编码、准确映射和数据操作清单在方案阶段确定，不直接写入当前尚不支持的引用结构。
- 迁移后初始含义仍是“大额拒绝；其余非 USD 人工审核；其他放行”，金额和币种变量由库统一提供。规则名称、分支说明和拒绝文案改为“超过配置阈值”等不会随变量值更新而失真的表达，不新增文案模板引擎。
- 使用已有版本保存机制生成可追溯的新配置，流程引用本次迁移后的准确规则集版本，原历史保留。共享变量值自动采用最新值，不等同于流程自动切换到任意最新规则集版本。
- 本期配置能力部署到 test 后执行该限定迁移，并核对保存、回读、变量引用和共享值修改后的展示。当前阶段不执行数据迁移，不把配置校验称为真实风控执行。

## 3. 本期不做

- 决策流真实执行、试运行、执行轨迹、发布激活及真实拒绝、冷却、打标签。
- 自定义公式、脚本、任意 SQL/HTTP 数据源、历史聚合、滑动时间窗和跨系统新取数集成。
- 把国家、行业等业务选项全部重新建设成一套通用字典平台；已有字典能力按职责复用。
- 泛化变量审批、自动发布、通用回执、复杂依赖调度或无实际引用消费者的新表。
- 自动升级 API 版本或给代码类增加 `V1/V2` 后缀。

## 5. 关键决定与待确认项

已明确：统一管理、左右两侧变量或常量、字段/常量/集合及节点输出纳入本期、保留 matched、真实执行延期、接口版本沿用及每阶段确认。

**Q2（已确认）：前后端的风控业务变量统一由变量库管理，test 示例迁移为变量引用。**

第 2.1.1 节和第 2.5 节分别明确唯一来源与示例迁移边界。此前“修复哪处示例数据”的问题已解决，不再按单个条件损坏排查。该确认落实需求范围；后续系统影响、具体接口/数据设计、研发和发布仍按既有阶段流程交付。

**Q1（已确认）：共享常量和集合自动采用最新值。**

用户明确选择“自动采用新的值”。此前建议的“保留保存时的值、主动更新引用”不采用。

- 自动更新适用于通过变量标识引用的共享常量/集合；修改成功后，引用方使用其最新成功保存值，不要求逐条重新保存规则或流程。
- 直接写在条件里的常量仍为该条件保存的值。不会按名称或数值相同，就将原有直接常量自动转换成共享变量引用。
- 例：两个规则都引用“公共金额阈值”，从 `8000` 改为 `10000` 后，两处引用均采用 `10000`；另一条直接填写 `8000` 的条件仍为 `8000`。
- 历史规则/流程保存的条件结构、直接常量及变量引用身份不改写。历史页面若展开该动态变量，应标注为“当前值”；不能把当前值当作保存当时或过去执行时的值。本期不承诺恢复共享变量的过往值，也不为此增加一套变量历史管理。
- 变量更新不自动改写引用方的历史内容、Hash 或版本，也不自动发布/激活规则或流程。未来真实执行采用最新值的解析、一轮执行中的一致性及实际用值证据在执行期设计；本期只交付对应的配置与展示合同。

本决定不预设新增变量版本表。阶段 2/3 需核对既有规则/流程内容与 Hash、Candidate 及静态目录的兼容方式，避免把动态引用自动开放到当前未支持的执行入口。

阶段 3 还需给出明确可审阅建议：结果唯一枚举、多个规则的结果汇总、无结果表达、旧终态兼容、类型/运算符/空值矩阵、集合容量、字段映射可编辑边界，以及动态值读取/刷新与错误处理合同。不得将它们默认为已批准，更不能以“配置阶段”回避影响保存含义的合同。
