# platform-support：联合查询 · 需求

> 状态：**已实施并部署 mor-test（2026-10-30，阶段 1—8 完成；含修订 b / c）**。来源：[2026-10-29 联合查询决定](../../../agent-docs/decisions/2026-10-29-data-query-joint-query.md)（J1—J9、Q1—Q7）；讨论稿 [design-discuss/joint-query](../../../design-discuss/joint-query/design.md) 与 `joint-query.pen`。确认记录见 [delivery.md](./delivery.md)；技术方案从阶段 2 起写入 [technique.md](./technique.md)。

## 1. 背景

- data-query（2026-10-22 交付，[需求](../../20261022/platform-support-数据查询服务/requirement.md)）已有：已登记的只读数据源、自研模板语法、参数声明 `parameters_json`、列声明 `columns_json`（含屏蔽）、多层只读校验、模板版本、`DATA_QUERY_EXECUTE`；REQ-05 又增加了模块内公开执行入口 `RunDataQueryTemplateProcessor`。
- 每次只能执行一个模板。排查一笔退款要先查退款单拿到订单号，再查支付意图、尝试、动作、渠道交易号，再查计费事实、记账、凭证、对账流水——跨 7—8 个系统手工接力。

## 2. 目标

1. 运营选择键类型、输入单号，一次查出整条链路上各系统的数据。
2. 展开路径由模板上的键类型标注自动推导，新增一个系统的模板即可接入链路，不改代码。
3. 每条数据说明“是由哪个模板、用哪个键值、从哪一行查到的”。
4. 展开受控：不因维度键（客户、OE、MID）拉出无关数据；护栏触发时给出部分结果和截断说明。

## 3. 使用者与场景

| 使用者 | 场景 | 成功结果 |
|---|---|---|
| 运营 / 客服 | 客户报一个退款单号，选 `REFUND_REQUEST_NO` 输入 | 看到退款、订单、该订单全部退款、支付意图 / 尝试 / 动作、渠道退款、渠道交易号、计费事实、记账、凭证、对账流水，以及它们的来源链路 |
| 运营 | 只有渠道交易号（渠道对账差异） | 选 `EXTERNAL_TRANSACTION_ID`，反查到支付动作、订单及财务数据 |
| 运营 | 结果中看到 `CLIENT_ID` | 维度键不自动展开；点击后另起一次以该键为入口的查询 |
| 模板作者（Owner） | 新写一个“争议 by 订单”模板并标注键类型 | 保存时提示“参与联合查询”；可达预览中 `ORDER_ID` 下出现该模板 |
| 模板作者 | 模板有两个必填参数 | 保存成功，警告“不参与联合查询：必填键参数不唯一” |
| 管理员 | 新增键类型 `PAYOUT_ID` | 模板编辑器可选；被 ACTIVE 模板引用后不能停用 |

## 5. 不做项

- 单号类型自动识别（J7）；预设链路方案（J5）；按另一列值决定键类型的动态绑定（Q4）。
- 查询记录、结果导出、跨模板按主键合并去重（Q5）。
- Client / Partner 门户使用；workflow `DATA_QUERY` 动作调用联合查询。
- 新的跨库读取例外、新的执行权限码（Q6）。
- 修改各业务系统代码或表结构。

## 6. 业务规则

| # | 规则 |
|---|---|
| B1 | 键类型编码全局唯一；值类型 INTEGER / STRING；分组 `group_name` 与默认角色 `default_role` 由数据维护（阶段 3 修订：链路 / 维度以模板列标注为准，键类型只给默认值；列标 LINK 而默认为 DIMENSION 时提醒但不阻止） |
| B2 | 参与条件：模板 ACTIVE；配置了 `joint`（行主体键类型 + 一个键参数）；键参数为必填；其余参数可选或有默认值（FRAGMENT 取默认） |
| B3 | 参数类型须与键类型值类型匹配：INTEGER 键可绑 INTEGER 或 STRING（含 LIST），STRING 键只绑 STRING（含 LIST）；列的 `keyType` 与 `keyRole` 须同时出现；LINK 列不可屏蔽；被引用的键类型须 ACTIVE。LINK 列不在结果中时执行节点给出提示（服务端保存不执行查询）。阶段 2 修订（S-02、S-03） |
| B4 | 值规范化：INTEGER 去前导零并校验 64 位范围；STRING 原样（不 trim、不改大小写）；规范值用于去重和绑定 |
| B5 | 展开：同一 `(键类型, 规范值)` 全程只作为触发键一次；只有 LINK 列的非空值进入下一跳；DIMENSION 列不展开。展开双向：上游对象由“按自身 ID 查”的模板带出（如输入支付尝试 ID 可查回订单与收银台） |
| B5a | 展示：节点按行主体键类型定位——泳道为其分组 `group_name`，泳道顺序取分组内键类型最小 `sort_no`，颜色按泳道顺序取色板；分组名与颜色不在代码中写死，泳道内按 `sort_no`；与跳数无关，跳数只显示在节点详情 |
| B5b | 已加载对象不重复查询：“按自身 ID 查”的模板（触发键 = 行主体键）遇到已加载的对象值时跳过，不计入护栏；被跳过的视图在节点明细中可按需查看。其他模板照常执行（2026-10-30 阶段 7 验收后修订） |
| B5c | 页面按对象合并显示：同一对象（行主体值）经多条路径查到时只显示一次，其余路径在该对象的节点明细中注明；模板“查出来的每一行是”须为该行自身身份（子行模板用独立键类型）（2026-10-30 修订 c） |
| B6 | 同层同键类型的值合并为一次 LIST 执行；标量键参数逐值执行；同一模板被不同键类型触发时分别执行、不合并 |
| B7 | 每个模板执行只取第一页，行数 = min(maxRowsPerTemplate, 模板 maxPageSize)；超出标记截断 |
| B8 | 护栏（默认值，可配置）：服务端单步——单键值数 50、单模板行数 100、单步执行数 20、单步并发 8、单步预算 8 秒；页面累计——层数 6、模板执行总数 60、总时长 60 秒、可随时停止。触发后停止新执行，已完成结果照常返回。阶段 2 修订（S-01：Gateway 10 秒硬上限下单次调用无法容纳 30 秒） |
| B9 | 单模板失败（超时、数据源不可用、只读校验拒绝、参数错误）只记在该节点，不影响其他节点 |
| B10 | 结果沿用模板列屏蔽；执行不写 `mor_platform`；所有被查库访问在事务外 |
| B11 | `CLIENT_ORDER_ID` 作为入口命中多个 Client 时全部展开并提示（Q3）；`EXTERNAL_TRANSACTION_ID` 当全局键，结果显示渠道列（Q2） |
| B12 | 键类型被 ACTIVE 模板（当前版本）引用时不能停用，且不能修改值类型；分组、默认角色可改 |
| B13 | 入口值按键类型 `value_pattern` 整串匹配（为空不校验）；只校验入口值，不校验展开得到的值；正则只允许 Java 与 JavaScript 行为一致的语法 |

**功能验收**

## 9. 已确认事实、假设与待确认

**已确认**：J1—J9、Q1—Q7（见决定）；入口由用户选择键类型。

**假设（阶段 2 核对）**

- A1 `RunDataQueryTemplateProcessor` 可被联合执行复用，且支持按模板编码 + 参数 + 行数上限执行、不经会话权限二次校验；否则需在 data-query 模块内抽出共用执行入口。
- A2 data-query 连接池可承受单请求并发 8；`DataQueryRunner` 单次超时上限 8 秒（REQ-05 记录）与 totalTimeoutSeconds 30 的关系在阶段 2 明确。
- A3 mor-test 已登记的 `MOR_*_REPLICA` 数据源与只读账号覆盖演示链路需要的 acquiring、payment、billing、account、ledger、reconciliation、channel-connector、dispute 库；不足的需补登记（属阶段 7 环境数据）。
- A4 讨论稿第 4 节来源列按 schema 推断；`t_payment_intent.source_type` 的订单类型取值、ledger `source_event_key` 与 account 记账批次的对应关系需按代码核对。
