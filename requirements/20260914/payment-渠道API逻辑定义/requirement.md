# 通用外部 API 配置与执行

2026-09-15 最新页面修订见[公共脚本与 HTTP 对象](./public-script-http-context-design.md)：公共方案与独立脚本合并为公共脚本，提供源码、参数、阶段对象权限和 API 引用；原 Pencil 已替换 3 张画板、新增 2 张画板，并同步模型页导航及响应取值路径。当前为设计工件，未实现脚本执行。

2026-09-15 当前设计增量见[公共模型、层级对象与响应场景](./model-library-and-response-scenes.md)：Operations 新增数据模型页，维护嵌套对象、数组元素和模型引用；API 绑定输入名称与模型，响应按公共场景映射不同 outputs。用户要求做此设计，原 Pencil 已补 M01～M08 画板；实际功能仍未实现。

本需求从 Payment 渠道 API 推广为通用外部 API 配置执行能力。当前边界以[通用执行修订](./generic-execution-amendment.md)为准：无支付方式节点、无固定支付身份及幂等入参；执行过程不持久化、不重试；返回 executeStatus 与自定义 outputs。目录沿用原需求路径以保留历史引用；Owner 与执行方式由[Platform HTTP 执行修订](./platform-http-execution-amendment.md)收敛为 Platform 管理并执行、业务方通过内部 HTTP 调用。确认范围见[交付记录第 19 节](./delivery.md#19-通用执行边界修订2026-09-14)。

字段映射与简单脚本原理继续参考[模型与映射设计](./model-and-mapping-design.md)。[NI 样例](./ni-refund-example.md)、[详细设计](./design.md)及其管理 Wire、SQL、Pencil 是通用化前的工件，受本次修订影响的部分待同步。当前仍为阶段 3 设计，未进入应用研发、真实外部调用、正式模型变更或 SQL 执行。

## 1. 背景与目标

用户希望通过 Operations 配置外部接口，以 `接入分组 → API` 组织配置，建议技术名称为 Integration。支付渠道、地图服务、邮件服务均可使用这个模型，不要求支付方式、MID 或退款等业务概念。定义需要表达传输协议、请求头/体、响应头/体、加签、验签、加密、解密及结果字段映射。HTTP 为当前设计示例，SMTP、XML 等只保留扩展位置，不宣称已经实现。

同一接入分组可以有多套公共脚本；不同 API 可以共享或分别选择。API 显式维护 scriptCode、参数绑定及执行顺序，不依赖隐含继承。

调用方提供支付上下文、退款上下文等业务数据。需要额外数据时，直接使用开发者已实现并注册的系统函数，绑定入参，并通过字段选择工具读取函数返回值。查询是函数的内部实现，不让 Operations 维护独立查询策略。这里的调用方是渠道 API 执行能力的调用者，不表示新增公网调用入口。

字段取值统一为三种方式：上下文 JSON 路径（如 xxxContext.abc）、表达式（本设计使用 Aviator）和系统函数。表达式可同时取值与加工；系统函数先绑定入参并取得返回值，再用 result 表达式选字段或处理。不增加单独的转换格式选择器，固定值也可由表达式字面量表示；报文编码及协议保护仍独立处理。

普通请求 Body 用字段映射组装，响应按公共场景和 outputMappings 映射。公共脚本可修改当次 http.requestHeaders/requestBody 或 responseHeaders/responseBody；复杂逻辑由代码函数实现。脚本不是字段取值的第四种来源，也不直接取代最终 outputs 映射。

本轮面向熟悉外部接口文档的接入人员与开发者，交付可评审的定义及调用边界。Operations 是管理入口；通用能力的工程位置和配置管理 Owner 仍需确定，不自动新增独立服务，也不把地图或邮件配置写进 Payment 渠道主数据。

## 2. 本轮范围

1. **API 定义：** integrationCode、apiCode、输入合同及数据来源、传输配置、请求处理链、响应处理链、状态映射及输出合同；不含必填支付方式。
2. **处理步骤定义：** 公共脚本引用、参数绑定、阶段、执行顺序及失败行为；请求组装支持已注册的只读业务查询。
3. **公共脚本定义：** 接入分组内多套命名脚本，维护参数结构、源码和 HTTP 工作对象访问范围；API 通过 scriptCode 引用，复杂算法由代码函数实现。
4. 表达请求与响应的处理顺序、对象/文本/字节边界，以及一次调用内部的数据依赖。
5. 表达公共脚本共享、差异配置和明确引用；保存成功后新调用直接生效，暂不设计版本发布。API、公共脚本及公共模型分别维护，分组存储与最终物理表数量待确定；旧 Payment DDL 不作为通用模型。
6. 提供合成示例、字段图解与评审验收项，让每项配置能对应一次调用中的具体数据；以 NI 退款公开协议给出完整逻辑配置、合成输入输出与过程图，对照工程列出现状差异和影响。
7. 明确 Operations 页面、Owner/BFF 管理接口、输入/共享输出合同及数据库需要同步的部分；保留旧稿证据，不把尚未同步的 Wire、Pencil 或 SQL 声明为可实施的通用设计。
8. 单次运行只在内存中组装和执行，不建执行流水、幂等记录或重试任务，不写已有业务表。业务调用方保留自身事实、幂等、并发和恢复职责。

一次 API 执行最多发起一次本 API 的目标渠道通信；基础输入、查询补数或请求处理失败时渠道通信次数为零。注册查询可以调用 Owner 的内部同步接口，“一次渠道通信”不限制合法的数据查询为零，但查询不能夹带另一笔渠道动作。认证所需材料先作为受控输入；共享 Token API 的独立归属、自动获取、刷新、缓存和跨渠道 API 调用关系暂不展开。

## 3. 已确认边界

- API 按接入分组和 apiCode 定位。支付方式与具体 API 的选择由 Payment 业务适配完成，通用配置不保留 paymentMethodCode 或 paymentMethodRefs。
- 删除固定 InvocationIdentity。每个 API 通过输入合同声明所需 context 字段；权限由可信入口和受控函数适配保证，不能以调用者提供的 JSON 自证权限。
- 同一接入分组可以维护多套公共脚本，由 API 显式引用；共享不意味着所有 API 必须统一算法。
- 每个 API 声明自己需要的数据和输出，通过调用方业务上下文与查询结果满足，不要求调用方预先构造所有渠道字段；不要求本轮对齐统一支付动作或平台资金状态。
- 返回仅包含 executeStatus（SUCCESS/FAIL/ERROR）和 outputs。每个 API 配置状态规则；保护、类型或输出校验失败以及未匹配响应归为 ERROR，不能通过成功规则绕过。ERROR 不证明外部未执行，不授权自动重试。
- outputs 可定义字段、类型、必填性和映射。同类业务的不同接入 API 引用业务 Owner 的共同输出合同；小范围差异使用已声明可选字段，支付与退款可以使用不同合同。
- 不要求通用 channelIdempotencyKey。外部协议需要稳定请求键时，由业务方作为普通 Header/Body 取值输入；执行器不生成、不判重，也不隐式重试目标操作。
- 处理和查询能力由受控实现提供，配置选择能力及参数；允许注册业务查询内部所需的 Owner 调用，不开放任意程序、SQL 或任意 URL。
- 查询结果作为当次命名输出复用，不覆盖调用方已经冻结的金额、币种、OE、Account/MID 和原交易身份；先校验必要上下文与查询入参，补数完成后再校验完整渠道请求。
- 标准 API（用户举例 `authorize`、`sales`、`query`）及其对渠道 API 的流程编排留到后续。此处保留用户举例，不据此建立新枚举或改变现行 `SALE` 等业务术语。
- 普通 Channel 配置不扩大原始卡数据权限；涉及原始卡的片段仍服从 Card 的受控执行边界。
- 用户明确要求暂不考虑版本发布，修改直接生效；保存成功后的新调用读取新配置，进行中的调用使用开始时完整读取的数据，不增设发布操作。

## 4. 本轮不做

- 标准支付 API、标准操作映射、跨渠道接口编排、循环/并行调用、支付状态机、重试补偿及恢复调度；注册的只读补数查询属于本轮逻辑定义。
- 自动 Token 管理、真实账户/密钥接入、真实 NI 或其他渠道调用、Card 原始材料处理实现。
- 回调接入/路由/确认应答/去重的详细设计；它们未来可以复用协议方案，但不混入本轮单次出站 API 模型。
- Operations/执行器应用代码、正式 PDManer/完整 Schema 修改、SQL 执行、配置发布基础设施及部署；页面/管理合同及增量 SQL 草稿属于本阶段设计材料。
- JSON/XML 具体编解码器、签名算法和加密库选型；仅定义可扩展位置及数据契约。

已有[数据清单](./db/README.md)是 Payment 专属前版草稿。移除支付方式后的唯一键、分组关系、Owner 和管理注册需进一步同步，不应用到数据库。通用 execute 是逻辑调用合同，不新增公网任意执行入口，不改写第一方 HTTP 错误规范。

## 5. 评审验收标准

以下为按本次通用化修订后的设计验收项，不是已运行的功能测试。[前期技术稿对照](./technique.md#10-评审对照)与历史验证保留旧版范围；当前调用语义以[通用执行修订](./generic-execution-amendment.md)为准。

| 编号 | 验收内容 |
|---|---|
| CAPI-01 | 以接入分组 → API 组织，不要求支付方式或固定 Payment 身份；不向 Payment 渠道表写入非支付接入方 |
| CAPI-02 | API 有明确数据来源、输出及一次目标渠道传输边界；允许组装查询，不含标准支付 API 或跨渠道 API 执行节点 |
| CAPI-03 | 协议参数与消息结构分开，HTTP 请求头/体及响应状态/头/体均可表达 |
| CAPI-04 | 编解码、签名与加密步骤具备明确输入输出类型、顺序和失败行为 |
| CAPI-05 | 同接入分组的 API 可以共享或分别使用方案/脚本，复用采用显式引用 |
| CAPI-06 | 固定规则、允许的 API 参数、凭据用途和实际认证材料相互区分，引用不依赖隐含继承 |
| CAPI-07 | 返回只含 executeStatus 与 outputs；状态按 API 规则映射，同业务跨渠道遵循共同输出合同，API SUCCESS 不自动等于资金成功 |
| CAPI-08 | 配置、输入、函数、保护、传输、映射失败或无法识别归为 ERROR；没有执行流水/幂等/重试，ERROR 不表示外部未执行 |
| CAPI-09 | 保存 API/方案后新调用直接生效；当次调用内配置完整一致；不引入配置版本或发布流程，数据库落点须显式评审 |
| CAPI-10 | 通过图解、普通用语和具体字段值解释模型，并覆盖不同方案、无加密接口及响应处理差异 |
| CAPI-11 | 支付/退款等业务上下文、运行上下文、查询结果和步骤输出有明确数据来源，提供退款补数示例 |
| CAPI-12 | 数据查询作为注册系统函数使用；配置只绑定函数、入参与返回字段，缺失处理由函数合同负责；先校验入参再调用，同一次返回值复用、不覆盖冻结事实，必需数据获取失败不发送渠道请求 |

| 编号 | 类型 | 验收内容 | 设计入口 |
|---|---|---|---|
| CAPI-13 | 功能设计 | 通用 API/方案/脚本管理、目录、检查、错误与权限可逐操作审阅；前版管理 Wire 待按新 Owner 与分组同步，不开放任意执行入口 | [管理 API](./api.md) |
| CAPI-14 | 数据设计 | API、公共脚本及模型的复用/并发/生效关系明确；Owner 已定为 Platform，分组、唯一键和物理设计补齐后才算完整通过；不建执行记录和发布版本 | [通用执行修订](./generic-execution-amendment.md)、[数据设计](./db/README.md) |
| CAPI-15 | 合同设计 | 上下文路径、Aviator、函数 result 表达式及独立脚本合同明确；脚本仅处理简单逻辑，复杂能力由代码实现；类型/精度/缺失/依赖/身份校验不被绕过；缺实现显式不可用 | [定义合同](./definition-contract.md)、[模型与映射](./model-and-mapping-design.md)、[查询合同](./query-contract.md) |
| CAPI-16 | 视觉/交互设计 | 接口配置、数据模型、公共脚本三个入口；采用技术页签、层级映射及脚本引用/参数编辑，明确各自草稿和保存范围 | [页面设计](./ui.md) |
| CAPI-17 | 模型设计 | 数据模型页支持 OBJECT、ARRAY、MODEL_REF 多层结构；明确子字段、数组元素、必填/null、引用影响和循环检测；模型结构不包含实际调用数据或查询 | [模型与场景设计](./model-library-and-response-scenes.md) |
| CAPI-18 | 合同/交互设计 | 同状态可有多个响应场景，各场景引用不同嵌套输出模型；API 只维护匹配与取值；输入名称生成真实 context 根路径；模型及 API 引用错误可审阅 | [模型与场景设计](./model-library-and-response-scenes.md) |
| CAPI-19 | 脚本/交互设计 | 公共方案并入公共脚本；按阶段读写 HTTP 工作对象，展示系统函数、参数绑定及顺序，保留原始响应验证与最终发送字节约束 | [公共脚本设计](./public-script-http-context-design.md) |

当前 Operations UI 在[现有 Pencil 设计文件](../../../operations-console-web/docs/design.pen)中交付，画板索引见[页面设计](./ui.md)。合成数据与设计状态不代表管理后端或真实渠道执行能力已实现。
