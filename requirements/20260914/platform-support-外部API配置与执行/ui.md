## 1. 布局与入口

沿用现有 Operations 的 PAYTECH 侧栏、运营平台顶栏、白底、蓝色主操作及紧凑表格。实际实现使用现有 Ant Design、usePaging、权限菜单及错误反馈组件。

先选 Channel，再选支付方式，查看所属 API。新建继承当前 Channel 和精确支付方式；进入表单后始终在面包屑显示归属。API 代码和支付方式创建后只读。公共方案在 Channel 下独立维护，各 API 显式引用。

进入已有 API 默认只读；拥有 MANAGE 权限时才显示编辑、新建及删除操作。编辑形成一份本地草稿，区域切换不丢字段。只读详情沿用相同的信息分区，隐藏检查和保存。

编辑器采用五个无编号页签：**接口定义 / 请求映射 / 协议处理 / 响应映射 / 校验**。新建与编辑均可自由切换；工具栏统一放置返回列表、校验和保存，不再使用上一步/下一步向导。保存整份 API 草稿，成功后回到详情，新调用立即使用当前配置。存在未应用的字段编辑时须先应用或取消该局部编辑，不能保存一份遗漏面板改动的草稿；定义不完整或无修改时保存禁用，并定位具体原因。无版本、发布或审批流程。

界面面向接入开发者，使用字段名、类型、规则表格、代码路径和诊断。删除“如何识别接口结果”“调用方需要提供什么”等问答标题与常驻教学卡片；保留输入约束、缺实现、冲突、错误定位及接口限制等影响配置正确性的提示。变量/函数目录是编辑工具，继续保留。界面主体中文命名，协议名、函数名和实际字段路径保留原标识。

## 2. API 编辑内容

| 页签 | 维护内容 |
|---|---|
| 接口定义 | API 标识、Protocol、Method、Endpoint、Path、Timeout |
| 请求映射 | Context、Path/Query/Header/Body 字段绑定、表达式、函数引用 |

| 响应映射 | 响应处理链、条件、结果码、默认结果、分支输出 |

### 2.1 输入上下文

它指调用这个 API 时，调用方能够提供的字段集合。选择退款数据（REFUND）会让字段选择器提供退款金额、币种、原交易引用等候选字段；**不会发起退款，也不代表标准 API 编排中的退款动作**。

该选择放在请求映射页，显示 Context: REFUND / refundContext，并保留类型切换及字段目录入口。输入类型来自开发者注册目录；字段清单只读取元数据，不读取真实交易或遍历任意对象。已有选择更换后须重验全部绑定，不静默丢弃或改写原字段。

本示例使用 refundAmount、currency、originalTransactionRefId 作为合成调用数据的展示字段；实际字段名以选中的注册目录为准。Account/MID、目标域名和访问令牌由可信运行时提供，不属于普通业务字段或页面录入内容。

### 2.2 统一的字段取值面板

点击“添加字段”或行内“编辑”，打开同一个取值面板：**渠道字段 → 发送类型 → 取值方式 → 取值规则 → 必需/null 约束 → 添加/应用**。右侧是当前方式的辅助工具；编辑中不改动参数表，应用成功才加入本地草稿，通过工具栏保存整份 API。初次新增路径及规则为空，发送类型和约束由已知渠道字段合同预填，未知时必须明确填写。现有行编辑时回填完整规则。

取值方式只有三项，三张示例画板是并列分支，不是连续步骤：

| 方式 | 如何配置 | 例子 |
|---|---|---|
| 上下文路径 | 直接输入 xxxContext.abc，或从 JSON 字段目录插入路径 | refundContext.currency |
| 表达式 | 写一个返回目标值的 Aviator 表达式；工具可插入变量、纯函数及参数模板 | money.minorUnits(refundContext.refundAmount, refundContext.currency) |
| 系统函数 | 选择已注册函数、绑定入参；用 result 表达式读取或处理返回值 | READ_REFUND_TARGET → result.orderRef |

不再维护独立的“转换规则”或“转换渠道格式”下拉框。固定值也是表达式，如 `'AED'`、`true` 或 Content-Type 字符串。普通运行字段和前序结果按当前位置的目录显示在可用变量中，不再作为第四、第五种取值方式。保护头仍由认证方案产生。

主参数表统一为“渠道字段 / 取值方式 / 取值规则 / 操作”，直接显示路径、表达式或“调用名 → result.xxx”。长表达式最多展示三行并支持展开；编辑入口常驻，不能被长代码挤走。路径变量自动列为待绑定参数；Body 的 amount.currencyCode 与 amount.value 写入同一 amount 对象。目标路径持久化为字段段数组，带点等特殊字段名使用逐段编辑器；目标路径与来源路径有独立标签，不共用输入框。

#### 上下文路径

以 amount.currencyCode 为例：发送类型选字符串，选择“上下文路径”，输入 `refundContext.currency`。右侧显示当前退款上下文的可搜索字段树，含字段路径、中文含义和类型；点击字段再“插入此路径”，填入左侧。只读目录，不加载真实退款。

输入路径时按已注册字段校验，可展开对象，不支持任意 JSONPath 过滤、通配或函数。上下文类型更换后重验原绑定。直接路径只读取；如果要加工值，切换“表达式”并自动将原路径填入编辑器。已编辑表达式切回路径时，只对可以无损还原为单一路径的表达式自动转换，否则保留原草稿并让用户填新规则，不能静默丢失处理逻辑。

#### Aviator 表达式

以 amount.value 为例：发送类型选整数，在编辑器填写 `money.minorUnits(refundContext.refundAmount, refundContext.currency)`。右侧提供变量目录和允许的纯函数：名称、说明、输入参数、返回类型及插入按钮。编辑器支持补全、括号提示和错误定位，表达式结果直接成为字段值。

money.minorUnits 是项目拟注册的纯函数，不是 Aviator 内置；按币种精度产生精确整数，不靠乘 100 适配所有币种。此处只规定取值设计，不声称函数已实现。界面的 10.00 AED → 1000 明确为固定合成示意，不是试算；不把示例数据保存成运行输入。

“检查表达式”只触发静态检查：语法、字段/函数是否允许、依赖、预算及可以推导的类型。使用现有 A13 候选检查接口，不新增接口；报告定位当前字段，候选中其他未完成字段保留独立提示。浏览器即时提示不能替代服务端最终校验。无法静态确定的类型明确提示“调用时校验”，不能冒充检查通过后的真实结果；检查不执行表达式、系统函数或渠道请求。

#### 添加与失败处理

点“添加到请求体/应用到字段”前检查重复路径、父子结构冲突、未知路径、表达式错误、未绑定的函数入参和不可兼容类型。错误留在对应输入框，草稿不丢失；取消关闭不添加。高级已有定义不能因切换简化视图丢失步骤、引用或处理顺序。

本例发送必需且不允许 null：运行时缺值、表达式异常、函数失败或整数结果越界均停止发送，不补 0、不吞异常。可选字段省略、允许 null、空字符串分别服从定义合同。普通表达式不能绕过目标类型约束；JSON 编码和协议签名仍在“协议处理”维护。

### 2.3 系统函数 + 返回值表达式

用户已明确函数由系统实现和注册。保留函数选择和入参绑定，删除“什么时候查询 / 先检查哪个字段”等查询专用设置，没有查询管理页。

以 Path.orderRef 为例：

1. 选择“系统函数”，选择 READ_REFUND_TARGET，目录展示说明、入参和完整返回 Schema。
2. originalTransactionRefId 绑定为上下文路径 `refundContext.originalTransactionRefId`。入参也可用表达式；需要另一函数的结果时引用明确的前序调用，拒绝循环及前向依赖，不在 Aviator 中隐藏查询。
3. 返回值编辑器初始为 `result`，表示完整返回值。右侧选择 orderRef 并插入，表达式成为 `result.orderRef`；可在此继续写 Aviator 处理，变量和纯函数工具与普通表达式共享。未改动原协议标识的示例保持 result.orderRef。
4. 点击“应用到字段”，记录函数调用引用及该字段自己的结果表达式。若目标是字符串却返回整个对象，提示类型不兼容，不能自动 JSON 字符串化。
5. outletId、paymentRef、captureId 使用同一函数返回时，在系统函数方式中点击“选择已有调用”，选择“原交易信息”，分别编辑 result.outletId 等表达式。显示全部引用字段；修改共享函数/入参影响所有引用，修改当前字段的结果表达式只影响该字段。删除最后一个引用时才允许清理无消费者调用，不能误删其他引用所需步骤。

result 只指向当前选中的一次函数返回，不能因另一个字段选择了函数而被覆盖。相同调用复用一次返回，不同调用不做隐式去重或跨请求缓存。函数内部如何获取数据、处理缺失/null/多条结果由开发者合同负责；表达式只能处理成功返回的数据，不接管查询异常策略。

字段目录和保存检查均不执行函数。NI 的 READ_REFUND_TARGET 仍缺真实实现，页面明确“只有返回合同”，结构有效可以保存但不意味着能发起真实退款。

### 2.4 认证与报文处理保留协议细节

认证、签名、加密分别选择本 API 所用的方案，允许不使用。同 Channel 的不同支付方式可共享或使用不同方案，同方式下不同 API 也可分别选择。

NI 示例为 JSON 编码和 Bearer 认证，未设置签名或加密。处理区显示当前发送顺序；需要“先加密后签名”等协议时展开顺序与作用范围，指定签名覆盖的 Header、Body 或编码后字节。方案选择器过滤当前阶段允许的能力；修改后重验依赖及类型，不按固定的 UI 区域顺序强行决定执行顺序。

响应侧独立维护验签、解密、解析与身份核对顺序。结果规则按顺序匹配，未匹配固定为 UNRECOGNIZED，先分类再检查分支必需输出。示例的 UNRESOLVED 表示无法唯一识别本次退款；它不推进平台支付或退款状态。

### 2.5 结果规则与输出映射

响应映射分为响应处理、结果映射、输出映射三个配置区，不用自然语言句子作为可编辑条件。

- 响应处理展示已登记步骤、Codec、Verify、Decrypt 及处理链编辑入口。JSON 结构、身份和保护校验仍是进入结果映射的前置要求，失败中断；不能把这些要求删掉后仅凭 HTTP 200 判断业务成功。
- 结果表按“序号 / 条件摘要 / 结果码 / 操作”展示，序号来自 rules 数组顺序，不新增持久化 priority 字段。编辑、删除和排序均作用于同一份草稿，首个命中生效。
- 展开规则后用“左值字段 / 操作符 / 右值类型与来源 / 右值”编辑；EQ、NE、EXISTS 与 ALL、ANY、NOT 继续遵守定义合同，EXISTS 隐藏无意义的右值控件，NOT 只有一个子条件。两侧使用现行允许的 ValueBinding，常量输入与来源选择按类型呈现。此次不把条件语言改成 Aviator；表达式投影仍在响应处理链中产生明确输出。
- 默认结果以只读字段显示 UNRECOGNIZED，不能设为成功。NI 图例的 rule 01 为 ALL(response.status EQ INTEGER 200)，响应结构/原身份/投影已由前置处理校验；结果仍为 UNRESOLVED，不增加真实退款成功判定。
- 输出表按 resultCode 切换，展示“输出字段 / 类型 / 必填 / 取值路径 / 操作”。业务字段取自 steps.observedFacts.facts 的已校验投影；Header 仍按协议多值类型处理，图中的 responseContentType 明确为 ARRAY<STRING>。不直接透传原始退款数组。默认分支在此样例为零字段，保留明确分支配置。

以上只把现有 Condition、rules 和 outputDefinition 直接呈现在编辑器，不改变匹配策略、执行事实或结果的业务归属。

## 3. 方案编辑

方案列表显示名称、代码、单能力/步骤组合、引用 API 数量及更新时间。详情展示固定规则、开放给 API 的参数、凭据用途、输入输出及引用清单。组合可展开查看内部步骤。

从认证或响应配置进入方案维护时，返回原 API 保留草稿。编辑共享方案持续显示影响范围；保存时检查同 Channel 直接和间接引用。破坏任一 API 则拒绝整次保存并保留草稿。被引用方案不可删除，服务端再次校验。

本期只引用受控材料的用途，不填写 Token、密钥或算法源码。签名与加密列表中的额外方案明确为配置示例，不表示 NI 的实际要求或已接入算法。

## 4. 核心状态和文案

| 状态 | 页面行为 |
|---|---|
| Channel/支付方式无 API | 空状态及有权限的新建入口，不生成默认 API |
| 只有 READ | 只读详情，无编辑/检查/保存/删除 |
| 无修改或定义不完整 | 保存禁用，并给出具体原因 |
| 配置检查失败 | 校验页签列出错误；点击定位对应页签及字段，行内解释“期望/实际/如何修正”，保留草稿 |
| 字段类型错误示例 | amount.value 需要最小单位整数，却绑定小数金额：定位此行并引导使用返回精确整数的表达式 |
| 结构有效但缺少执行能力 | “定义有效，缺少执行能力：…”；允许保存定义，不表示可交易 |
| 保存成功 | “已保存，新调用立即使用当前配置”，返回只读详情 |
| 并发修改409 | 读取当前内容、核对差异，保留本地草稿，不强制覆盖 |
| 保存请求超时/中断 | “保存结果待确认”；重新读取核对，不自动重试写入 |
| 离开/切换对象存在未保存修改 | 选择继续编辑或放弃；普通步骤切换不弹确认 |
| 依赖权限/服务不可用 | 保留可安全保留的草稿，提供重试，旧数据不冒充已确认当前值 |

管理检查只读定义和注册元数据，不执行 Q1/Q2、不获取访问令牌、不进入 prepare、不发送目标渠道请求。检查通过与真实调用能力分开展示。NI 原目标查询及本次退款关联仍未闭合。

API 与方案的筛选、页码、选择和只读/编辑状态由现有页面模型管理。URL 不放业务上下文、Token 或完整草稿。跨页面离开不把敏感草稿持久化到浏览器存储。

## 6. 界面与配置模型的对应

| 界面操作 | 仍使用的底层合同 |
|---|---|
| 选择调用方数据类型、查看必需输入 | InputDefinition.contextType / requiredPaths |
| 为请求字段设置取值 | ValueBinding 和对象映射 / 传输绑定 |
| 上下文路径读取 | contextName + 字段路径映射为 CONTEXT 等允许的路径绑定 |
| 编写表达式并处理值 | EXPRESSION ValueBinding；纯函数来自 expressionProfile |
| 选择系统函数并使用返回字段 | CALL_SYSTEM_FUNCTION Step + EXPRESSION，以 STEP 绑定 result；无查询专用触发模式 |
| 选择公共方案、安排执行顺序 | SCHEME Step / requestSteps / responseSteps |
| 判断返回结果、选择输出字段 | resultRules、fallback、分支 outputDefinition（ResultOutput[]） |

这是已有逻辑合同的任务导向编辑方式，不增加第二份取值模型。表单与高级步骤必须围绕同一份草稿编辑，保存和再次读取时保留步骤标识、输出引用、类型、保护属性与顺序，不得因为切换简化视图而丢失复杂定义。无法完整展示的高级配置保留明确摘要和编辑入口，不静默重排。底层字段以[定义合同](./definition-contract.md)和[查询合同](./query-contract.md)为准。

## 注册目录对取值工具的约束

首批目录集中见[registry-contract.md](./registry-contract.md)。上下文选择器按字段 Schema 展示稳定的 contextName/path；系统函数按当前 Channel 与 contextType 取交集筛选，已注册但缺执行实现的项可配置并明确显示缺失状态。共享调用以 stepCode 识别，四个字段引用同一个调用只执行一次。

纯函数补全按 argumentOrder 生成位置参数模板，不依赖 JSON 对象字段顺序。字段取值仍只有上下文路径、Aviator、系统函数三种方式，不增加注册管理页、转换选择器或引导步骤。目录更新只改变选项及类型提示；A13 编译检查器不可用时显示明确错误，不把静态检查未完成展示为校验通过。
