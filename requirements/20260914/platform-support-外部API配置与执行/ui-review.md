## 1. 方法与口径

- 在本机 3e 环境（独立库 `mor_platform_external_api`，3e 合成配置）用 1440 宽视口，逐张进入与画板对应的页面状态并截整页。
- 以下状态为对照而构造，只发生在截图脚本的浏览器会话中：空状态新建了一个无实现的接入方 `E3_EMPTY_*`；加载失败、流程校验失败由浏览器拦截返回固定响应；并发冲突由两个标签页先后保存同一版本；删除保护为删除仍被流程引用的原子 API。
- **不比较**：控制台外壳（左侧菜单、顶栏，用户确认保持不动）；示例数据（设计用 NI/PAY/createPayment，实现用 E3_* 与 createOrder/queryOrder）。
- **比较**：内容区的结构、内容（文案、字段、按钮）、样式（字号、等宽字体、颜色、边框）与显示缺陷。

## 6. 逐张偏差

每张只列主要偏差；共性问题按第 4 节编号引用，不重复展开。

### 01 QsmsL 标准 API 列表（小）
- 结构：C1；筛选区设计为“标签在上 + 宽输入框 + 查询（描边）”，实现为行内标签 + 窄输入框 + 主色“查询”+“重置”；“共 N 条”设计在表格下方与分页同行，实现在表格上方并多“刷新”；表格无外框（C3）。
- 内容：缺表格下方说明（已实现接入方跳转、删除保护、保存即生效）；时间格式（C5）；分页形态不同。
- 样式：标题与表头加粗；操作列“···”带边框；接入方链接为 antd 亮蓝。

### 02 aWSB5 标准 API 编辑（中）
- 结构：C1、C2；基本信息设计一行三列不包卡片，实现为卡片 + 多行说明；编辑字段设计为锚定在表格右侧的无遮罩浮层，实现为带遮罩的居中弹窗；多“变更原因”卡片（R2）。
- 内容：字段路径设计只显示末段并缩进，实现缩进后仍是完整路径；类型显示中文（C4）；表格上方层级规则提示被替换为“共 N 个字段”；浮层缺“位置”字段、必填用复选框而非开关、按钮“确 定”而非“应用”；缺表格下方服务端校验说明。
- 缺陷：显示名称列截断；正在编辑的行没有高亮。

### 03 zM5lQ 接入方列表（小）
- 同 01 的筛选区、表格外框、说明、时间与分页差异。
- 列名“脚本”应为“公共脚本”；标准 API 实现列设计为蓝色链接（“、”分隔），实现为灰底标签块，与 01 的链接样式不一致。

### 04 rDRrX 接入方工作区｜基本信息（中）
- 结构：C1；编辑按钮应在页面右上（主色），实现在卡片内并多“删除接入方”；基本信息设计为四列“标签在上、值在下”不包卡片，实现为卡片内纵向列表；白名单说明设计在表格下方灰底框（3 条），实现在表格上方蓝色提示条（1 条）。
- 内容：“最近修改（时间 · 账号）”被“版本 / 更新时间”替代；缺“2 / 16”数量上限；缺行尾“···”操作；表头缺英文名。
- 样式：地址代码与 baseUrl 应为等宽字体。

### 05 B6SIWQ 原子 API 编辑｜接口（中）
- 结构：C1；页签应在卡片外；应为三张独立卡片（基本信息 / HTTP 传输 / 被引用），实现为一张大卡片 + 引用卡片；HTTP 第一行应为 Method（窄）/ 地址代码 / 路径模板（宽），第二行四列（两个超时、请求编码、响应解码），实现为两列栅格且有异常大空白。
- 内容：地址代码下方应显示所选 baseUrl；路径模板应为动态核对“变量 {outletRef} ✓ 已有同名 PATH 字段”；编码提示应列出可选值；缺传输说明框（超时取较小值、不重试、不跟随重定向、不保存 Cookie、Host 等由系统处理）；被引用应为带影响说明的一句话。
- 缺陷：D7。

### 06 ajM1s 原子 API 编辑｜状态规则（中）
- 结构：C7（行内编辑 → 只读行 + 编辑）；“添加规则”应在表格右上；“条件可读取”应为表格下方灰底框；本页签不应出现引用卡片。
- 内容：列名应为“顺序 / 条件（Aviator 布尔表达式）/ 执行状态 / 操作”；固定行序号应为“—”、文案“其他情况（固定，不可编辑）”；可读变量应为通用变量（http.responseStatus / responseHeaders / responseBody / params.*，受控句柄除外）及异常与必填说明；缺“不存在‘HTTP 200 即成功’的默认规则”。
- 样式：执行状态彩色标签；固定行灰底；条件为灰底代码块。

### 07 H8MVL7 公共脚本编辑（大）
- 结构：C1；顶部四个字段应一行排开不包卡片；执行阶段应为“REQUEST | RESPONSE”分段按钮；参数应为灰底小卡片列表 + “+ 添加参数”链接；三栏应按内容自然高度，实现被拉成等高留大片空白；引用应为底部灰底说明条。
- 内容：右栏标题应随阶段变化（“REQUEST 阶段可用”）；对象列表应为“对象 + 读写/只读”紧凑列表（含 http.method / path / query）；注册函数应只列当前阶段可用的签名；字节数应在源码标题右侧；缺签名与参数绑定规则说明。
- 样式：源码区应为深色代码编辑区；函数签名蓝色等宽；“读写”绿色。
- 缺陷：D6。

### 08 D6g5lH 流程编辑（含校验失败）（大）
- 结构：应为铺满内容区的工作台（左 / 画布 / 右通栏分隔 + 底部固定操作栏），实现包在卡片里、整页超出视口；“添加节点”应为左栏组件面板（原子 API 节点、SUCCESS / FAIL / ERROR 出口），实现为画布上方工具栏；校验结果应为底部全宽浅红横幅（“校验结果 · 1 个错误 / 定位”），实现为画布下方白色卡片。
- 内容：标题应为“NI 实现 PAY”、面包屑从“外部 API”开始；预算标签“流程总预算”；初始化卡片应有“必需”徽标、“→ resources.channelAccount”和说明文字；节点卡片应为绿色“请求 6/6 · 参数 1/1 已覆盖”；出口卡片应列出输出字段名；画布下方应有约束说明（不支持环、每节点最多执行一次、只引用本接入方原子 API、不编排冲正）；出错的出口节点应标红框和红字原因。
- 样式：正交连线、出口排右列、标签“1 · SUCCESS”（实现为“1 · 执行状态 SUCCESS”）；初始化编码等宽。
- 缺陷：D4。

## 7. 涉及前端以外的项

- **D1 引用方清单**：Platform 删除被引用对象时以 400 返回引用方说明，但经 BFF 后页面只拿到“业务校验未通过”。需确认 BFF 是否丢弃了 Problem 的 `detail`，或改为结构化返回引用方（会改管理接口合同）。
- **18 冲突横幅的修改人、时间、版本**：当前 409 不带这些信息。可选：页面收到 409 后重新读取详情取得最新版本与修改人（不改接口），或扩展 409 Problem（改合同）。建议前者。

修改后截图在 [assets/ui-review/screens-after](./assets/ui-review/screens-after/)，与 [修改前](./assets/ui-review/screens/) 同一脚本、同一视口；经两轮逐张复核（设计图 / 修改后截图并排）。
