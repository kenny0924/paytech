# 注册密码与邮箱所有权绑定：当前决定与开放前优化

2026-09-15，用户明确：“没事，暂时邮箱密码注册吧。对外开放前会优化。”

当前决定：本期保留 A01 email/password，A03 challengeNo/secret；注册页不改为邮箱单字段，验证页不增加设置或再次输入密码。账号仍先进入 PENDING_VERIFICATION，邮箱验证后才允许密码登录，不自动登录。继续阶段 4 研发，无需就这个选择重复确认。

下文保存发现的问题与后续候选方案，作为对外开放前优化事项，不是当前批准流程。开放前须完成选定的密码归属方案及相应入口测试；本次决定不构成对外开放、部署或数据库执行授权。

## 1. 可复现的问题

1. 他人先用客户的邮箱提交注册，并设置一个自己知道的密码。
2. 客户之后进入待验证页面，重发并打开验证邮件。
3. 如果 A03 只接收 challengeNo/secret 并激活原账号，就可能把对方设置的密码一起激活。

重复注册时覆盖未验证密码只能缓解其中一种路径，不能保护“只重发邮件再验证”的路径。延迟邮件、冷却期间重复注册和并发替换也必须一起考虑，不能把点击邮件当成认可服务器上已有的密码。

## 2. 推荐方案：邮箱注册，验证时设置密码

页面顺序为：注册页填写邮箱 → 受理/重发 → 打开邮箱链接 → 设置并确认密码 → 验证成功 → 邮箱密码登录。

- A01 Register 只接收 email；创建 PENDING_VERIFICATION Account，暂不创建 Password Credential。
- A02 保持只接收 email；60 秒冷却和旧链接失效不变。
- A03 增加 password；必须持有有效邮件秘密才能最终设置密码。浏览器确认密码仅用于表单校验，不重复发送。
- 先在事务外验证链接 HMAC，再授权 Reveal 登录邮箱、校验密码规则并计算 Argon2id。无效秘密不能触发 Reveal。
- 最后在同一本地事务中重新检查准确挑战、账号状态及邮箱归属，单次消费挑战，创建密码凭据，激活账号并记录邮箱验证时间。
- 密码不合规不消费有效链接；链接已消费、到期或被替代均拒绝。并发只能完成一次。
- 已激活账号不被 A01/A02 改写。恢复密码继续使用原 A07/A08 的独立用途和 20 分钟时效。
- A03 不自动登录，不签发工作区会话；完成后进入原邮箱密码登录页。

这样预注册者既不知道客户最终设置的密码，也不能仅凭公开邮箱完成账号激活。无需 OTP、第三方登录、额外页面或数据库列；未验证账号没有密码行属于允许的中间状态。

## 3. 可选方案：保留注册页密码，验证页再确认

A01 保留 email/password。A03 也要求 password，并在激活前验证它与本次未验证注册尝试的密码一致；准备和提交之间同时校验账号/凭据版本，重发不能跳过该验证。已有预注册密码与客户输入不一致时，客户必须重新发起注册并使用对应新链接。

这个方案保留原注册表单，但客户需要再次输入密码，恢复路径也更复杂，因此优先推荐方案 2。
