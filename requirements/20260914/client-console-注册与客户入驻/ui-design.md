人员和关系编辑只在 CCT 允许修改的草稿范围内提供。新增人员不创建登录账号或团队邀请；身份标识的永久归属不能通过编辑抽屉改绑。持股比例例值只演示校验，适用关系目录、必填条件、精确范围/精度和资料更正合同仍由 Owner 定稿；最终提交继续校验必要关系和审核依赖，移除关系不能绕过门禁。

抽屉宽 680—800px，材料预览使用宽弹窗；窄屏展开为全屏，内容区滚动、底部操作固定且不得遮挡字段。打开时聚焦标题/首个字段，焦点限制在当前弹层；保存错误定位具体字段，关闭后回到原入口。只读详情与补件记录仅展示客户有权查看的内容，不出现内部审核理由或下载地址。

## 3. 认证路径

### 邮箱注册与验证

注册页先收邮箱和密码；此时不出现客户名称、组织身份或工作区选择。密码支持粘贴、密码管理器和显示/隐藏；沿用 15—128 个字符的密码规则，前端规则只是即时提示，最终校验由 Platform 执行。字段错误显示在相应字段下，提交错误显示于表单上方。

提交中禁用重复提交，失败保留邮箱、不持久化密码。网络超时先恢复原请求状态，不能自动用新请求创建第二个账号。公开成功反馈不得透露该邮箱是否已有账号。

验证页只显示允许返回的脱敏邮箱。重发倒计时取服务端允许重发时间，画板的“58 秒”为视觉示例，不定义新的限流规则。Challenge 沿用 30 分钟有效期；重发成功后提示使用最新邮件。发送请求被接受不等于已投递到收件箱。

验证成功显示“邮箱已验证”，主操作为“返回登录”；重复消费不重复激活。过期、被替代和无法验证的链接可进入失效提示；若上下文不足以安全重发，先引导登录/重新发起验证，不把浏览器自报账号作为重发权限。Token 只在认证专用处理流程短暂使用，处理完成后移除地址栏中的敏感参数，不写入分析事件、页面日志或浏览器持久存储。

### 登录、密码恢复与 Google

登录失败使用统一提示，不回显账号存在性；需验证邮箱时只提供当前允许的验证引导。锁定和频率限制显示实际重试时间，不让前端倒计时改变服务端门禁。

找回密码始终显示统一请求反馈。密码重置成功后旧会话失效，清空密码字段并回到登录。Google-only 账号遵循现行恢复边界，不能通过找回密码补造一个密码登录入口。

Google 回调成功后走同一登录后路由。同邮箱存在原账号时，进入原账号验证和显式绑定；取消或验证失败不绑定。原账号需要其他已批准重新认证方式时展示相应引导，不能为了复用画板强制所有账号都有密码。回调失败提供重新发起入口，避免自动重定向循环。

注册声明/隐私说明链接的正式内容和版本由相应 Owner 提供；画板没有创造法律条款或接受证据，也不复用 Consumer Checkout 的三项法律接受记录。

## 4. 进入申请与保存草稿

`/start` 聚合当前账号可见申请和可用工作区。没有申请时才展示首次入驻类型选择；有草稿时提供“继续入驻申请”；已提交时进入进度；有多个既有工作区时逐项选择。受限项显示可公开原因，不直接进入业务页面。用户已确认个人/组织合计一份未完成 Client 申请：已有 DRAFT/RETURNED 时只展示继续填写，SUBMITTED/UNDER_REVIEW 展示查看进度，均不提供新建第二份的入口；终态历史与多个已有工作区仍可查看。此为现行交互合同，旧画板按本条迁移。

创建草稿后，资料页显示真实保存状态：未保存、保存中、已保存、保存失败、内容冲突。首期建议采用“保存草稿”和“保存并继续”的显式保存；离开存在未保存内容的页面时给出“继续编辑 / 放弃未保存修改”确认。密码、验证 Token、原始文件内容不得进入表单草稿缓存。

“个人 / 组织”决定资料分支，不把登录账号直接复制成法定代表、UBO 或 Signatory。身份类型创建后不在同一草稿中静默改换；返回类型选择涉及重新开始时先遵守 CCT 当前申请规则。

### 个人与组织的划分

| 对比项 | 个人 INDIVIDUAL | 组织 ORGANIZATION |
|---|---|---|
| 客户主体 | 一个自然人 | 一个企业或其他组织 |
| 基础资料 | 姓名、出生日期、国籍、居住国家与地址；适用身份标识 | 法定名称、注册国家、组织类型、成立日期与地址；适用注册标识 |
| 经营资料 | 业务模式、行业、网站、币种、预计规模/单笔金额、业务联系方式 | 同类字段，按该组织的实际经营填写 |
| 相关人员 | 不展示组织相关人员步骤，也不创建组织关系 | 按适用要求填写相关人员身份及关系；具体角色、比例和有效期由 Owner 合同决定 |
| 材料示例 | 该个人客户的身份材料、居住地址证明 | 组织注册及地址材料、适用相关人员的身份材料 |
| 审核对象 | 该自然人的资料、经营情况及适用检查 | 该组织的资料、经营情况及适用人员/关系检查 |
| 编辑步骤 | 个人资料 → 经营资料 → 申请材料 → 确认提交 | 组织资料 → 经营资料 → 相关人员 → 申请材料 → 确认提交 |

个人版的步骤条、材料对象和提交摘要均独立展示，不残留组织或人员 A 示例。经营资料复用同类字段；注册、保存、上传/扫描、提交冻结、审核进度、补件和激活规则共用。个人步骤较少不意味着免除适用的审核检查。账号只是登录与授权身份，不能因此推断其就是正在入驻的自然人或组织相关人员。

| 步骤 | 编辑内容与来源 | 页面规则 |
|---|---|---|
| 客户资料 | CCT Individual / Organization Profile、Identity Key、Address | 姓名或法定名称、出生/成立日期、国家和地址等；地址行、城市、州省、邮编、国家分别编辑，不合为一个无法校验的自由文本 |
| 经营资料 | CCT Business Profile、经营分类及联系资料 | 业务模式、网站、行业、币种、预计规模/单笔金额、联系邮箱/电话；不提供 OE 或 MID 选择 |
| 相关人员（仅组织流程） | CCT Party Relation 与适用人员资料 | 人员列表中编辑身份、真实关系、适用持股比例和有效区间；添加人员/关系是页内表单。个人流程直接进入申请材料，步骤条不展示此项 |
| 申请材料 | CCT 申请材料要求与 Platform 文件事实 | 展示材料对应对象、说明、原件名称、上传/扫描状态；缺项可定位 |
| 确认提交 | CCT 当前可提交草稿预览 | 展示即将冻结的客户、经营、关系和文件资料，可返回修改；提交后变为只读 |

字段类型、长度、国家/行业目录、必填条件、预计规模统计周期及人员范围必须在后续数据/接口合同中落定。个人稿的两项材料、组织稿的三项材料、示例持股比例和审核清单用于展示排版，不是某司法辖区的法定材料清单，不固定一个全球统一阈值。金额提示随币种和字段合同展示，不能猜测月/年周期。

保存的并发冲突保留当前未提交编辑，并提示刷新权威版本再处理；不静默覆盖其他浏览器中的更新。提交超时显示“正在确认提交结果”，刷新同一申请，不自动新建申请。

## 5. 材料与正式提交

| 状态 | 显示内容 | 允许操作 |
|---|---|---|
| 文件上传权限准备中 | “正在准备材料上传，请稍后重试” | 可继续编辑普通资料；上传禁用 |
| 尚未上传 | 具体材料要求及允许的格式、大小、有效期 | 选择文件 |
| 正在上传 | 文件名、进度、上传失败原因 | 防重复提交同文件；失败后重试 |
| 安全扫描中 | 扫描等待提示 | 可离开后返回；不能提交为有效材料 |
| 扫描通过且可用 | 文件名、可用状态 | 查看；DRAFT 中按授权更换 |
| 扫描失败或不允许使用 | 可公开原因，如不支持类型或文件不可用 | 更换文件；不提供可绕过扫描的下载入口 |
| 已随申请提交 | “原提交材料”及时间 | 仅受控查看，不覆盖或删除冻结记录 |

上传采用现行 Account Context → 唯一 PENDING Tenant/Onboarding Member 解析。浏览器不能提交 Tenant ID 来决定归属；账号有多个候选造成歧义时保持拒绝，直到相应业务决定和合同被批准。

文件格式、大小、扫描规则和可下载性来自 Platform 的有效授权投影，不能仅依赖扩展名或客户端文件状态。提交时 CCT 再次校验材料对象、要求、归属和可用性，前端绿色标签不是提交依据。

提交确认不增加未批准的协议勾选。点击“确认并提交申请”后锁定操作，成功进入原申请进度页；缺项返回准确字段/材料位置。版本冲突展示“资料已更新，请重新核对后提交”。

## 6. 审核进度、补件和工作区

| 页面表达 | 权威事实 | 客户下一步 |
|---|---|---|
| 草稿 | CCT DRAFT | 继续编辑 |
| 已提交，等待进入审核 | CCT SUBMITTED，Risk 登记尚未完成 | 查询同一申请，不能重新提交造新单 |
| 审核中 | CCT UNDER_REVIEW + Risk 当前处理事实 | 查看只读提交，等待结果 |
| 需要补充材料 | Risk WAITING_EVIDENCE / 具体 Requirement | 进入对应要求补件；CCT 不新增补件状态 |
| 补件已收到 | Risk 接受新 Evidence，Requirement 回到相应接收状态 | 查看历史并等待核验 |
| 申请未通过 | CCT/Risk 已确认拒绝结果 | 查看公开原因；仅在 CCT 允许时准备新申请 |
| 正在开通 | 审核通过，CCT 激活或 Platform 投影尚未完成 | 等待/刷新；不能强制进入工作区 |
| 工作区可访问 | Client、Tenant、Account、Member 当前事实均允许 | 创建/切换到当前有效 Tenant Context 后进入 |
| 工作区访问受限 | 来源状态、安全状态或成员权限当前不允许 | 查看允许公开的原因，返回其他可访问项目 |

补件页必须展示对象、要求、客户可见说明、原件（只读）、本次新增材料和可选说明。替换本次尚未提交的文件不覆盖历史 Evidence；提交后保留新旧记录与准确关联。补件改变客户身份/业务 Profile 时，必须走 Owner 确定的新申请路径，不把身份变更塞进文件替换接口。

Risk 的内部命中、筛查细节、理由底稿及敏感数据不进入 Client 进度投影。前端显示已授权的公开说明，不将未知内部错误直接转为客户审核原因。

工作区始终展示当前客户名称和身份。激活不覆盖安全暂停；访问上下文切换失败留在选择页，并重新读取可用项。当前工作区只承诺已批准的资料查看，不展示付款按钮、余额、团队邀请或可收款状态。

## 7. Operations 最小审核

审核列表按当前读取权限展示案件，查询条件为客户/申请编号、客户类型和处理状态；无权限不展示操作入口。列表空状态和查询失败分别展示，不把后端错误解释为“没有案件”。

详情按原始申请、后续补件、核验记录、结论分区。原件与替代证据分列，明确材料对象和历史时间。受控材料查看需要当前权限和文件授权，不能把存储地址或 Vault 引用直接交给页面。

核验记录编辑需选具体 Requirement/Check、形成处理结果并附必要理由/证据。截图的 2/3 是示例；批准可用性来自 Risk 的完整门禁结果，包括必需材料、检查、筛查和相关人依赖。不能用客户端计算的“已勾选全部”代替资格判定。

补件确认分开填写客户可见要求与内部记录。结论确认再次展示客户、申请和送审资料，选择批准或拒绝，填写理由并明确公开说明；只有当前合法决定才能提交。并发更新、权限变化或门禁不满足时留在确认上下文并展示原因，不静默覆盖。确认面板展示的是正常可提交示例，缺少真实必要核验时仍应保持不可批准。

Operations 只形成 Risk 审核决定，不直接修改 CCT Client 或 Platform Tenant。提交超时通过原命令恢复/读取案件确认结果；不能让操作者盲目新发另一结论。

## 8. BFF 页面数据职责

## 9. 样式与验收

品牌、蓝色与字体沿用现有 Operations 的 PAYTECH / `#315ACB` / Noto Sans SC。按用户“左侧这个太丑了，页面简约点”的反馈，Client 01—07 认证页统一采用纯白底与 400px 居中表单，移除左侧大色块、宣传标题和入驻步骤说明。品牌缩小为 16px，表单标题 26px，标题与简短说明居中，字段保持左对齐，输入框和按钮高 44px，不增加包围表单的装饰卡片。手机注册稿 22 同步采用该视觉层次。
