## 1. 本期流程

邮箱注册 → 邮件链接验证 → 邮箱密码登录 → 选择个人/组织 → 单页填写并保存草稿 → 核对提交 → 人工审核 → 通过后开通工作区。

审核分为三个出口：批准；退回修改原申请；最终拒绝并结束申请。退回后再次提交创建新审核任务，申请编号不变。行业与 MCC 由运营分别选择并确认，作为最终批准的前置条件。个人没有组织人员区；组织人员及关系在当前表单抽屉维护。

## 2. 接口与数据

- [数据设计](./data-design.md)：逐表差异、不完整草稿、稳定身份、运营分类事实、共享读取迁移和 SQL 使用范围。
- [字段投影](./db/target-field-projection.json)：源模型 Hash、原字段、目标字段、索引和逐项变更。它是评审工件，不能替代现行 PDManer。
- [注册设计](./registration-design.md)：37 条公共路由、5 项运营权限、1 个运营菜单与 4 个按钮；48 个 Owner 管理命令模板，初始入口禁用。Client 入驻前使用固定页面入口，不创建无权限菜单。

- [研发与验证计划](./implementation-plan.md)：按 Owner 和依赖顺序实施，明确状态、权限、恢复和 UI 验收。

### 3.1 登录错误反馈补充（2026-09-16）

本次用户要求聚焦登录页反馈：邮箱格式/必填错误标红对应输入框，中文提示放在字段下方；每个字段预留 26px（含 6px 间距）的提示区域，正常态和错误态保持相同布局。提交时校验并聚焦首个错误字段；编辑对应字段后清除旧提示。邮箱或密码错误时两框标红，在密码下方统一提示“邮箱或密码不正确，请重新输入”，不区分账号是否存在。网络、限流及服务不可用使用简短中文说明，不把凭据标为错误，不展示请求编号或后端诊断文字，不使用浏览器原生验证气泡或插入大块错误卡片。

原设计文件的 S01 同步使用预留提示区域；S01a、S01b、S01c 分别描述邮箱格式错误、凭据错误、390px 错误态。注册、入驻及真实认证联调不随本次视觉修正扩展。

### 3.2 公共文本输入组件补充（2026-09-16）

用户后续指出找回密码仍使用原生气泡，要求文本框通用。本次将上节的提示方式扩展到登录、注册、找回密码、重发验证邮件与设置新密码。它们统一使用 `TextField`：标签、输入框、可选密码显示按钮、26px 提示区域及 ARIA 关联属于公共组件；字段规则、服务器错误归属及提交动作属于各页面。辅助说明、字段错误和操作反馈共用预留区域；修改输入清除对应旧错误；确认密码错误随新密码修改一并清除。聚焦可见的错误字段不滚动页面，仅在字段超出视口时滚动到该字段。

UI 稿使用同一个可复用“公共组件 · TextField 文本输入”（`kAoAn`）；S01/S01a/S01b/S01c、S04 注册、04 找回密码与 05 设置新密码引用该组件，并补充 04a 找回密码错误态。本次不扩展邮件服务或入驻业务；原登录局部修正的页面范围由本节扩展。

## 4. 申请数量与恢复规则

用户确认“一份”：同一 CUSTOMER Account 的个人与组织 Client 入驻合计最多一份未完成申请，不是每种类型各一份，也不是最多一个 Client 或工作区。DRAFT、SUBMITTED、UNDER_REVIEW、RETURNED 均占用名额；APPROVED、REJECTED 以及已有合法 WITHDRAWN 终态释放名额。首期不因保留 WITHDRAWN 状态新增自助撤回功能。

有 DRAFT/RETURNED 时恢复原表单，有 SUBMITTED/UNDER_REVIEW 时进入原申请进度，不创建第二份。申请类型创建后不变；携带另一类型调用创建接口时返回明确冲突并提示继续原申请，不能清空资料或自动切换类型。最终通过或拒绝后可按既有身份/资格规则发起下一份申请；旧终态不复活。工作区尚在开通时仍显示真实等待状态，不据批准状态伪造可用工作区。

数据唯一性由 CCT 的 `UNIQUE(requested_by_account_id, active_slot)` 保护；进行中 slot=1，终态为 NULL，申请发起账号必填。上传要求指定当前 applicationId 作为操作目标，服务端核对归属、可编辑状态及对应 Client，再由 Platform 解析唯一合法入驻 Tenant。浏览器不能指定 Tenant；历史投影残留造成零个、多个或目标不匹配时拒绝并等待恢复，不挑第一条。精确处理见[数据设计](./data-design.md#2-草稿身份与字段映射)及[API 合同](./api-contract.md#5-保存重提与一致性)。

该限制只覆盖本期 Client 入驻，不修改 Partner 的申请数量规则，也不限制账号按真实 Member 进入多个已有工作区。

新注册账号没有 Tenant，认证邮件必须使用 Platform 自身认证投递能力，不借用客户 Tenant。详细投递行为见数据设计。真实邮件通道、文件扫描策略和发布实例在阶段 6 绑定；权限/资源 ID 由现有管理接口生成，不再等待预设 ID。非空环境须先完成该环境历史迁移证据才允许启用，不阻止按目标模型研发。
