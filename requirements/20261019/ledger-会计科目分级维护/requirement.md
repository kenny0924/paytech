# ledger 会计科目分级与维护

状态：**阶段 1 已确认（2026-10-19）；2026-10-20 已部署 mor-test，已本地提交（未推送）**。确认记录见 [delivery.md](./delivery.md)。

## 1. 背景

用户对照常见财务系统指出：会计科目应分级，并按正常财务系统的方式维护。

现状（2026-10-19 核对 mor-test 与代码）：

- 表结构已预留层级：`t_chart_account.parent_account_id`（上级科目）、`posting_allowed`（是否末级可记账）；[FINANCE_DATABASE.md](../../../agent-docs/database/FINANCE_DATABASE.md) 已规定父子同表、不成环、父科目不可记账、科目表被账簿采用后既有结构冻结。
- 实际数据是平铺的：STANDARD 科目表 29 个科目全部 `parent_account_id = NULL`、`posting_allowed = 1`，只按资产 / 负债 / 权益 / 收入 / 费用五类区分。
- 代码只使用 `posting_allowed` 做记账校验；上级科目字段没有任何查询、汇总、试算平衡或页面用到。
- 没有科目维护接口，科目只能由初始化 SQL 写入；Operations「账务基础资料 → 科目表与币种」页签只读、平铺展示。
- 科目代码是英文语义编码（如 `CLIENT_PAYABLE`），被 ledger 记账规则、account 明细账账户类型、reconciliation、Operations BFF / Web 共同引用，没有财务意义上的数字科目编号。

## 2. 目标

1. 科目按级次组织成树：一级科目按会计要素分类，下设汇总科目，末级科目才能记账。
2. 每个科目有财务人员使用的分级数字编号，可从编号看出层级与归属。
3. 财务人员在 Operations 控制台维护科目（新增、修改、调整层级、停用），不再依赖 SQL。
4. 科目余额和试算平衡能按级次汇总查看。
5. 现有系统代码（`CLIENT_PAYABLE` 等）保持不变，记账规则、account、reconciliation 与已有事件不受编号引入影响。
6. 每个 ledger 账户与 account 明细账账户都有财务人员可读的账户号，可在控制台显示与搜索。

## 3. 使用者与场景

| 使用者 | 场景 | 成功结果 |
|---|---|---|
| 财务 | 新增一个汇总科目或末级科目，指定上级、编号、名称、类别 | 立即在科目树中出现，变更记录留痕 |
| 财务 | 在科目表尚未被账簿采用时调整科目的上级或编号 | 生效后树结构变化，校验不成环、父科目不可记账 |
| 财务 | 停用一个不再使用的末级科目 | 新账户、新规则不能再引用它；历史分录照常查询 |
| 财务 / 审计 | 查看某账簿某期间的科目余额表 / 试算平衡 | 按级次展开或折叠，父科目金额等于下级合计 |

## 4. 本期范围（草案）

- **R1 科目编号与级次：** 每个科目新增分级数字编号，按 IFRS 五类：一级首位 1 资产 / 2 负债 / 3 权益 / 4 收入 / 5 费用，级次 4-2-2-2（一级 4 位，下级各加 2 位，最多 4 级）。编号唯一，下级编号以上级编号为前缀。系统代码 `account_code` 保留为程序引用的稳定键。
- **R2 标准科目表重建：** 把 STANDARD 的 29 个现有科目作为末级科目挂到新的一级 / 二级汇总科目下，形成完整科目树；系统代码、类别、余额方向不变。
- **R3 科目维护：** ledger 提供科目新增、修改名称、调整上级与编号（仅限科目表未被账簿采用时）、停用 / 启用；科目表被采用后只能追加科目、改名称、停用。
- **R4 生效与留痕：** 科目变更不走审批，有维护权限即直接生效；每次变更记录操作人、时间与变更前后内容，可在控制台查看。
- **R5 控制台：** Operations「科目表与币种」页签改为科目树展示，支持维护操作与变更记录查看；建账户、选科目处按编号 + 名称显示。
- **R6 级次汇总查询：** 账簿科目余额与试算平衡都按级次汇总，父科目金额等于下级合计，控制台可展开 / 折叠。
- **R8 可读账户号：** ledger 账户（`t_ledger_account`）与 account 明细账账户（`t_owner_account`）在创建时生成一个可读账户号，由主体、币种、科目编号、Owner 与余额桶组成，格式在阶段 3 设计。账户号创建后不再改变、全局唯一，只用于显示与搜索；程序之间仍以账户 ID 与现有唯一身份关联，不进入事件载荷与关联键。控制台账本查询、明细账查询、余额查询与分录详情显示账户号，并可按账户号搜索。
- **R7 测试环境数据：** mor-test 现有 AE001 演示财务数据（日历、期间、账簿、8 条计费事实及下游记账）在发布时清理，按新科目表重建演示数据。用户已于 2026-10-19 同意清理。

## 5. 不做项

- 不修改既有系统代码，不改 ledger 记账规则行、account 账户类型、reconciliation 和 `AccountPosted` 等事件载荷。
- 不做辅助核算（客户、项目、部门等维度）；按 Owner 区分的明细继续由 ledger 账户和 account 明细账承担。
- 可读账户号不作为对外账户号：不用于 Client 充值虚拟账户、银行流水匹配或任何对外合同。
- 不做多套科目表之间的映射，也不做对外法定报表（资产负债表、利润表）的格式化输出。
- 不做科目表版本化与按期间切换科目表。
- 不改动 billing 计费事实重构需求（同日另一需求）的范围。

## 6. 验收标准（草案）

| 编号 | 验收标准 |
|---|---|
| AC-01 | 每个科目都有唯一的分级编号；下级编号以上级编号为前缀、位数符合级次规则；违反时接口拒绝并给出中文原因 |
| AC-02 | STANDARD 科目表为完整树：每个末级科目都有上级，一级科目覆盖五类会计要素；29 个现有系统代码、类别、余额方向不变 |
| AC-03 | 父科目 `posting_allowed = 0`；向父科目建账户、配置规则或记账均被拒绝 |
| AC-04 | 科目表未被采用时可调整上级与编号；成环、跨科目表、父科目可记账、类别与上级不一致时拒绝 |
| AC-05 | 科目表被采用后，修改既有科目的编号、上级、类别、余额方向、可记账属性被拒绝；追加科目、改名称、停用允许 |
| AC-06 | 停用的科目不能新建账户、不能被新规则引用；已有账户与历史分录照常查询 |
| AC-07 | 有维护权限的操作人提交科目变更后直接生效；无维护权限被拒绝；每次变更可查到操作人、时间与变更前后内容 |
| AC-08 | 科目余额表 / 试算平衡按级次汇总，任一父科目的借、贷、余额等于其直接下级合计，一级科目合计借贷平衡 |
| AC-09 | 已有的记账链路（billing → account → ledger）在新科目表下全部通过原有验收 |
| AC-10 | mor-test 旧演示数据清理后，按新科目表重建的演示数据可在控制台按科目树查看 |
| AC-11 | 新建的 ledger 账户与 account 明细账账户都有可读账户号：格式符合阶段 3 规则、全局唯一、创建后不变；控制台各账户列表与分录详情显示账户号，按账户号可精确搜到该账户；事件载荷与跨系统关联不使用账户号 |

页面验收（阶段 3 出原型后细化）：

- **功能：** 科目树展开 / 折叠、按编号或名称搜索、新增 / 编辑 / 停用 / 启用、变更记录、错误在字段下就地提示。
- **视觉 / 交互：** 沿用现有财务页面样式；树中区分汇总科目与末级科目、停用科目；空状态与无权限状态有明确提示。

## 7. 已确认决定（2026-10-19）

| 编号 | 问题 | 决定 |
|---|---|---|
| Q1 | 编号体系 | IFRS 五类（1 资产 / 2 负债 / 3 权益 / 4 收入 / 5 费用），4-2-2-2，最多 4 级 |
| Q2 | 科目变更是否审批 | 不审批，直接生效；保留变更记录 |
| Q3 | 级次汇总范围 | 账簿科目余额与试算平衡都做，控制台展示 |
| Q4 | 科目停用 | 需要，科目增加启停状态 |

## 8. 适用阶段

八个阶段全部适用：涉及 ledger 模型与 SQL、接口、Operations BFF / Web、Platform 路由注册与 mor-test 数据清理重建。
