> 的待迁移现状；完成 [Vault 消费者对齐](../../../docs/superpowers/plans/2026-09-05-vault-consumer-model-alignment.md)

## 3. 支付成功与入账、Channel 清算与银行到账

交易成功先借记 `CHANNEL_UNSETTLED_RECEIVABLE`、贷记交易负债并确认预计 Channel Cost；预计 Channel Cost 的分录借记 `CHANNEL_FEE_EXPENSE`、贷记 `CHANNEL_FEE_ACCRUAL`，后续不得重复。只有交易对账完整的最终 Settlement/Remittance Batch 才把未结项重分类到 `CHANNEL_SETTLEMENT_RECEIVABLE`；`VALIDATED` 单独不能触发重分类。多条 Transaction Match 汇聚到一个批次，只生成一个批次 Journal。正向 Batch Entry 32240 借 20208/103 与 20209(CHANNEL_FEE_ACCRUAL)/2、贷 20201(CHANNEL_UNSETTLED_RECEIVABLE)/105。随后只有 CONFIRMED Bank Statement Match 才借记 `BANK_CASH`、贷记结算应收。

负向权威事实先贷记 `CHANNEL_UNSETTLED_PAYABLE`；交易对账完整后转到 `CHANNEL_SETTLEMENT_PAYABLE`，Bank Statement Item 的 Debit Match CONFIRMED 后才贷记 `BANK_CASH`。Preliminary Transaction Report 不能成为最终批次；PROPOSED/REJECTED Bank Match 不过账，cash settlement policy 为 NONE 时禁止 Channel Bank Match。任何差异进入 `CHANNEL_SETTLEMENT_MISMATCH`。

第一层：Channel 交易对账。Channel Transaction Match 使用 Finance 本地冻结引用匹配 open/debit item，无需在线查询 Payment；未知外部流水进入异常。VALIDATED 只表示报表语法和来源通过，交易对账完整还要求 FEE/ADJUSTMENT 与 Cost Confirm 全部闭合。第二层：银行现金对账。Channel Batch 本身就是银行对账目标，CONFIRMED 后才改变 Bank Cash。Channel T+2 仅表示 Channel 资金时间，独立于 Owner 成熟周期，不能被解释为 Partner 的另一个到期规则。

实际成本 5、预计成本 2：借记 `CHANNEL_FEE_EXPENSE`、贷记 `CHANNEL_FEE_ACCRUAL`，差额形成 CHANNEL_COST_INCREASE。实际成本 1、预计成本 2：借记 `CHANNEL_FEE_ACCRUAL`、贷记 `CHANNEL_FEE_EXPENSE`，差额形成 CHANNEL_COST_DECREASE。实际成本等于预计成本时不创建 COST_ADJUSTMENT。

## 7. Platform Service Charge 双账

Partner OE 计算好的 `PLATFORM_SERVICE_CHARGE` 为 USD 0.40（交易示例 USD 100.00）。Partner 账使用 `PLATFORM_SERVICE_CHARGE_PARTNER`：Dr PLATFORM_SERVICE_FEE_EXPENSE / Cr PLATFORM_SERVICE_PAYABLE；Platform Finance Entity 账使用 `PLATFORM_SERVICE_CHARGE_PLATFORM`：Dr PLATFORM_SERVICE_RECEIVABLE / Cr PLATFORM_SERVICE_REVENUE。两条 Journal 各自平衡并在同一 Finance 本地事务 commit once；锁顺序固定为 `ledger_book.id ASC`、`account.id ASC`，任一失败全部回滚。

Finance Entity 不存在、重复或 CLOSED，或 Platform Service Party 不一致时 Fail-Closed。相同 Event Key + 相同 Payload 幂等返回；相同 Key + 不同金额或主体拒绝。非 Partner 来源不生成平台服务费。Refund 沿 parent_economics_id + component link 反向冲销。Accounting Rule 只读取已计算的 PLATFORM_SERVICE_CHARGE Component Amount。两本账分别执行 Trial、Close 和 Profit Carry Forward。
