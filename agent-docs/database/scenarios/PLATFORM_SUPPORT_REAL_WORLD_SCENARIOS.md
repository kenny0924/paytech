## 1. 固定参与方与边界

- Account 是全局登录身份；Operations 使用 `OPERATIONS` Realm，Client/Partner 共用 `CUSTOMER` Realm。
- Operations 仅允许 Email + Password；除一次性 Bootstrap Admin 外，所有 Operations 人工账号都由已授权管理员创建。
- Client/Partner 支持 Email 注册、Password 登录与 Google 授权登录；Google 的 Code/PKCE/state/nonce 和密封 Pending Binding Proof 只在协议层短暂存在，不落业务表，Email 相同也不自动绑定。
- Client/Partner 权限来自独立 Tenant Member 关系；一个 Account 可同时属于多个 Client/Partner Tenant，一个 Access Token 只绑定一个当前 Tenant。
- Platform MySQL 保存全局公共 Route、受控 Target、Route Guard 参数与 Console Resource 的当前权威状态，但不保存 Snapshot、Release、Runtime Counter 或 Tenant Override。当前 Gateway 运行时仍使用已加固的静态 Catalog；动态 Snapshot 切换是后续实现。
- 文档、通知、Webhook 的 Tenant 归属统一使用 `tenant_id`。跨系统引用只保存稳定 ID/事件键，不建立跨数据库 Foreign Key。

### 2.2 登录、Token 与 Readiness 判定

- Cookie 固定为 `__Secure-operations-refresh`，Path 为 `/api/operations/auth/v1`；Client 使用 `__Secure-client-refresh`，Path 为 `/api/client/auth/v1`；Partner 使用 `__Secure-partner-refresh`，Path 为 `/api/partner/auth/v1`。
- Account Context 的 `tenant_id/tenant_type/tenant_member_id` Claims 全为空；Tenant Context 三者全有值且 Channel 与 Tenant Type 一致。一个 Access Token 只绑定一个当前 Tenant。
- PLT-I03 只校验 ACTIVE CLIENT Tenant 的 Credential，并返回 `tenant_id + tenant_type=CLIENT + owner_ref_id + credential_id + effective scopes`；`owner_ref_id` 来自已验证 Access Tenant，不从 Key Prefix 或客户端参数推断。
- PLT-I13 只派生 CLIENT Readiness：同一查询快照内缺少必需 Credential/Scope/Webhook 事实返回 `NOT_READY`，Owner/Security 限制返回 `RESTRICTED`；歧义、不一致、查询超时或数据库错误返回技术依赖失败且不返回业务状态。全部非 READY/技术失败均 Fail-Closed，不保存 Evaluation、Version、Reason Set 或证据快照。
- 当前已部署 Gateway 仍只按静态 Route/Guard 事实执行；后续动态版本从 Platform 拉取完整不可变 Snapshot。Operations Guard 在 Redis 使用 raw canonical socket IP 与 exact validated JWT `sub`，没有 Redis HMAC；Access Log 才使用独立 HMAC。公共 Guard 行保存全局参数，不保存 Redis Runtime Counter，也不保存 Tenant 配额覆盖。

## 3. SCN-PLT-02：文件显式重扫、双输入 Consumer Document 与 Credit Note 更正

### 7.2 运行时关系与失败关闭

- Human 授权链为 `t_gateway_route.permission_id -> t_permission <- t_role_permission <- t_role <- t_tenant_member_role <- t_tenant_member`。示例中的 Operations Route `720001`、Menu `730001` 和 Button `730002` 分别独立引用 Permission `230102`；Partner Route `720003` 使用 `HUMAN_PERMISSION` 并由 Partner BFF 调 PLT-I02，以当前 Gulf Member `220912`、Tenant `210002` 和 Permission `230103` 做 Fail-Closed 决策。Console Resource 不引用 Route，Route 也不引用 Console Resource。
- `t_role.scope_key` 是由 `tenant_scope + tenant_id` 派生的复合 FK 隔离键，不是调用方提交的业务 Scope String。Client API 的 `t_gateway_route.required_scope_code=orders.write` 则与 PLT-I03 返回的当前 Effective `t_api_credential_scope.scope_code=orders.write` 做语义匹配，不建立全局 Route 到 Tenant Credential Grant 的 FK。
- Guard 行只保存全局 Route 参数；`TENANT` Dimension 在认证后把 trusted `tenant_id` 加入 Redis Key，它不是 Guard 行的 Foreign Key，也不允许 Tenant 覆盖数据库参数。
- Target 的 `target_service_code + discovery_service_name + channel` 必须再由 Gateway 静态 Approved Target Registry 双重校验，数据库不能配置 Host、URI、Port 或任意服务。
- DISABLED Target `710007` 下的 ACTIVE Route `720007` 保留管理事实，但下一份 Snapshot 必须把 Target 和全部子 Route 一并排除；重新启用时要重新校验完整全局 Catalog。
- Gateway 调 Platform Snapshot/PLT-I03 是受信任内部控制链路；BFF 到核心系统、核心系统互调以及 MQ/XXL-Job/Vault 调用不创建公共 Route，也不消耗公共 Guard Bucket。

## 9. 失败关闭与最小数据清单

- 不保存 Password 明文、Google authorization code、Access/Refresh/ID Token、OIDC client secret、KMS private key、Webhook signing secret 值、PAN 或 CVV。
