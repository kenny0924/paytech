## 1. 确认来源与边界

用户确认本期只完成规则配置，规则决策及真实执行不在当前需求范围；要求在原 V1 上调整。用户进一步确认冷却主体应动态选择、标签采用主体标签设计、标签代码手工输入，以及拒绝原因和文案暂时手工输入，未来再建设 Risk 拒绝原因字典。

本期包含规则编辑、条件与条件组、排序、启用、终态决定选项、可选非终态附加动作、不可变配置保存、详情回显与配置合法性校验。保留既有 Freeze、TEST Candidate 的兼容和回归责任，但不新增决策流编排、运行评估、真实冷却、实际打标签、标签查询、规则读取标签、Shadow、审批、激活或生产生效。

决策选项是规则配置内容，保存该选项不执行决策。保存附加动作参数不产生 Action Intent/Effect、Restriction、主体标签事实、MQ 或补偿任务。本决定不授权部署或扩大其他核心系统的运行接口；SQL 应用需明确环境授权，执行证据只在当前状态台账记录。

## 2. V1 增量

- 沿用现有 Operations 页面和 V1 管理路径，不另建 V2 页面、V2 路由或两套业务版本流。
- 现有 Rule Set 的不可变业务版本机制继续有效；V1 指接口演进方向，不表示可以覆盖已保存的业务版本。
- 列表收起、选中编辑与字段控件调整复用当前条件 AST。历史 NOT、比较方向、Decimal、非拒绝 reasonCode 和变更原因必须无损。
- PASS/REVIEW/REJECT 是展示名称；Risk 的 ALLOW/REVIEW/DENY 语义不变。CHECKOUT_PREPARE 的 REVIEW 不新增审批后恢复原创建请求的流程。
- 一条规则最多一个终态决定。可以选择不产生决定并配置附加动作；无终态且无附加动作的空操作规则不开放。
- FIRST_TERMINAL、默认 REVIEW、技术失败不伪造业务决定等既有语义继续有效，本期不实现执行器。

## 3. 动态主体绑定

主体配置分为工程能力定义与运营规则选择两层。Risk 拥有主体类型、输入字段映射、参数资格与适用决策点；Operations 从 Risk 返回的目录动态选择作用主体，Web/BFF 不写死只允许 Consumer/Client，也不允许运营随意注册没有输入语义的主体类型。

规则保存“当前请求对应主体”的绑定定义及动作参数，不保存某个实际 Client/Consumer ID、Vault Token、IP 或任意字符串模板。Consumer 身份使用 Client 命名空间及合法的不透明消费者引用，不能跨 Client 混同。

Consumer/Client 是当前主要使用方向，不表示每个决策点都可以选择它们。只有当前决策点的批准输入能提供所需字段，绑定才可进入 Authoring Context；缺失或不支持时拒绝配置。CHECKOUT_PREPARE 发生在消费者交互之前，不能为填充下拉框而伪造 Consumer 字段或引入新的决策点。实际可开放的绑定、版本和字段映射以接口合同为准。

冷却动作配置目标绑定和正持续时长；保存规范使用毫秒字符串，页面可提供分钟等单位。允许时长范围由 Risk 的动作参数定义控制。相同目标的冷却截止时间取 MAX 是既有未来执行语义，不在配置保存时更新冷却事实。

## 4. 主体标签

ADD_RISK_TAG 表示给指定主体添加分类标签，不表示本次请求临时标签。目标复用动态主体绑定，标签使用规范的稳定代码集合，首期手工录入。展示示例 REQUIRES_ATTENTION 不是必须预置的目录项。

- 标签本身不自动拒绝、冷却或改变资格；这些行为由独立规则/动作表达。
- 相同目标上的相同标签去重，多个标签取 UNION；不能按标签文字推断其他动作。
- 本期仅保存配置。主体标签关系、实际赋值、查询、有效期、解除及后续规则消费属于未来独立执行设计。
- 本期不建设标签字典表、标签管理页面或主体标签运行表，也不把标签静默改造成黑名单成员。
- 标签代码不包含个人数据、凭据或自由消息；精确长度、大小写、数量和重复处理在接口合同中统一定义。

## 5. 手工拒绝原因与文案

新拒绝规则手工填写 reasonCode 和 reasonMessage，二者完整必填；保留 reasonCode 的代码含义，不以消息代替操作级 changeReason。非拒绝规则的既有 reasonCode 不能因本次调整被静默清空。

本期不查询拒绝字典，不预置原因目录，不提供默认消息或恢复默认入口，不新增拒绝字典表/API/DML。reasonMessage 随规则不可变版本保存，历史记录不补造消息。消息用于内部说明，对外提示仍由消费接口的独立合同映射。

未来引入 Risk 拒绝原因字典时，改变新配置的选取方式；旧规则仍以当时保存的代码和消息为准，不重新绑定当前目录或重算旧 Hash。

## 6. 配置与执行就绪

配置校验覆盖结构、字段引用、主体绑定、动作/参数类型、值域、终态数量与保存一致性。它不证明运行 Handler、正式 Release 或副作用执行已存在。

现有 HANDLER_HASH 及 Freeze/Candidate 对工程注册能力的检查不得通过占位 Handler、虚构实现 Hash 或无条件通过来规避。本期配置目录使用 CONFIGURATION_ONLY，含附加动作的版本阻断 Freeze；缺少执行证据时明确失败关闭，不能借本期范围新增执行器，也不能将配置保存成功展示为可发布/可执行。
