## 1. 确认来源

用户已认可条件连线页面方向，选择前端 React Flow 和 Risk 自定义轻量后端执行器的选型方向；明确本期“先做配置管理：编辑、保存校验、历史查看；真实执行下一期”。在完整需求稿及“仅判断”规则调整被交付后，用户回复“继续”，确认阶段 1 并进入现状差异与影响分析。用户随后明确要求简化规则处理方式，并确认统一条件必填、动作可选；该确认用于本轮设计修订，未确认进入研发。完整记录见 [delivery.md](../../requirements/20260912/operations-console-决策流配置/delivery.md)。

## 2. 本期决定

业务范围与 14 项验收标准以 [requirement.md](../../requirements/20260912/operations-console-决策流配置/requirement.md) 为准：

- 独立决策流配置列表、新建编辑、准确规则集版本引用、静态校验、不可变版本保存、详情/历史只读和整体删除；同一决策点允许多条配置，不据此选择运行生效流。
- 开始、规则集、结束三类节点；条件配置在线上，按明确顺序选择首个匹配出口，正常均未命中才走其他情况；可在业务节点后直接结束，不引入并行、循环或任意脚本。
- 条件来源是当前决策点已开放输入和本节点是否命中；“命中”表示至少一条启用规则满足条件，不伪造实际运行结果。
- 规则统一为匹配条件必填、命中后的动作可选。取消“仅判断 / 配置决定或附加动作”模式切换，不新增规则类型或模式字段；未配置动作时提供命中结果供流程连线分流。原有 ALLOW/REVIEW/DENY 仍终止整个流程，技术失败不产生伪造业务决定，系统义务不可绕过。
- 只保存结构完整的配置；准确 DRAFT/FROZEN 引用不表示执行就绪，退休/删除后的历史展示与新引用资格须保持区别。
- 沿用既有接口版本或默认 v1，代码类型名不带 V1/V2；不为画布升级接口版本或修改历史内容。

保存和静态校验不执行真实决策、不产生冷却/标签事实，不交付试运行、运行轨迹、业务调用接入、发布激活或后端执行器。后端自定义只是已选方向，下一期再做运行合同与实现。

## 3. 取代与交付边界

本决定批准配置目标变化，不表示现有 Validator、前端或数据库已经支持。合法空动作的精确请求表示、格式识别、旧 Hash/回放兼容及冻结保护见阶段 3 设计；不得将损坏旧记录自动解释为合法空动作，或放宽旧 Candidate 检查来宣称执行就绪。

流程配置引用本身不改变 RCO-15 的规则集“当前 ACTIVE Release 才算使用中”定义。既有规则集、字典与发布历史继续保留；新流程是否影响其他查询及具体模型数量，由 [阶段 2 分析](../../requirements/20260912/operations-console-决策流配置/technique.md)交付审阅后进入设计。

本需求按八阶段逐步确认。用户确认阶段 2 后已进入阶段 3，明确本期仅 CHECKOUT_PREPARE，并补齐原因引用的流程结束来源；当前设计包待确认，不授权应用研发、SQL、部署、发布或提交。实际实现、验证和环境状态仍只由 [CURRENT_IMPLEMENTATION.md](../CURRENT_IMPLEMENTATION.md)维护。
