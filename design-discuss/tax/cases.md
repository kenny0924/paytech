# Tax 模型验收案例

状态：**讨论稿，待评审**，2026-10-26。以下为模型推演，不代表系统已经运行或测试通过。地区适用前提见 [regional-policies.md](regional-policies.md)。

完整流程见 [flows.md](flows.md)；同一笔销售、退款、申报、缴款的关联行与追加分支见 [example-data.md](example-data.md)。下面44项是独立验收场景，不合并成一份数据库快照。2026-10-29 修订：C13 改为事件重复投递，新增 C35–C39（`NOT_MANAGED`、服务费税、billing 不等待、持有方操作）；第二轮新增 C40–C44（总金额退款分摊、采购事实随销售登记、`TaxPaymentFailed`、两阶段报价），C25 / C27 措辞更新。第三轮（人工降级）：C42 改为人工登记进项，C36 改为首期不计算，新增 C45–C48（人工核验、外部 B2B 税票、人工事实执行重校验、待处理清单阻止关期）。

## 1. 同一 SaaS 产品的收款金额

假设：对应收税义务成立、注册有效、标准税率产品、仅一个比例税组件；以下以 USD 展示价格，法定申报仍需换算为相应注册的申报币种。示例按两位小数、逐行四舍五入；实际取整以批准地区包为准。

| 场景 | 税前价 100 时：净额 / 税 / 收款 | 含税标价 100 时：净额 / 税 / 收款 |
|---|---|---|
| AE 本地普通销售，5% | 100.00 / 5.00 / 105.00 | 95.24 / 4.76 / 100.00 |
| SA 跨境 B2C，15% | 100.00 / 15.00 / 115.00 | 86.96 / 13.04 / 100.00 |
| EG 跨境 B2C，14% | 100.00 / 14.00 / 114.00 | 87.72 / 12.28 / 100.00 |

计算：未税价格 `tax = round(net × rate)`；含税价格 `tax = round(gross × rate / (1 + rate))`，`net = gross - tax`。多个同基数比例税组件先使用有效税率之和反算基数，再按各组件分配税额和尾差；复合税不套该公式。

## 2. 逐场景验收

| 编号 | 输入 / 操作 | 必须观察到的结果 |
|---|---|---|
| C01 | AE 本地企业买家，税号有效 | 仅“有税号”不会使普通本地销售免收 5% |
| C02 | SA 买家满足跨境反向征税条件，税前价 100 | 收取 100、charged_tax=0、treatment=REVERSE_CHARGE、liable_role=BUYER；不假造 0% 标准税率 |
| C03 | EG 买家填写公司名，但 UIN 核验超时 | evidence=UNKNOWN；不认定已登记、不静默免收；按批准的失败策略处理 |
| C04 | IP 属 AE、账单地址 SA、用途信息矛盾 | 按地点证据规则要求补证或阻断，不单靠 IP / 多数票决定 |
| C05 | SA 有收税义务但注册尚待办理 | market 不允许正常收税销售；不因 registration_id 为空返回成功零税 |
| C06 | Checkout 报价后改地址、产品、折扣或卖方 | 原 source_revision 失效，重新计算后才可支付 |
| C07 | 月度 SaaS 续费，价格相同但税率变更已生效 | 新周期新 calculation；旧交易和单据保持原税率 |
| C08 | SA 原交易净 100、税 15、总 115；部分退净 40 | 新 REFUND：净 -40、税 -6、总 -46；原交易不变，可退净额余 60、税余 9 |
| C09 | 原行净 0.10、税 0.02；分三次退清 | 非最后退款按批准方法取整；最后一次退剩余税，累计精确 0.02，不产生多退或漏退 |
| C10 | 两个退款同时各申请原交易的 70% | 原交易资源锁 + 累计封顶，第二次不得使累计超过 100% |
| C11 | 原 15% 销售在税率变化后退款 | 引用原组件；不能按当前税率冲回 |
| C12 | 支付争议败诉，但尚不满足当地税额抵减条件 | 可以有资金损失事实，但不自动产生退税 / 贷项税额 |
| C13 | `OrderPaymentSucceeded` 被重复投递给 Tax | 源事实唯一身份对应同一个 transaction；billing 独立消费同一事件，只产生一笔 `SELLER_TAX` 行，且不调用 Tax |
| C14 | 开票联网超时，未知是否已接受 | 同号码、同 document 身份查询恢复，不能新建第二张发票 |
| C15 | 单据已经发行，Customer 后来改名或删除档案 | 旧单据和证据仍保持当时内容；受法定留存约束，不使用当前档案重渲染 |
| C16 | 交易 USD，法定申报 AED | 保存原币与申报币金额、fx_rate、日期、来源、取整；不能按当前汇率重算历史报表 |
| C17 | 已发生交易但暂缺法定汇率 | transaction 存在、reporting=PENDING；期间封存被阻止，补汇率后只生成一次底稿 |
| C18 | 本期零销售但仍有申报义务 | 可生成并提交零申报；不会因无 entry 而漏报 |
| C19 | 原申报 100 已缴 100，完整修订为 120 | 有效应纳=120、历史已缴仍为100、新待缴20；旧版本保留 |
| C20 | 上述修订改为 80 | 推算超缴20；未有认可证据前不自动抵其他期、不伪造银行退税 |
| C21 | 一笔缴款300，分配期间A100、期间B200 | payment 一条、allocation 两条；付款币种分配合计300；银行现金只扣一次 |
| C22 | 一个期间应纳300，已有银行确认100、UNKNOWN 在途200 | 不允许再创建300或200的重复支付；UNKNOWN 保留占用 |
| C23 | 缴款被标记失败后出现真实迟到银行扣款，且已暂记 | 记录迟到证据与人工归类；只发重分类事实，不再扣一次现金 |
| C24 | 银行已扣款100，税局归错注册 / 期间 | bank_confirmed 与 authority_disputed 分开；不显示法定已结清，不立即自动补付100 |
| C25 | 源期净抵税50获准转用30到下期 | credit_application=APPLIED，源可用额减少30，目标待缴减30；无银行流水、无假付款、不向 billing 发布任何事件 |
| C26 | 对同一抵税额并发申请退税与转用 | 同 registration 锁下校验总占用，不允许两次使用同一额度 |
| C27 | Partner OE 向境外 Client 采购净100，财务按 Client 发票人工登记自计税5，复核人确认允许抵扣3 | `origin=MANUAL`、`MANUAL_INPUT`；RCM_OUTPUT=5、RCM_INPUT=5 且可抵扣=3，本项净税负2；不凭默认规则全额抵扣；附发票文件与摘要 |
| C28 | MoR 销售价100、向 Client 的合同采购价80 | 两笔独立供应；不能把20差价额外当一笔平台服务费征税 |
| C29 | billing 确认独立服务费基数10 | tax 只对该独立供应计算税；不能再次把买家100总额算税 |
| C30 | 新国家使用既有比例算法与手工申报 | 新地区包、注册、证据 / 模板配置即可；不新建该国专属业务表 |
| C31 | 新国家要求尚未支持的固定额税 / clearance协议 | 发布 / 启用校验拒绝；增加真实适配能力后才能开放 |
| C32 | 一个税务底稿需进入两个展示栏目及一个应纳栏目 | return_item 可多行，但合计按栏目角色计算，不重复征税 |
| C33 | 首次申请缴款时 account 锁定成功，本地回写失败 | 用相同 payment ID 查询 / 恢复预留；不创建第二笔锁款、不提前展示 READY |
| C34 | 已审批缴款100，提交前申报修订为80 | 提交前重验失败并调整 / 撤销未提交支付，不能持旧批准继续超付 |
| C35 | PSP 合同下消费者销售，`TAX_RESPONSIBLE`=Client，Client 自报税额 7 | calculation `NOT_MANAGED`、`tax_amount_source=DECLARED`、charged_tax=7；无 component、evidence、transaction、底稿、单据；支付不阻断；billing 不生成 `SELLER_TAX` 行 |
| C36 | 同一 PSP 合同，PayFac 向 Client 收服务费 10，条款 `fee_tax_treatment=EXCLUSIVE` | 首期 Tax 不计算、不登记；billing 费用明细可按期导出供 Partner 财务自行开票申报；消费者销售仍为 `NOT_MANAGED`。`PLATFORM_SERVICE` 供应类型保留给第二期 |
| C37 | 事件携带 calculation 1001 与税 15，Tax 登记失败进死信 | billing 的 PAYMENT 事实照常落 `SELLER_TAX` 15 并引用 calculation 1001；Tax 恢复后登记 4001，金额与 billing 一致；期间不出现"等待 Tax"的入账阻塞 |
| C38 | 事件携带的税额 16 与冻结 calculation 的 15 不一致 | Tax 进死信并告警，不以任一方覆盖；运营待办可见 |
| C39 | Partner 在 Partner 控制台批准其 OE 的 SA 准入并登记缴款；平台运营尝试替其批准 | `managed_by=SUBJECT_HOLDER` 的记录只接受持有方审批；平台运营只读；授权边界按 `tax_subject_party_id`，不按 OE 来源 |
| C40 | 原交易两行均 15%：行 A 净 60 / 税 9，行 B 净 40 / 税 6；只带总金额退款 46 | 按剩余可退 gross 比例分摊：A 退 24 / 3.60，B 退 16 / 2.40；尾差给剩余额最大的行；`refund_basis_amount` 分别为 24 与 16，`quantity` 不变 |
| C41 | 原交易一行 15% 应税、一行反向征税；只带总金额退款 | 拒绝并要求 Commerce 提供行级退款金额；不自行猜测比例 |
| C42 | C1 销售净 100 的 `OrderPaymentSucceeded` 事件；期末 Partner 财务收到 Client 发票 | 事件只建 SALE 交易；采购不自动登记；"待登记进项"清单列出该期间；财务登记 `MANUAL_INPUT`（发票号唯一）后清单项消失。合同性质确认后才改为随事件自动建 PURCHASE |
| C43 | 已 SUBMITTED 的缴款，银行出具未执行证明 | 发 `TaxPaymentFailed`，reconciliation 取消预期银行流水，释放现金预留与分配占用；仅超时不得触发 |
| C44 | Client 建单时按声明国家 AE 报价 5%，消费者提交 SA 地址后重算 15% | 两份 calculation 都保留；只有 `source_revision` 最新的 READY 计算可供支付；建单阶段计算不能用于收款 |
| C45 | EG 企业买家提交 TRN + UIN，系统无自动核验能力 | 买家进入"待核验"清单；Partner 财务在 ETA 门户核验后登记 `source_code=MANUAL` 证据与截图摘要；核验前按地区包按 B2C 收税或阻断，不自动免税 |
| C46 | SA 已核验 B2B 买家的正式交易需要含买方名称与 VAT 号的税票 | 系统不渲染含个人资料的票据；交易进入"待开票"清单；财务在 ZATCA / 自有系统开具后回填外部单据号与回执，`issuance_mode=EXTERNAL`、ISSUED；金额以系统事实为准 |
| C47 | 人工登记进项：审批通过后执行时发现同一 Client 发票号已登记，或 RCM_INPUT 6 > RCM_OUTPUT 5 | 执行拒绝并退回登记人；审批通过不等于可执行（D13）；不留下半成品事实 |
| C48 | 期间结束时"待登记进项"或"待开 B2B 税票"清单非空 | 期间不能关闭；可申报但需复核人对零进项或缺票明确确认并留痕；关闭前清单必须为空或逐项标注原因 |

## 3. 进入实施时的验证范围

计算：十进制精度、折扣、含税与未税、多行尾差、原税率退款、总金额退款分摊与拒绝、`NOT_MANAGED` 出口。状态：事件消费去重与内容冲突死信、人工事实的审批与执行重校验、外部开票与人工报送回填、单据未知恢复、申报完整性与修订、待处理清单阻止关期、持有方与平台运营的操作权边界。并发：退款封顶、序列、缴款容量与抵税共用额度。跨服务：事务外调用、消息恢复、counterparty 原值隔离、已暂记重分类不重复扣现金。

只有这些行为真的实现并运行通过后，才能在当前状态台账记录验证结果。本轮只完成文档静态与示例算术核对。
