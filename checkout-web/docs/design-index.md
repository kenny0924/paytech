# Checkout 页面与状态设计

设计文件：[design.pen](./design.pen)。本批沿用用户选定的第一版：左侧浅灰订单摘要、右侧白色内容区、Inter 字体和紫色主操作。第一版 `bi8Au` 的节点内容未修改，已删除的其他风格版本未恢复。

本文件是设计稿索引与交互说明，不是接口或实现状态台账。当前提供桌面端可编辑画板，骨架占位带有 Pencil 动画 Shader；一个画板可以是同一 Checkout 页的状态或弹层，不代表新增一条路由。没有改前端业务代码、服务、网关、数据库或 PDManer。

## 流程衔接

加载 → 信息填写 → 支付准备 → 第一版支付页面。准备暂时失败进入 13，重试仍恢复原订单。

支付页面可打开条款查看弹层；校验失败进入 04。校验和三份独立确认通过后，按渠道需要进入钱包继续页、银行验证或直接进入处理中。原生 Wallet / SDK 面板使用实际 Provider 的组件；06 不是所有 Wallet 的统一跳转协议。

处理中按服务端事实进入成功、确定失败、待确认或授权待完成。确定失败且订单可继续时，12 返回第一版支付页面。待确认和授权待完成不创建新 Attempt。过期或取消与在途支付竞态时，应先展示并收敛真实在途结果，不能用页面超时推断支付失败。

## 加载与状态页样式

- 01、03、05 的骨架共用 [skeleton-shimmer.glsl](./assets/skeleton-shimmer.glsl)：浅灰底色、轻微流光、1.8 秒循环。Pencil 通过 `@time` 驱动动画；PNG 只保存静态画面，不播放动画。该素材需要与设计文件一起保留。
- 初次加载按订单摘要与表单的大致结构预留空间；只有获得授权的服务端数据才替换占位。骨架中的按钮、输入框、选择项均不可交互。
- 准备中保留已知信息，只对待确认区域占位；条款弹层的骨架只替代尚未返回的正式正文。
- 06–16 的状态图标改为 26px 线性图标，位于标题左侧，取消原先独立的彩色方块底座。标题、说明、详情和操作按同一正文边缘对齐。成功用绿色、确定失败用红色，过期、取消及不可用用中性灰，进行中的动作保留紫色。
- 支付处理中、结果待确认和已授权仍显示明确的状态及操作限制，不用骨架掩盖支付事实。
- 后续前端实现应遵循系统减少动态效果设置：`prefers-reduced-motion: reduce` 时使用静态骨架；此设计素材也可通过 `u_animate=0` 关闭流光。占位形状对辅助技术隐藏，实际加载区域设置 `aria-busy`，加载说明只礼貌播报一次。这里记录实现要求，不代表浏览器交互已经落地。

## 保留的业务边界

- 准备前只展示已知订单小计；不假设最终 OE、卖方或税额。准备完成后才展示最终总额和法律材料。
- 原订单的 OE、最终金额和法律上下文冻结后不得被后续支付尝试覆盖；改变支付方式不代表切换 OE。
- 02 是准备前的信息采集状态。原版页面上的 Edit 不授权改写已冻结的账单国家、税额或上下文；准备后的具体可编辑范围需要由消费接口明确。
- Consumer Terms、Refund Policy、Privacy Notice 分别确认，均不预选。阅读、关闭或切换文档不替代确认。
- 卡号、有效期、安全码等示意输入框属于 Provider 托管组件。设计稿没有卡号、安全码、钱包凭据、验证码或真实支付秘密。
- 钱包/银行继续按钮恢复同一次消费者动作；回跳参数、SDK 完成和验证完成不能单独证明订单已支付。
- `AUTHORIZED` 与 `PAID` 分开；未知结果不显示失败，也不允许再次付款。
- 成功页没有承诺已发邮件、可下载收据或自动返回商户地址。后续存在权威能力和合法目的地时再补充相应操作。
- 商品、姓名、邮箱、卖方和 `PT-10482` 等引用均为沿用或新增的合成展示数据，不定义实际编号规则或已支持的渠道清单。
